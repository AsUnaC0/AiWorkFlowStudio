## 一、一句话理解

**一个** **`MemoryPanel`** **组件两种用法：嵌在 Agent 配置页 Tab 里（embedded，660px 高 + 「全屏」按钮），或铺满** **`/memory`** **路由；两个视图（星图 / 列表）共用同一份数据源，原文只在打开详情时才请求。**

```
Agent 管理 → 平台助理 → 「记忆」Tab ──embedded──┐
                                                ├─→ MemoryPanel ──┬─ 星图（MemoryGraph.vue，Three.js）
/memory 路由（Tab 里的「全屏」按钮跳过来）──────┘                 └─ 列表（分页卡片）
                                                       数据源：GET /memories/graph（不带 content）
                                                       详情：  GET /memories/:id（唯一带 content 的接口）
```

## 二、入口设计：为什么侧边栏不放菜单

`fronted/src/views/memory/index.vue` 全文只有十几行——它就是一层路由壳：

```vue
<script setup lang="ts">
import MemoryPanel from "@/components/memory/MemoryPanel.vue";
/**
 * 记忆全屏页。
 * 入口只保留在「Agent 管理 → 平台助理 → 记忆」Tab 里的「全屏」按钮，
 * 侧边栏不再单独放菜单 —— 记忆是平台助理的上下文资产，不是独立功能模块。
 * 真正的实现全在 MemoryPanel（与 Tab 内嵌共用同一份）。
 */
defineOptions({ name: "MemoryGraph" });
</script>

<template>
  <MemoryPanel />
</template>
```

路由注册（`router/index.ts`）同样带着这条注释：

```ts
{
  path: "memory",
  name: "MemoryGraph",
  component: () => import("@/views/memory/index.vue"),
  meta: { title: "记忆" },
},
```

**设计意图**：记忆不是独立功能模块，是平台助理的「上下文资产」。所以入口收在
「Agent 配置 → 平台助理 → 记忆」Tab 里（`detail.vue` 用 `v-if="isPlatformAssistantAgent"` 控制，
判据是 `isSystem && isDefault`，普通 Agent 看不到这个 Tab），Tab 里的面板右上角再放一个
「全屏」按钮跳 `/memory`——3D 视图空间越大越好操作。

两种模式的差异只在样式（`MemoryPanel.vue` 的 `.is-embedded`）：

| 模式            | 高度                             | 外观                                       |
| ------------- | ------------------------------ | ---------------------------------------- |
| 全屏（`/memory`） | `calc(100vh - @header-height)` | 铺满内容区                                    |
| 嵌入（Tab 里）     | `660px` 固定                     | 圆角边框 + 投影，整块做成深色「观星窗口」——浅色工具栏压在星图上方会显得割裂 |

## 三、接口封装（`api/memory.ts`）：后端的关键约定

文件头注释写死了这条约定：

> 列表 / 图数据只返回摘要与元信息，**不含原文**；原文只在 `getMemory(id)` 里返回，详情面板打开时才请求。

原因有二：一是隐私（需求 4.5），二是体积——3D 图一次取 500 个节点，带正文会把响应撑到几 MB。

| 方法                                           | 路径                                     | 返回                                                                 | 说明                                                      |
| -------------------------------------------- | -------------------------------------- | ------------------------------------------------------------------ | ------------------------------------------------------- |
| `listMemories`                               | `GET /memories?page&pageSize&category` | `{ items, total, page, pageSize, hasMore }`                        | 列表视图用；`MemoryListItem` 无 `content`                      |
| `getMemoryGraph`                             | `GET /memories/graph?category&limit`   | `MemoryGraphPayload`                                               | 星图数据源；`nodes` 带 `degree`（连线数）无 `content`                |
| `getMemory`                                  | `GET /memories/:id`                    | `MemoryDetail`（含 `content` / `sourceMessageId` / `embeddingModel`） | **唯一返回原文的接口**                                           |
| `deleteMemory`                               | `DELETE /memories/:id`                 | `{ success }`                                                      | 单条删除                                                    |
| `clearMemories`                              | `DELETE /memories`                     | `{ success, deleted }`                                             | 清空当前用户全部                                                |
| `getMemorySettings` / `updateMemorySettings` | `GET/PUT /memories/settings`           | `MemorySettings`                                                   | `autoCaptureEnabled` / `captureModelId` / `recallLimit` |
| `getMemoryCategories`                        | `GET /memories/categories`             | `MemoryCategoryMeta[]`                                             | 分类元信息                                                   |

文件里还定义了两个前端常量，**3D 节点和列表标签共用**，保证两处配色一致：

```ts
export const MEMORY_CATEGORY_LABELS = { PREFERENCE: "偏好", FACT: "事实", TASK: "任务",
                                        EVENT: "事件", EMOTION: "情感", OTHER: "其他" };

export const MEMORY_CATEGORY_COLORS = { PREFERENCE: "#5eead4", FACT: "#7dd3fc", TASK: "#fbbf24",
                                        EVENT: "#c4b5fd", EMOTION: "#f9a8d4", OTHER: "#94a3b8" };
```

> 配色是「高饱和 + 中亮度」的发光色：深色底上如果用暗色，Three.js 的 additive blending
> 会把颜色全部糊成白色。`LABELS` 不是列表兜底（列表用的是后端返回的 `categoryLabel`），
> 而是**悬停标签**的分类名来源（`MemoryGraph.vue` 的 `updateTip()`）。

`getMemoryCategories()`（`GET /memories/categories`）虽然封装了，但**全项目没有任何页面调用**——
分类信息统一从 `GET /memories/graph` 的 `categories` 字段拿。留着是为了将来做「分类管理」页。

## 四、MemoryPanel.vue：面板的状态机

### 4.1 状态清单

```ts
const mode = ref<"graph" | "list">("graph");   // 星图 / 列表
const graph = ref<MemoryGraphPayload | null>(null);
const activeCategory = ref("");                // 分类过滤（空 = 全部）
const selectedId = ref("");                    // 当前打开详情的记忆 id
const detail = ref<MemoryDetail | null>(null); // 详情（带 content）
const listItems / listTotal / listPage          // 列表分页（pageSize 固定 20）
const settingsVisible / settings                // 设置弹窗
```

### 4.2 数据流

| 动作           | 行为                                                                                     |
| ------------ | -------------------------------------------------------------------------------------- |
| `onMounted`  | 只 `loadGraph()`——列表数据等用户第一次切到列表才拉（`switchMode('list')` 里 `loadList(1)`）                |
| 点星点 / 点卡片    | `handleSelect(id)`：再点一次同一个 = 关闭（`closeDetail`），否则 `openDetail(id)` 单独拉 `getMemory(id)` |
| 删除单条         | `DialogPlugin.confirm`（warning）→ `deleteMemory` → `refreshAll()`                       |
| 清空全部         | `DialogPlugin.confirm`（danger，文案带 `total` 条数）→ `clearMemories` → `refreshAll()`        |
| `refreshAll` | `Promise.all([loadGraph(), 列表模式时再 loadList(1)])`；若详情开着则重拉详情                            |
| 保存设置         | 只提交 `autoCaptureEnabled` 和 `recallLimit` 两个字段（`captureModelId` 面板里不暴露）                 |

两个删除入口（详情面板底部按钮、列表卡片上的「删除」）都走 `handleDelete` 同一个函数，
二次确认是硬要求（删除不可恢复）。

### 4.3 工具栏构成

```
[记忆网络  123 条·已按重要度截取前 N 条] [全部] [●偏好 12] [●事实 30] … [星图|列表] [全屏] [设置] [刷新] [清空]
```

- **分类 chip**：数据来自 `graph.categories`（`count > 0` 才显示），选中写入 `activeCategory`，
  星图据此压暗其它分类（见 §5.5）。注意这个过滤**只影响星图的高亮**，列表接口的分页过滤是另一套
  （`listMemories` 的 `category` 参数当前页面没有接）。
- **`graph.truncated`**：后端按 `importance desc, createdAt desc` 排序后截断到 500 个节点，
  截断了就在总数徽章后用琥珀色提示「已按重要度截取前 N 条」——保留「重要的记忆」，而不是「最近的流水账」。
- **清空按钮**：`total === 0` 时禁用。

### 4.4 详情面板

右侧浮层（340px，`backdrop-filter` 毛玻璃），`<transition name="panel">` 滑入滑出。
内容分三块：头部分类标签、元信息（重要度 / 形成时间 / 被召回次数）、记忆原文（`white-space: pre-wrap`）。

`watch(selectedId, (id) => { if (!id) detail.value = null })`：关掉详情时清掉原文——
原文只在面板开着的时候存在于前端内存里。

### 4.5 设置弹窗

两项：`autoCaptureEnabled`（t-switch，「关闭后不再新增记忆，已有记忆不受影响」）和
`recallLimit`（t-slider，1\~10，「条数越多越记得清楚，也越占上下文」）。

## 五、MemoryGraph.vue：星图渲染

先看它对外的契约——**组件本身不发请求、不存数据，纯粹是「给定数据 → 画出来 → 把点击吐回去」**：

```ts
const props = defineProps<{
  nodes: MemoryGraphNode[];
  links: MemoryGraphLink[];
  activeCategory: string;   // 空字符串 = 全部；否则非该类节点被压暗
  selectedId: string;
}>();

const emit = defineEmits<{ (e: "select", id: string): void }>();
```

| 项 | 说明 |
| --- | --- |
| 数据来源 | 全部由父组件 `MemoryPanel` 通过 props 传入，组件内部只有 `hoveredId` / `ready` / `tip` 三个 UI 状态 |
| 视觉状态的三输入 | `hoveredId`（内部）、`props.selectedId`、`props.activeCategory` —— 三者任一变化都走 `refreshVisualState()` |
| 焦点优先级 | **悬停 > 选中**（`const focusId = hoveredId.value \|\| props.selectedId`） |
| 点击回传 | `pointerup` 位移 `\|dx\| + \|dy\| ≤ 4px`（曼哈顿距离）才 `emit('select', node.id)`；面板侧 `handleSelect` 再判断「同一条 = 关闭」 |

内部维护的几张大表（重建图时全部重算，不要在交互里重建）：

| 变量 | 内容 |
| --- | --- |
| `indexById` / `positionById` | id → 顶点索引 / 世界坐标（拾取与标签定位都要） |
| `neighborsOf` | id → `Set<id>`，**无向**（`link.source` 和 `link.target` 各 `add` 一次），高亮时决定谁被点亮 |
| `linkMeta` | 每条连线在顶点缓冲里的区间 `{ a, b, start, count }` —— `SEG = 12`，一条逻辑连线是 **12 段 / 24 个顶点**，高亮要整段一起改 |
| `linkBaseAlpha` | 长度衰减后的基础透明度，高亮时**在它基础上放大**而不是覆盖 |
| `baseColors` | 节点原始色（未压暗），过滤/高亮都基于它重算 |

### 5.1 为什么是「星图 + 星座」而不是「球 + 直线」

早期版本用 `InstancedMesh` 画实体球 + 直连线，在加法混合下会糊成一片糖果色圆点、
连线织成铁丝网。这一版改成**四层叠加 + 后处理泛光**：

| 层     | 实现                                                                                                                                                  |
| ----- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| ① 星点层 | `Points` + 自定义 `ShaderMaterial`：炽白核心（`smoothstep`）+ 指数衰减光晕（`pow(1-d, 3.4)`）+ 轻微闪烁（`sin(uTime)`）；重要度 > 0.78 的节点额外画十字星芒（模拟望远镜衍射尖）。**尺寸映射重要度（并叠加连通度），亮度映射重要度** |
| ② 星云层 | 每个分类一团同色 `Sprite` 色雾（`scale = 9 + min(8, count*0.06)`，透明度随节点数增长但封顶 0.105），让「簇」有体积而不是散点；再加一层整体紫色底雾（`0x3b1d8f`，scale 52）托出深空感                         |
| ③ 连线层 | `LineSegments`，但每段用**二次贝塞尔**拆成 12 段弯曲弧线 + 长度衰减（`1/(1+len*0.16)`）+ 颜色从源端渐变到目标端；静息 `uOpacity = 0.032`（几乎隐形），悬停/选中提到 `0.55` 并压暗非邻居                     |
| ④ 景深层 | 按视距衰减亮度与尺寸（`smoothstep(22, 60, dist)` 压到最低 0.4）+ 星尘（1400 颗远景 `Points`，不参与交互）+ 中心核心 `Sprite` 光晕（scale 16，`sin` 呼吸）                                   |

后处理链：

```ts
renderer.toneMapping = THREE.ACESFilmicToneMapping;
renderer.toneMappingExposure = 1.05;
composer = new EffectComposer(renderer);
composer.addPass(new RenderPass(scene, camera));
composer.addPass(new UnrealBloomPass(size, 0.88, 0.75, 0.15));  // strength / radius / threshold
composer.addPass(new OutputPass());
```

**没有 bloom 就只是彩色圆点**——这是发光感的来源。

相机与轨道控制器（`init()` 里，数值都是调出来的，改之前先看效果）：

| 参数 | 值 | 作用 |
| --- | --- | --- |
| `PerspectiveCamera` | `50 / 0.1 / 400` | 50° 视角够宽但不畸变；`far = 400` 要装得下 1400 颗星尘 |
| `camera.position` | `(0, 16, 23)` | **抬高俯视**而不是平视——平视会让分类簇叠在一条线上 |
| `controls.enableDamping` / `dampingFactor` | `true` / `0.06` | 松手后惯性收尾，手感不发飘 |
| `rotateSpeed` / `zoomSpeed` | `0.55` / `0.8` | 节点密集，转太快会晕 |
| `minDistance` / `maxDistance` | `8` / `90` | 下限防止钻进星团内部（全是糊住的光斑），上限防止缩成一个点 |
| `autoRotate` / `autoRotateSpeed` | `true` / `0.22` | 静息缓慢自转，让「星图」有生命感；悬停时置 `false` |


### 5.2 确定性布局：刷新不重排

布局全部由 `hash01(id, salt)` 决定，用户的空间记忆不被刷新破坏。
`hash01` 是「盐值参与串哈希 + MurmurHash3 `fmix32` 收尾」：

```ts
function hash01(input: string, salt = 0): number {
  const s = `${salt}|${input}`;
  let h = 2166136261;                          // FNV-1a
  for (const ch of s) { h ^= ch.charCodeAt(0); h = Math.imul(h, 16777619); }
  h ^= h >>> 16; h = Math.imul(h, 2246822507); // murmur3 fmix32 收尾
  h ^= h >>> 13; h = Math.imul(h, 3266489909);
  h ^= h >>> 16;
  return (h >>> 0) / 4294967295;
}
```

> ⚠️ **盐值不能只异或进初始状态**：`FACT-1…FACT-61` 这类只差末位的 id 会让结果强相关，
> 节点排成一条弧线（像风筝骨架）。收尾的几步 avalanche 把相关性彻底打散。

布局三步走（`layoutNodes`）：

1. **分类簇心围圈**：`categoryCenters()` 把各分类均匀放在 `radius = 8.6` 的圈上，
   `y = sin(i*2.1) * 1.3` 错开高度，避免看起来像平面圆环。
2. **簇内按摘要前缀分子簇**：key 是 `category:summary.slice(0, 12)`（同一话题的相近记忆抱成团），
   子簇偏移角度和半径都由 `hash01` 决定（r ∈ \[1.1, 3.4]）。
3. **重要度决定离簇心距离**：`reach = 0.45 + (1 - importance) * 3.6 + hash01(id,24) * 0.9`——
   越重要越靠近簇心，簇心天然是「最要紧的那几条记忆」。

**fill 系数（容易漏）**：`fill = 0.28 + pow(hash01(id,25), 0.55) * 0.9`，
把点填进**体积**里。如果所有点都落在同一个半径上，它们会贴在球壳表面，
连线就变成多边形的边（看起来像风筝骨架）。

### 5.3 星点 shader 里每个属性从哪来

| attribute | 来源                                                                               | 作用                             |
| --------- | -------------------------------------------------------------------------------- | ------------------------------ |
| `aColor`  | 分类色 ×（0.55 + importance×0.45）亮度 + 同色系 HSL 抖动（hue ±0.0225 / lightness ±0.06）      | 次要记忆退成暗星，主角立得住；一整簇同色会像串珠       |
| `aSize`   | `(2.2 + importance^1.2 × 7.0) × (1 + min(degree,4)×0.06) × (0.72 + hash01(id,41)×0.56)` | 星等映射重要度；连通度再加一点；抖动避免像按网格摆的串珠   |
| `aPhase`  | `hash01(id, 31)`                                                                 | 闪烁相位错开                         |
| `aHl`     | 视觉状态机写入（0 / 0.35 / 1）                                                            | 高亮：更亮更大（`boost = 1 + hl×0.75`） |
| `aSpike`  | `importance > 0.78 ? 1 : 0`                                                      | 十字星芒只给最重要的几颗                   |

顶点着色器里 `gl_PointSize = aSize × boost × twinkle × vFade × uPixelRatio × (uScale / dist)`
（`uScale = 78`）——尺寸随距离衰减是「三维纵深」的来源，避免前后节点糊在同一平面。

### 5.4 连线的弯曲方向

```ts
const perp = new THREE.Vector3(-dir.z, 0, dir.x).normalize();  // 盘面内的垂线
ctrl.addScaledVector(perp, (hash01(source + target, 7) - 0.5) * len * 0.22);
```

**控制点只在盘面内偏移**：上下翻越会让连线穿过整团，显得杂乱。
长连线更淡（`lenFalloff`）：短程关联是主要结构，跨类长线只做「远处的引力丝」。

### 5.5 视觉状态机：一次算完所有「谁亮谁暗」

`refreshVisualState()` 在三种输入变化时重算（悬停、选中、分类过滤），规则：

| 状态            | 节点亮度系数 k     | aHl  | 连线              |
| ------------- | ------------ | ---- | --------------- |
| 分类过滤未命中       | ×0.18        | 0    | 任一端未命中 → 透明度 ×0 |
| 焦点（悬停 > 选中）本人 | max(k, 1.25) | 1    | 与焦点相连 → 保持      |
| 焦点的邻居         | max(k, 1)    | 0.35 | —               |
| 有焦点时的其它节点     | ×0.16        | 0    | 透明度 ×0.08       |

连线整体透明度：有焦点 `uOpacity = 0.55`，静息 `0.032`。
**静时是星图，动时才是网络**——静态画面干净，交互时一眼看清「这条记忆和谁连着」。

实现上直接改 BufferAttribute（`aColor` / `aHl` / `aAlpha`）再 `needsUpdate = true`，
不重建几何体。`baseColors` 数组存着未压暗的原始色，过滤与高亮都基于它重算，
避免「压暗后再压暗」越叠越黑。

### 5.6 交互：拾取、悬停、点击

```ts
raycaster.params.Points.threshold = 0.38;   // 点的拾取半径是世界单位，经验值
const hits = raycaster.intersectObject(nodePoints, false);
const node = nodeList[hits[0].index];        // 命中点的 index（不是 instanceId——Points 没有实例）
```

- **悬停**：命中后 `updateTip()` 把节点世界坐标 `project(camera)` 投到容器像素坐标，
  浮动标签贴着星点显示（分类 + 摘要，最多两行）。**悬停时暂停自转**
  （`controls.autoRotate = false`），否则标签跟着转，读不了。同一节点上继续移动也要
  `updateTip()`——相机会转，位置会漂。
- **点击 vs 拖拽**：`pointerdown` 记坐标，`pointerup` 位移 `|dx|+|dy| > 4px` 视为拖拽旋转，不触发选中。
- **离开容器**：清悬停、恢复自转、光标回 `grab`。

### 5.7 性能与资源回收

| 措施                           | 位置                                                                                                       |
| ---------------------------- | -------------------------------------------------------------------------------------------------------- |
| 节点上限 500                     | 后端截断（`MEMORY_GRAPH_NODE_LIMIT`），前端只渲染收到的                                                                 |
| `setPixelRatio(min(dpr, 2))` | renderer 与 composer 都设                                                                                   |
| 页面不可见时不渲染                    | `animate()` 里 `if (document.hidden) return`（省电）                                                          |
| 尺寸变化自适应                      | `ResizeObserver` 观察容器，`w/h` 为 0 跳过                                                                       |
| 数据变化整体重建                     | `watch([nodes, links])` → `rebuild()`：先 `clearGraph()`（dispose 旧图元）再重建                                   |
| 卸载全量 dispose                 | `onBeforeUnmount`：controls / 图元 / coreGroup / 纹理 / composer / renderer（含 `renderer.domElement.remove()`） |

> 光晕 / 星云 / 星尘共用**同一张**径向渐变贴图（`createRadialTexture` 只建一次，
> 重建图时不重新生成）——canvas 渐变贴图是昂贵的，能复用就复用。

### 5.8 空状态与颗粒感

- 节点数为 0 时画布依然会初始化（`init()` 照建 renderer / scene / camera / composer，
  `buildBackgroundStars()` 也照跑），只是 `rebuild()` 在 `nodeList.length === 0` 时提前 return，
  **跳过节点 / 星云 / 连线三层图元**——所以看到的是「星尘背景 + 空状态文案」，不是黑屏。
  模板里 `v-if="nodes.length === 0"` 叠一层纯 CSS 的空状态（三个同心圆环 + 中心脉冲光点）。
- `.memory-graph::after` 叠一层极淡（`opacity: 0.035`）的 SVG 噪点（`feTurbulence`），
  `mix-blend-mode: overlay`——纯色渐变容易显得「塑料」，一层噪点压出胶片质感。

## 六、常见坑

1. **星图一坨白 / 颜色糊掉** —— 分类色太暗或 additive blending 下多层叠加过曝。
   配色必须用「高饱和 + 中亮度」（`MEMORY_CATEGORY_COLORS` 那套值就是这么选的）；
   连线静息透明度 0.032 不能再调高。
2. **节点排成弧线 / 风筝骨架** —— 两类原因：① 哈希盐值只异或进初始状态（必须用
   串哈希 + fmix32，见 §5.2）；② fill 系数丢了，点全落在同一半径的球壳上（见 §5.2 第 3 步）。
3. **连线穿过整团显得很乱** —— 贝塞尔控制点跑到盘面外了。控制点只能沿盘面内垂线
   `(-dir.z, 0, dir.x)` 偏移（见 §5.4）。
4. **点选总是误触发旋转，或旋转误触发选中** —— 检查 4px 位移阈值还在不在；
   `pointerup` 里没做位移判断就会这样。
5. **悬停标签读不了** —— 自转没暂停。`onPointerMove` 命中节点时必须
   `controls.autoRotate = false`，离开时恢复。
6. **切换分类后画面全黑** —— 大概率是过滤逻辑把 `k` 叠乘到已压暗的颜色上。
   必须基于 `baseColors` 重算（见 §5.5）。
7. **页面切走再回来显卡占用不降** —— `document.hidden` 判断被删了，或
   `onBeforeUnmount` 里 dispose 不全（composer / renderer / 纹理一个都不能漏）。
8. **详情面板能打开但原文是空的** —— 检查是不是用了列表数据渲染原文。列表 / 图接口
   本来就不带 `content`，必须等 `getMemory(id)` 返回（§三）。
9. **嵌入模式下面板把 Agent 配置页撑爆** —— `.is-embedded` 的固定高度 660px 被改掉了，
   或者外层容器没 `overflow: hidden`。
10. **星图看起来是「扁的一坨」/ 分类簇互相叠住** —— 相机被放平了。
    `camera.position` 必须是 `(0, 16, 23)` 这种**带高度**的俯视位；`y` 归零就变成平视，
    围在 `radius = 8.6` 圈上的六个分类会投影到同一条水平线上（见 §5.1）。
11. **滚轮缩放一推就钻进星团、满屏光斑** —— `controls.minDistance` 被调小了。
    星点用的是屏幕空间尺寸（`uScale / dist`），离得越近越大，8 是实测的舒适下限。

## 七、已知边界

| #  | 边界                | 影响                                                 |
| -- | ----------------- | -------------------------------------------------- |
| F1 | 分类过滤 chip 只影响星图高亮 | 列表视图的分页不过滤分类（`listMemories` 支持 `category` 参数，面板未接） |
| F2 | 记忆只能删不能改          | 没有编辑接口；要改请删了让小蝶重记                                  |
| F3 | 星图最多渲染 500 节点     | 超出的部分按重要度截断（工具栏有提示）；想看完整请用列表视图翻页                   |
| F4 | 普通 Agent 没有记忆 Tab | 记忆只对平台助理生效（后端同样如此，见后端 12 §十 M1）                    |
| F5 | 3D 图依赖 WebGL      | 极端老环境 / 禁用 WebGL 的浏览器只能用列表视图（当前无降级提示，画布会是空白）       |
