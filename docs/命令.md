执行 Migration

⚠️ 本项目**不要**用 `pnpm prisma migrate dev`（早期文档里写的 `--name init` 已废弃）。
原因是它会把 pgvector 的 IVFFlat 索引 `dc_embedding_ivf` 当成「schema 里没有的多余对象」，
在生成的 SQL 开头塞一句 `DROP INDEX "dc_embedding_ivf"` —— 跑完向量检索索引就没了
（`schema.prisma` 声明不了向量索引，Prisma 7 不支持，官方 pgvector 扩展要等 Prisma 8）。

正确流程是**手写迁移**：

1. 在 `backend/prisma/migrations/<timestamp>_<名字>/` 下手写 `migration.sql`
2. 应用：pnpm prisma migrate deploy
3. 重新生成 Client：pnpm prisma generate

如果确实跑了 `migrate dev`，**务必打开生成的 SQL 检查**，
把里面针对 `dc_embedding_ivf` 的 `DROP INDEX` 手动删掉再应用。

首次执行后：
PostgreSQL
│
├── users
├── workspaces
└── workspace_members
建立起来。

常用开发命令

后端（backend/）：
pnpm start:dev            开发模式（热重载，端口 3000）
pnpm build                构建
pnpm prisma generate       改了 schema 后必须跑
pnpm prisma migrate deploy 应用手写迁移

前端（fronted/）：
pnpm dev                   开发服务器
pnpm build                 构建

环境依赖：PostgreSQL（pgvector 镜像）+ Redis + Ollama 都要起。
Redis 挂了的话，BullMQ 的 Worker 初始化会失败；聊天附件的解析会自动降级为进程内执行，
但那只是兜底，不是免死金牌 —— 详见 docs/后端代码逻辑/10-聊天文件上传模块.md。
