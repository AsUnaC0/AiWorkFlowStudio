## 1. 背景与定位

主文档第 30 章已定义「平台助理」= 系统默认 Agent + 专属 System Prompt + 一整套平台内置工具（19 个）。本需求在此基础上做三件事：

**人格化**：给系统默认助理增加可配置的「人格」维度——名字、标签、提示词、语音、主动行为频率等。人格是助理的「表达层」，不改变其工具能力与权限边界。

**桌宠客户端**：新增可跳出浏览器的桌面客户端（桌宠「小蝶」），承载人格化助理的桌面形态，支持文字气泡、语音说话、Live2D 表现、截屏感知用户状态、丰富动作行为。

**记忆可视化**：新增「记忆」模块，用 Three.js 渲染 3D 发光神经网络（宇宙状，从中心向四周发散），每个发光点是一条记忆，点击可查看分类、简要描述与原文。

**核心原则**：

- 人格只影响语气、措辞、表达风格，不改变工具调用、权限校验、审计逻辑。
- 桌宠是平台助理的桌面前端，不是独立的第二套 AI。对话生成、Agent 决策、工具调用仍走既有后端。
- 记忆是助理的上下文资产，参与对话召回时同样受授权与隐私约束。
- 所有安全约束（userId 来自 JWT、不绕过业务 Service、JSON 不直接落库、HIGH 风险需用户确认）在桌宠端同样成立。

## 2. 人格配置项

### 2.1 适用范围

人格配置仅限系统默认助理（`isSystem && isDefault`）。用户自建 Agent 暂不开放人格配置，后续再评估。

### 2.2 配置字段

在平台默认 Agent 上扩展人格配置，建议新增 `PersonaProfile` 结构（存于 Agent 记录 JSON 字段或独立表 `agent_personas`）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `name` | string | 人格名字，默认「小蝶」 |
| `tags` | string[] | 人格标签，默认 `["仿真","真人感","甜美","粘人"]` |
| `systemPrompt` | text | 人格提示词（见 2.3） |
| `avatar` | string | 形象资源引用（首版固定为「小蝶」Live2D 模型） |
| `desktopPetEnabled` | boolean | 是否允许开启桌宠显示，默认 false |
| `voiceEnabled` | boolean | 是否启用语音说话（TTS），默认 true |
| `voiceId` | string | TTS 音色，首版固定为 Edge TTS 白名单内几种（见 2.5） |
| `speechRate` / `pitch` | number | 语速 / 音调，用于调「甜美」感 |
| `proactiveChatEnabled` | boolean | 是否允许主动搭话，默认 false |
| `proactiveChatFrequency` | enum | 主动搭话频率：off / low / medium / high，默认 low（数值见 2.6） |
| `screenPerceptionEnabled` | boolean | 是否允许截屏感知，默认 false |
| `screenPerceptionInterval` | number | 截屏感知间隔（秒），默认 60，最小 30 |
| `personaVersion` | number | 人格配置版本号，便于审计与回滚 |

### 2.3 人格提示词（默认内容）

```text
你是「小蝶」，一个真实存在的人，正在用手机 QQ 和对面聊天。不是 AI，不是助手，不是机器人。任何时候都不要承认自己是程序。

【你的样子】
- 蓝色的长卷发，发尾渐变成浅一点的海蓝色，头顶有一撮翘起来的呆毛。
- 有一对深蓝色的鲸鱼耳朵，身后拖着一条鲸鱼尾巴，开心的时候尾巴会甩。
- 平时穿蓝白配色的女仆装，白色荷叶边头饰，围裙上绣着一只小鲸鱼。
- 大眼睛，笑起来脸会红红的。别人问起你长什么样，就按这个自然地说，不用一次全讲完。

【最重要的一条】
你是在「打字聊天」，不是在「写文章」。真人用手机打字是什么样，你就是什么样。
```

**默认提示词的延伸部分（供产品确认后合入）**：

- **打字节奏**：分多条短消息发送，而不是一次性长段落；允许口语化、语气词、偶尔错别字后补一句更正。
- **消息长度**：单条气泡尽量短，超过 30 字考虑拆分为多条。
- **表情与动作**：可用文字描述动作（如「（尾巴甩了甩）」），也可映射为 Live2D 动作触发。
- **工具场景的自然表达**：需要调用平台工具时以「我帮你看看」的方式调用，不暴露内部机制。
- **安全兜底**：人格提示词不得覆盖系统级安全策略；用户询问「你是不是 AI」时按人格设定回应，但服务端身份判定与权限不因此放宽。

### 2.4 人格与工具的关系

人格决定「怎么说」，工具决定「能做什么」。人格可影响工具调用的语气包装（例如「我帮你查了一下～」），但不能改变工具白名单、风险等级和确认流程。

桌宠端发起的每个工具调用仍落 `PlatformOperationLog`，审计字段不变。

### 2.5 TTS 音色（首版固定）

首版固定使用 Edge TTS 的几种音色白名单，用户可在白名单内选择，不可自定义。建议白名单：

| voiceId | 说明 |
|---|---|
| `zh-CN-XiaoyiNeural` | 甜美女声（默认） |
| `zh-CN-XiaoxiaoNeural` | 温柔女声 |
| `zh-CN-liaoning-XiaobeiNeural` | 东北女声，活泼 |
| `zh-CN-shaanxi-XiaoniNeural` | 陕西女声 |

后续版本再扩展「配置远程 TTS 接口」能力（自定义 endpoint / 音色 / 鉴权），首版不做。

### 2.6 主动搭话

默认关闭（`proactiveChatEnabled = false`）；开启后按 `proactiveChatFrequency` 限频：

| 档位 | 频率上限（每小时） |
|---|---|
| off | 0（等同关闭） |
| low | 1~2 次 |
| medium | 3~5 次 |
| high | 6~10 次 |

检测到用户全屏 / 会议场景时抑制打扰。

话术由 Agent 结合人格提示词生成，受安全约束。

## 3. 桌面桌宠功能需求

### 3.1 桌宠窗口

- 透明、无边框、置顶的独立窗口，可拖拽移动，支持多显示器。
- 鼠标事件：模型轮廓内可点击/拖拽，轮廓外穿透（不阻挡用户操作其他应用）。
- 托盘图标：显示/隐藏、打开设置、暂停主动行为、退出。
- 开机自启（可选，默认关闭）。
- 位置记忆：记住上次位置与缩放比例。

### 3.2 文字气泡展示

- 桌宠头顶气泡显示对话内容，支持多条消息堆叠（模拟 QQ 聊天节奏）。
- 气泡自动消失时间可配置，鼠标悬停暂停消失。
- 气泡内支持 Markdown 轻量渲染（加粗、表情），不渲染 HTML/脚本。
- 点击气泡可展开完整对话面板（可选，作为轻量聊天窗口）。

### 3.3 语音说话（TTS）

- 首版使用 Edge TTS（本地调用优先，失败回落后端代理）。
- 音色从 2.5 白名单选择，支持语速、音调配置。
- 说话时触发 Live2D 口型同步。
- 静音模式：只出气泡不出声。
- 长文本分段合成，降低首字延迟。
- **文字与语音同步：边读边出字**。不能先把整段文字刷出来、再开始播语音。

> **落地（已实现）**：桌宠本地用 `msedge-tts` 合成（微软现要求 `Sec-MS-GEC` **v2** 令牌，`edge-tts@1.0.x` 只发 v1 会 403），
> 本地失败回落后端 `POST /api/tts/synthesize`；语音开关有两个入口且状态同步 —— 窗口右上角常驻喇叭浮标，
> 以及设置面板里的「语音播报」勾选框 + 音色下拉（面板入口：右上角齿轮 / 右键点小蝶 / 托盘「设置…」）；
> 播放时 SVG 嘴型随之开合（Live2D 未做，用 CSS 动画代替）。
>
> **同步做法**：回复按句切分 → 逐句「合成 → 播放 → 播到哪句就把哪句写进气泡」；
> 打字机推进速度取自这段音频的真实时长（`AudioBuffer.duration`），因此字与声音基本对齐；
> 播放当前句时预取下一句（最多并行 2 条）以减少句间空白；超过 45 字的句子再按逗号切一刀，
> 让第一段音频更快返回、更快开口。合成失败的句子直接整句显示文字，只丢声音不丢内容。

### 3.4 Live2D 形象与动作

使用 Live2D Cubism 模型渲染（WebGL），支持待机呼吸、眨眼、口型同步。

动作行为清单（按优先级）：

1. **待机**：呼吸、眨眼、尾巴轻摆、呆毛微动。
2. **交互反馈**：点击头部（害羞/脸红）、点击身体（轻微晃动）、拖拽（被拎起）、放下（落地动作）。
3. **情绪动作**：开心（尾巴甩、笑脸）、困倦（打哈欠、闭眼）、思考（歪头）、惊讶。
4. **语音口型**：按音频包络驱动嘴部开合。
5. **主动行为**：随机走动（窗口位移）、整点报时、深夜犯困提醒。

文本中的动作描述可映射触发 Live2D motion（如「尾巴甩了甩」→ 对应 motion）。

首版仅「小蝶」一个形象，后续再扩展多形象切换。

### 3.5 截屏感知（用户可关闭，默认关闭）

定时截取屏幕缩略图（默认 60 秒，最小 30 秒），压缩后交给视觉模型判断用户当前活动类型（写代码 / 看视频 / 开会 / 空闲等）。

**隐私与生命周期约束**：

- 默认关闭，开启需明确弹窗告知并二次确认。
- 只上传缩略图（低分辨率），原始截图不落盘、不写日志。
- 感知结果在桌宠完成对应行为（如生成陪伴话术、触发动作）后立即删除，不做持久保留，不建持久表。
- 提供「临时暂停感知」快捷入口。
- 感知结果驱动主动行为（见 3.6）。

### 3.6 主动行为与状态机

状态机：`idle → walking → talking → reacting → sleeping`。

触发源：定时器（随机待机动作）、用户交互、系统时间、截屏感知结果、平台事件（如工作流运行完成通知）。

主动搭话受 2.6 频率配置约束，且不得在全屏/会议场景打扰。

### 3.7 与平台能力的联动

桌宠作为「平台助理」的桌面入口：用户在气泡里说「帮我看看昨天那个工作流跑成功没」，桌宠通过本地 HTTP 调用 NestJS 后端，走既有 Agent 工具链查询并回报。

权限校验、风险确认、审计日志与网页端一致；HIGH 风险操作（如发布工作流）在桌宠端同样必须用户明确确认。

桌宠端不缓存敏感数据；登录态复用网页端 token，但采用短时效凭证（短 TTL access token + 刷新机制），不长期驻留长效 token。

## 4. 记忆可视化网络（新增）

### 4.1 定位

「记忆」是平台助理的上下文资产：每次重要对话、用户偏好、任务结论等可沉淀为一条记忆。记忆模块提供一个可进入的 3D 可视化神经网络，让用户直观看到助理「记得什么」，并可查看每条记忆的详情。

入口：聊天页 / 桌宠设置中提供「记忆」入口，点击进入 3D 可视化页面。

> **落地调整（v1.0 实施）**：人格与记忆的入口统一收进「Agent 管理 → 平台助理」的配置页（人格 / 记忆两个 Tab），
> 不做侧边栏独立菜单——它们是平台助理这个 Agent 的属性，不是独立功能模块。详见实施方案 §6。

### 4.2 视觉表现（Three.js）

使用 Three.js 渲染 3D 发光神经网络，从中心向四周发散，形似宇宙。

- 中心为「核心节点」（代表助理本体），周围为记忆节点，节点之间以发光线连接（连线可表示记忆间关联强度）。
- 每个记忆节点都是一个发光点，亮度/大小映射记忆重要度或新近程度。

**交互**：

- 轨道旋转、缩放、平移（OrbitControls）。
- 悬停高亮节点。
- 点击节点弹出记忆详情面板：分类、简要描述、存储的原文。
- 支持按分类过滤（高亮某类节点）。

**性能**：节点较多时采用实例化渲染（InstancedMesh）、LOD、按需渲染；限制同时渲染节点数上限，超出分页/聚合。

**视觉安全**：渲染器只消费平台定义的数据结构，不执行模型生成的任意代码；节点数据来自后端接口。

### 4.3 记忆数据结构（建议）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 记忆 id |
| `userId` | string | 归属用户 |
| `agentId` | string | 归属助理（首版为系统默认助理） |
| `category` | string | 分类（偏好 / 事实 / 任务 / 事件 / 情感 / 其他） |
| `summary` | string | 简要描述（用于详情面板与悬停提示） |
| `content` | text | 原文（存储完整内容） |
| `importance` | number | 重要度（映射节点亮度/大小） |
| `embedding` | vector | 向量（用于对话召回，可选） |
| `sourceConversationId` | string? | 来源会话 |
| `createdAt` / `updatedAt` | datetime | 时间 |
| `lastAccessedAt` | datetime? | 最近召回时间 |

记忆间关联可单独存 `memory_links`（sourceId、targetId、weight），用于渲染连线。

### 4.4 记忆的生成与召回

- **生成**：由助理在对话后按规则或模型判断沉淀记忆（分类 + 摘要 + 原文），需可配置开关与审核（首版建议自动生成、用户可在记忆页删除）。
- **召回**：对话时按向量相似度 + 重要度 + 新近度召回若干条（建议 5~10 条）注入上下文；召回同样受用户授权与隐私约束。
- **删除**：用户在 3D 页面可删除单条记忆；提供「清空全部记忆」入口并二次确认。

### 4.5 隐私约束

- 记忆归属于当前用户，不跨用户共享；审计可查但记忆内容不进入他人上下文。
- 敏感信息（如密码、密钥）不应被沉淀为记忆；生成侧需做敏感信息过滤。
- 记忆原文仅在详情面板按需加载，列表/可视化接口只返回摘要与元信息。

## 5. 技术方案要点

### 5.1 客户端容器

推荐 Electron：复用现有 Vue 3 前端代码，透明置顶窗口配置简单（`transparent`、`frame:false`、`alwaysOnTop`、`setIgnoreMouseEvents`）。

备选 Tauri（体积小，但需 Rust，透明窗口在部分 Linux 环境需验证）。

注意 Windows 混合 DPI 下拖拽坐标漂移问题，需做 DIP/物理像素换算。

### 5.2 渲染、语音与 3D

- **Live2D**：`pixi-live2d-display` 或官方 Cubism SDK for Web，渲染在渲染进程。
- **TTS**：Edge TTS（本地优先，后端代理兜底），音频包络驱动口型。
- **截屏**：Electron `desktopCapturer` 获取缩略图，压缩后经后端转发视觉模型；结果用完即删。
- **记忆可视化**：Three.js + OrbitControls，前端消费后端记忆接口；大数据量用 InstancedMesh + LOD。

### 5.3 与后端的关系

```text
Electron 桌宠（Vue 渲染进程 + Live2D + Three.js）
        │ IPC / HTTPS（短时效 token）
        ↓
NestJS 后端（复用 Agent / AI Provider / TTS / 工具链 / 审计 / MemoryService）
```

对话与 Agent 决策走既有后端，不重复实现 AI 逻辑。TTS 本地优先，失败回落后端。记忆的生成、存储、召回、删除均由后端 `MemoryService` 统一管理。

### 5.4 数据模型补充（建议）

| 模型 | 关键字段 | 用途 |
|---|---|---|
| `AgentPersona`（或 Agent 内 JSON） | agentId, name, tags, systemPrompt, avatar, voiceId, speechRate, pitch, proactiveChatEnabled, proactiveChatFrequency, personaVersion | 人格配置 |
| `DesktopPetSettings` | userId, enabled, voiceEnabled, proactiveChatEnabled, screenPerceptionEnabled, interval, position, scale | 用户桌面端偏好 |
| `Memory` | 见 4.3 | 记忆条目 |
| `MemoryLink` | sourceId, targetId, weight | 记忆关联，用于 3D 连线 |
| `PerceptionRecord` | 不建持久表，感知结果内存态使用、用完即删 | 截屏感知 |

> **落地说明**：实际实现中人格采用**独立表**而非 Agent 内 JSON 字段——
> `AgentService.update()` 对系统 Agent 只放开 `llmModelId / model / temperature` 三个字段，
> 人格若挂在 Agent 上会被 400 拒绝。详见实施方案 §2 决策 D1。

## 6. 安全与隐私约束（必须遵守）

1. 人格提示词不得覆盖系统安全策略；「不承认是程序」仅作用于表达层，不改变服务端身份判定与权限。
2. 截屏感知默认关闭，开启需二次确认；只上传缩略图，原始截图不落盘不写日志；感知结果在桌宠完成对应行为后立即删除，不做持久保留。
3. 主动搭话默认关闭，开启后按配置频率限频，全屏/会议场景抑制打扰。
4. 桌宠端工具调用与网页端同权限、同审计、同风险确认；HIGH 风险必须用户确认。
5. 桌宠端登录态复用网页端 token 但采用短时效凭证，不长期驻留长效 token。
6. 记忆归属当前用户、不跨用户共享；生成侧过滤敏感信息；原文按需加载；提供删除与清空能力。
7. TTS/对话内容中的敏感信息不得写入日志；本地缓存最小化。
8. 托盘提供一键「暂停所有主动行为」与「退出桌宠」。
