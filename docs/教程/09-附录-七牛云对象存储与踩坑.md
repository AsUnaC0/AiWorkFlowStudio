# AI WorkFlow Studio 学习指南
## 第 9 篇（附录）：七牛云对象存储与踩坑实录 —— 私有空间的「签名下载」到底怎么回事

> **本篇是附录**：前面的教程（尤其是第 7 篇）都假设文件存在**本地磁盘** `uploads/` 下。
> 这篇讲清楚另一条路——把文件丢到 **七牛云对象存储** 里，以及我们在这路上踩过的**两个最典型的坑**：
> ① 私有空间用公开 URL 下载必然 **401**；② 七牛 SDK 拼出来的签名 URL **不带协议前缀**，axios 直接报 `Invalid URL`。
>
> 本篇按老规矩四步走：**配置发了什么 → 后端收到什么 → 后端怎么处理 → 返回/落盘到什么**。

## 1. 为什么要有「统一存储层」（local / qiniu 双驱动）

开发时文件直接丢本地磁盘，重启就没了、也不好共享；部署到服务器后磁盘又有限。
所以后端抽象出一个 **`StorageService`（`backend/src/storage/`）**，提供三个方法，业务代码根本不关心底层是磁盘还是七牛：

```
StorageService
│   storage.service.ts   ← 真正的双驱动实现
│   storage.module.ts    ← @Module，导出 StorageService（被 knowledge / queues 引入）
│
├── upload(buffer, originalName, subDir)   → { key, size }
│      仓库里怎么存：local=绝对路径；qiniu=对象 key
│
├── getLocalPath(key)                      → 文件在服务器上的临时路径
│      七牛模式：先把对象【下载到临时文件】再返回路径（供 pdf-parse 等解析）
│
└── delete(key)                            → 删文件 / 删七牛对象
```

`STORAGE_TYPE` 环境变量决定走哪个驱动，**默认 `local`**。切到七牛只需改 `.env` + 重启，三处调用方（上传 Controller、解析 Processor、删除 Service）一行都不用改 —— 这就是「面向接口编程」的效果。

> **调用方是谁**：`documents.controller.ts`（上传）、`document.processor.ts`（解析）、`document.service.ts`（删除）。都只要 `import { StorageService }`，靠 NestJS 构造器注入。

## 2. 环境变量：怎么切到七牛

`backend/.env`（注意：`.env` 被 gitignore 忽略，不会进仓库）：

```env
# ============================================
# 存储配置：local（本地磁盘） | qiniu（七牛云对象存储）
# ============================================
STORAGE_TYPE=qiniu

# --- 七牛云配置（STORAGE_TYPE=qiniu 时生效） ---
QINIU_ACCESS_KEY=你的AK
QINIU_SECRET_KEY=你的SK
QINIU_BUCKET=lumobi
QINIU_REGION=z2
QINIU_DOMAIN=https://tmmwuqu7h.hn-bkt.clouddn.com

# --- 本地存储配置（STORAGE_TYPE=local 时生效） ---
LOCAL_UPLOAD_DIR=uploads
```

| 变量 | 谁在读 | 含义 | 配错会怎样 |
|------|--------|------|-----------|
| `STORAGE_TYPE` | `storage.service.ts` 构造函数 | `local` / `qiniu` 二选一，默认 `local` | 空着走本地 |
| `LOCAL_UPLOAD_DIR` | 同一个构造函数 | 本地模式的上传根目录 | 不配默认 `uploads`（相对后端运行目录） |
| `QINIU_ACCESS_KEY` / `QINIU_SECRET_KEY` | `initQiniu()` | 七牛控制台「密钥管理」里的一对 AK / SK | **缺一个启动直接抛错**，提示你去检查这三个变量 |
| `QINIU_BUCKET` | `initQiniu()` | 空间（Bucket）名，如 `lumobi` | 同上，必填 |
| `QINIU_REGION` | `initQiniu()` | 空间所在区域，默认 `z0`（华东） | **区域和实际不一致 → 上传卡住/慢/失败**（见坑⑤） |
| `QINIU_DOMAIN` | `initQiniu()` + `downloadQiniuToTemp()` | 空间绑定的 CDN 域名 | 私有空间下载全靠它拼 URL，忘了配会报「未配置 QINIU_DOMAIN」 |

区域映射（`zoneMap`）：

| `QINIU_REGION` | 对应 Zone | 地理位置 |
|----------------|-----------|----------|
| `z0`（默认） | `Zone_z0` | 华东 |
| `z1` | `Zone_z1` | 华北 |
| `z2` | `Zone_z2` | 华南 |
| `na0` | `Zone_na0` | 北美 |

> **AK/SK 是最高机密**：有了它们等于有了这把空间的钥匙。.env 不进 git、不要截图发群、不要写进任何文档/博客。
> 本教程里一律用 `你的AK / 你的SK` 代替。

启动时后端会打印一行：
```
[Storage] 使用七牛云存储，Bucket：lumobi，Region：z2
```
看到这行，说明配置读到了、切七牛成功了。

## 3. 写入路：上传一个 PDF（对象 key 长什么样）

第 7 篇 §4.2 讲过 Controller 只做 5 件事，现在中间那步「落盘」从「直接写 `uploads/`」换成了 `storageService.upload(...)`：

```typescript
// documents.controller.ts  upload()
// 2) 通过 StorageService 上传（本地磁盘 / 七牛云 自动切换）
const uploaded = await this.storageService.upload(
  file.buffer,          // 文件名和内容都在内存 buffer 里（multer 默认内存模式）
  file.originalname,    // 只用来抠扩展名 .pdf/.docx/...
  `documents/${kbId}`,  // 子目录：knowledge_base 的 uuid
);

// 3) 建文档记录 —— ★ storagePath 存的是上传返回的 key
await this.documentService.create({
  ...
  storagePath: uploaded.key,
  status: 'UPLOADED',
});

// 4) 入队 —— ★ Job data 里的 storagePath 同样存 key
await this.documentQueue.add('process-document',
  { documentId: doc.id, knowledgeBaseId: kbId, storagePath: uploaded.key },
  ...
);
```

### 3.1 local 模式：key = 服务器上的绝对路径

`uploadLocal()` 把 key 拼成 `join(uploads, subDir, uuid.pdf)`，然后 `writeFile` 写盘。

```
D:\...\backend\uploads\documents\<kbId>\3f2c0e6e-….pdf
```

数据库 `Document.storagePath` 里存的就是这个绝对路径（第 8 篇的文档记录示例能看到本地模式的真实路径样例）。

### 3.2 qiniu 模式：key = 空间里的对象地址，揉了一个日期

`uploadQiniu()` 的关键几步：

```typescript
const datePath = new Date().toISOString().slice(0, 10);        // 2026-10-10
const key = `${subDir}/${datePath}/${randomUUID()}${extension}`;
// key = documents/<kbId>/2026-10-10/3f2c0e6e-….pdf

const putPolicy = new qiniu.rs.PutPolicy({ scope: `${this.bucket}:${key}` });
const uploadToken = putPolicy.uploadToken(this.mac!);          // 上传凭证（后台盖签名章）

const formUploader = new qiniu.form_up.FormUploader(this.qiniuConfig!);
formUploader.put(uploadToken, key, buffer, putExtra, (respErr, respBody, respInfo) => {
  if (respErr) throw new InternalServerErrorException(`上传七牛云失败：${respErr.message}`);
  if (respInfo.statusCode !== 200) throw new InternalServerErrorException(`上传七牛云失败：HTTP ${respInfo.statusCode}`);
  // 成功 → resolve({ key: respBody.key, size: respBody.fsize ?? buffer.length })
});
```

要点：

- **key 里有日期**：`2026-10-10` 是自动加的，等于按天归档，方便以后在控制台按日排查、做生命周期策略（比如自动清理 30 天前的旧文件）。
- **scope = `《bucket》:《key》`**：这是七牛的上传凭证写法，意思是「只允许往这个空间的这个对象上传」，把权限收得最小。
- **上传是对外网络请求**：`FormUploader` 是异步回调，我们用 `Promise` 包一层扔回给调用方。失败会抛 `上传七牛云失败：…` 的 500。

> **savePoint**：本地模式 `storagePath` 是**磁盘路径**；七牛模式 `storagePath` 是**对象 key**。
> 同一个字段两种语义，`document.processor.ts` 注释里就写着：
> `storagePath: string; // local: 绝对路径；qiniu: 对象 Key`
> —— 读代码时看到 `storagePath` 先别急着当成文件路径，先看 `STORAGE_TYPE`。

## 4. 读取路：后台解析时怎么把对象「弄回本地」

上传接口只负责落对象 + 入队就返回。真正的解析在 `document.processor.ts`（BullMQ Worker）里：

```typescript
// ② 通过 StorageService 解析出可读取的本地路径（七牛云会先下载到临时文件）
let localPath = storagePath;
if (this.storageService.type === 'qiniu') {
  localPath = await this.storageService.getLocalPath(storagePath);
}
const text = await this.documentParserService.parse(localPath);
```

`getLocalPath(key)`：local 模式直接返回 key（本来就是路径）；qiniu 模式调用 `downloadQiniuToTemp(key)`——**先把对象拉到系统临时目录，再让 `pdf-parse` 这类只能读本地文件的解析器去读**。

### 4.1 ★ 私有空间下载的全部戏法：`downloadQiniuToTemp`

这一步正是坑②的藏身之处，整个方法长这样：

```typescript
private async downloadQiniuToTemp(key: string): Promise<string> {
  const tempDir = await mkdtemp(join(tmpdir(), 'qiniu-dl-')); // 系统临时目录建一个专属文件夹
  const fileName = key.split('/').pop()!;                     // 取 key 最后一段做临时文件名
  const tempPath = join(tempDir, fileName);

  // 1) 域名去掉末尾的「/」
  const rawDomain = (this.domain || '').replace(/\/$/, '');

  // 2) 规范化：确保有协议前缀（签名必须带协议！见坑②、坑③）
  const withHttp  = /^https?:\/\//i.test(rawDomain) ? rawDomain : `http://${rawDomain}`;
  const bareDomain = withHttp.replace(/^https?:\/\//i, '');
  const withHttps = withHttp.startsWith('https://') ? withHttp : `https://${bareDomain}`;

  // 3) 构造候选 URL 列表 —— 签名 URL 放最前面（私有空间不签名必 401）
  const allUrls: string[] = [];
  if (this.mac && this.qiniuConfig) {
    const bucketManager = new qiniu.rs.BucketManager(this.mac, this.qiniuConfig);
    const deadline = Math.floor(Date.now() / 1000) + 3600;    // ★ 过期时间戳：现在+1小时

    // 用 http:// 协议签名（CDN 证书可能有问题，优先 http，见坑③）
    const signedHttp  = bucketManager.privateDownloadUrl(withHttp,  key, deadline);
    allUrls.push(signedHttp);
    // 再用 https:// 签名一份兜底
    const signedHttps = bucketManager.privateDownloadUrl(withHttps, key, deadline);
    allUrls.push(signedHttps);
  }

  // 4) 再放两个公开 URL（公有空间用；私有空间会 401，排最后白试）
  allUrls.push(`${withHttp}/${key}`);
  allUrls.push(`${withHttps}/${key}`);

  // 5) 逐个试，第一个成功就落盘返回
  let lastError: unknown = null;
  for (const url of allUrls) {
    try {
      const response = await axios.get(url, {
        responseType: 'arraybuffer',
        timeout: 60_000,
        ...(url.startsWith('https:')
          ? { httpsAgent: new https.Agent({ rejectUnauthorized: false }) }  // 见坑③
          : {}),
      });
      await writeFile(tempPath, Buffer.from(response.data));
      return tempPath;                                  // 下载成功 → 临时路径
    } catch (err) {
      lastError = err;                                  // 失败 → 试下一个候选
    }
  }
  throw new InternalServerErrorException(`七牛云下载失败：${…lastError.message}`);
}
```

**核心思想就一句话**：挨个试，成功即停。顺序是

```
① http://  + SDK 签名 URL   （私有空间主力，图省证书麻烦）
② https:// + SDK 签名 URL   （签名 URL 的 https 兜底版）
③ http://  + key 拼的公网 URL（只有公有空间能用）
④ https:// + key 拼的公网 URL（同上）
```

为啥签名 URL 要在前面？因为**私有空间要求每个请求都带 token**，公网 URL 一访问就 401（坑①）。公有空间反过来：签名也能用但没必要，公网 URL 更快。这份候选列表把两种空间都覆盖了，还能优雅降级。

### 4.2 临时文件怎么收拾

`document.processor.ts` 的 `try/catch/finally` 里：

```typescript
let tempPath: string | null = null;          // 七牛模式下载的临时文件路径
let localPath = storagePath;
try {
  ...
  if (this.storageService.type === 'qiniu') tempPath = localPath;
  localPath = await this.storageService.getLocalPath(storagePath);
  const text = await this.documentParserService.parse(localPath);
  ...后续切块/向量化...
} finally {
  // 清理七牛云下载的临时文件（解析完就删，别在系统临时目录里堆垃圾）
  if (tempPath) { try { await unlink(tempPath); } catch {} }
}
```

要点：`mkdtemp` 每次建一个**独立临时目录**，`finally` 里 `unlink` 删掉下载的临时文件（目录本身是空的，系统会自己收拾）。失败重试时，重新 `mkdtemp` 再下载，互不干扰。

## 5. ★ 踩坑实录（本次接入实践中踩过的坑，浓缩在这）

按「现象 → 原因 → 修复」写，方便以后遇到同类问题直接对照。

### 坑① 私有空间：公网 URL 一发请求就 401
- **现象**：上传成功后，用 `http://域名/key` 直接在浏览器/axios 打开 → 返回 401。
- **原因**：你的 Bucket 是**私有空间**（控制台创建空间时选安全级别「私有」）。七牛的规则是：**公有空间**任何人拿到 URL 就能下载；**私有空间**所有请求必须带签名（`?e=过期时间&token=签名`），不带一律 401。
- **修复**：别再用「域名 + key」拼 URL，改用 SDK 生成签名 URL（见坑②），并按 §4.1 把签名 URL 放在候选列表最前。
- **自查**：控制台 → 空间 → 设置 → 「空间安全」，看看是公开还是私有。你那个 `tmmwuqu7h.hn-bkt.clouddn.com` 域名配的就是私有空间。

### 坑② SDK 拼出的签名 URL 不带协议前缀 → axios `Invalid URL`
- **现象**：这样调：
  ```
  bucketManager.privateDownloadUrl('tmmwuqu7h.hn-bkt.clouddn.com', key, deadline)
  ```
  拿到的字符串是 `tmmwuqu7h.hn-bkt.clouddn.com/documents/….pdf?e=…&token=…`，**开头没有 `http://`**。把它丢给 `axios.get(url)` 直接报：
  ```
  AxiosError: Invalid URL
  Invalid URL
  ```
- **原因**：七牛 SDK 的 `privateDownloadUrl` 是**按入参 domain 原样拼接**的。你传的是「裸域名」（没协议），它就返回「裸 URL」（也没协议）。axios 要求绝对地址，必须以 `http(s)://` 开头，所以歇菜。
  另外更隐蔽的一点：**签名是用 domain 参与计算的**。如果它真被拼成裸 URL，签名也可能对不上，就算你手动补了 `http://` 也能下载 401。（SDK 内部校验 `http` 前缀并据此构造完整 URL。）
- **修复**（当前代码已做两层防护）：
  1. 签名**之前**先把 domain 规范化，保证带协议：
     ```typescript
     const withHttp  = /^https?:\/\//i.test(rawDomain) ? rawDomain : `http://${rawDomain}`;
     ```
  2. 用**带协议**的 domain 去签（`withHttp`、`withHttps` 各签一份），这样拿回来的 URL 自带 `http(s)://`，axios 直接能用。
- **自查**：`console.log(url)` 看看开没开头 `http`。以后写任何给 axios/fetch 用的地址，先确认是绝对 URL。

### 坑③ https 证书：CDN 证书有问题，axios 直接握手失败
- **现象**：签名 URL 换成 `https://` 后，axios 报 `self signed certificate` / `certificate has expired` 之类的 TLS 错误。
- **原因**：测试域名的 CDN 证书链不完整或过期，Node 的 https 默认严格校验证书（`rejectUnauthorized: true`），握不上手。
- **修复**（两层）：
  1. **优先用 `http://` 版本签名下载**（代码里 `signedHttp` 排第一）。
  2. https 版本兜底时，给 axios 挂一个**忽略证书校验**的 agent：
     ```typescript
     new https.Agent({ rejectUnauthorized: false })
     ```
- **⚠️ 不要当成通用方案**：`rejectUnauthorized: false` 等于不验证对方身份，属于「能跑就行」的兜底。正式上线换了正式域名/证书以后，建议去掉它，把 http 版本也干掉，只留 https 提权。

### 坑④ 域名末尾多了个 `/`
- **现象**：`QINIU_DOMAIN=https://tmmwuqu7h.hn-bkt.clouddn.com/`（末尾带斜杠）时，拼出来的 URL 变成 `…clouddn.com//documents/…` 或签名对不上。
- **原因**：控制台复制域名常常自带 `/`。
- **修复**：代码里 `this.domain.replace(/\/$/, '')` 统一剥掉末尾斜杠；你自己配 `.env` 时也顺手别带 `/`。

### 坑⑤ `QINIU_REGION` 配错：上传不报错但巨慢/超时
- **现象**：上传偶尔成功偶尔超时，后台日志 `上传七牛云失败：HTTP 0` 或干脆卡住。
- **原因**：空间在华南（`z2`），配置里却写 `z0`（华东，默认值）。SDK 拿它去连华东入口，请求转了一大圈或直接超时。
- **修复**：去控制台看空间所在区域，把 `QINIU_REGION` 配成对应的值（本教程环境是 `z2`）。启动日志会打印 `Region：z2`，对不上就改。

### 坑⑥ 别忘了 `getDownloadUrl()` 现在返回的是公网 URL
- **现状**：`getDownloadUrl()` 里签名 URL 的代码是**注释掉的**，现在返回 `${cleanDomain}/${key}`——这在私有空间下浏览器打开就是 401。
- **为什么能跑**：因为目前整个项目**没有任何地方调用它**（文档下载走的是 §4 的解析链路，不需要暴露公网 URL）。
- **将来要用**（比如给前端返回「点击下载」链接）时，记得把签名那段取消注释，改成给私有空间签名的逻辑，否则用户一下一个 401。

### 坑⑦ 删知识库不会删七牛对象（已知缺口）
- **现象**：`STORAGE_TYPE=qiniu` 时删掉一个知识库，数据库里的文档没了，但七牛云控制台里对象还在，日积月累堆积。
- **原因**：删**单个文档**走的是 `StorageService.delete()`（会删七牛对象）；但删**整个知识库**走的是 `knowledge.service.ts` 里的 `rm(join(UPLOAD_DIR, id))`——**只 rm 本地目录**，在七牛模式下那个目录根本不存在，等于什么也没删。
- **修复建议**（目前未做）：删知识库前先查出该库下所有文档的 `storagePath`（对象 key），逐个 `storageService.delete()`，或改用七牛的分批删除接口。在这之前，七牛模式下删库后需要去控制台手动清对象。

> **一句话总结本次修复**：
> 私有空间 → 必须签名；签名 = domain 先补协议再给 SDK；下载顺序 = 签名 http → 签名 https → 公网 URL。
> 不要再问「为啥 401」「为啥 Invalid URL」了，答案都在坑①和坑②。

## 6. 怎么验证你接入成功（从零到跑通 6 步）

1. **改 `.env`**：`STORAGE_TYPE=qiniu` + 填好 AK/SK/Bucket/Region/Domain。
2. **重启后端**，看 stdout 里有没有 `[Storage] 使用七牛云存储，Bucket：…，Region：…`。
   - 如果直接抛 `七牛云存储配置不完整…`，说明 AK/SK/Bucket 缺一，回头补。
3. **传一个 PDF**（前端知识库详情页「上传文档」，或 curl）。
   - 预期返回 `{ status: 'UPLOADED', jobId, … }`；数据库 `Document.storagePath` 变成了 `documents/<kbId>/2026-10-10/uuid.pdf`（一个 key，不是路径）。
4. **盯后端日志**，Worker 会依次打印：
   ```
   [DocumentProcessor] Job 5 started …
   [Storage] 尝试下载：http://…/documents/…pdf?e=…&token=…
   [Storage] 七牛云下载成功：http://…?e=…&token=…
   [DocumentProcessor] Job 5 completed for document …
   ```
   看到「尝试下载 → 下载成功」就说明私有空间签名链路通了。
5. **看文档状态**：变成 `COMPLETED`（成功）或 `FAILED` + `errorMessage`（失败，错误原因就在 `errorMessage` 里）。
6. **手动 curl 验证签名 URL**：把日志里那条 `http://…?e=…&token=…` 整条粘到地址栏，能直接下到文件；把 `?e=…&token=…` 去掉再开，必然 401——完美演示坑①。

## 7. 本篇小结（速查表）

| 问题 | 一句话答案 |
|------|-----------|
| 怎么切七牛 | `.env` 设 `STORAGE_TYPE=qiniu` + 填 `QINIU_*`，重启 |
| 上传后文件在哪 | 空间里 key = `documents/<kbId>/<日期>/<uuid>.pdf` |
| 数据库存的是什么 | `storagePath` = 对象 key（不是路径），语义跟 `STORAGE_TYPE` 走 |
| 私有空间怎么下载 | 必须签名 URL：domain 先补协议 → `privateDownloadUrl(带协议domain, key, deadline)` |
| 为什么用候选列表 | 签名 URL 优先（私有空间），公网 URL 兜底（公有空间），成功即停 |
| 401 是什么 | 空间是私有的，请求没带签名 token |
| `Invalid URL` 是什么 | 传给 axios 的 URL 缺 `http(s)://` 前缀，先去 `console.log(url)` |
| https 报证书错 | 测试域名证书不完整 → 优先 http，或 `httpsAgent: rejectUnauthorized:false`（临时） |
| 临时文件会清理吗 | 会，`mkdtemp` 建独立目录，`finally` 里 `unlink` |
