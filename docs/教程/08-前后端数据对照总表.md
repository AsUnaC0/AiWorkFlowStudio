# AI WorkFlow Studio 学习指南
## 第 8 篇：前后端数据对照总表（全部 28 个接口逐一拆解）

> **本篇是全书收尾**。前 7 篇教会了你走通链路原理，这一篇给一份“字典”：
> 每个接口 → **前端发什么 → 后端怎么校验 → 后端怎么处理 → 返回什么 → 前端类型怎么定义**。
> 以后写新页面、修 bug、加接口，都回来翻这一篇。
>
> 全后端实际 **28** 个接口；前端 API 层封装了其中 **25** 个（有 3 个后端接口前端暂未调用，见文末）。

---

## 0. 公共约定（先读）

| 约定 | 值 |
|------|----|
| Base URL | 前端 `/api` 前缀被 Vite 代理到 `http://localhost:3000`（axios 直接写 `/auth/login`，fetch 需要写 `/api/...`） |
| 响应解包 | axios 拦截器直接返回 `response.data`，所以 `request.get()` 拿到的就是业务 JSON |
| 鉴权 | `Authorization: Bearer <accessToken>`；登录返回的 `accessToken` 存 Pinia + localStorage |
| 未登录访问保护接口 | 401，前端拦截器自动登出并跳 `/login` |
| Token 过期 | JWT 过期，返回 `{ statusCode: 401, message: "Unauthorized" }` |
| 参数错误 | NestJS 全局校验管道返回 `{ statusCode: 400, message: [...y],"error": "Bad Request" }`，`message` 是数组 |
| 内容类型 | JSON 用 `request`（自动 `application/json`）；文件上传必须 FormData + `fetch`（第 5/6 篇讲过的坑） |

**28 个接口全览：**

| 模块 | 接口数 | 路径前缀 |
|------|-------|---------|
| Auth | 3 | `/auth/*` |
| AI | 2 | `/ai/*` |
| Workspaces | 5 | `/workspaces/*` |
| Workflows（含运行） | 6 | `/workspaces/:id/workflows`、`/workflows/:id`、`/workflow/run*` |
| Knowledge（含文档） | 12 | `/knowledge-bases/*`、`/workspaces/:id/knowledge-bases/*`、`/documents/*` |

## 1. Auth 认证（3 个）

### 1.1 注册 `POST /auth/register`

| 项 | 内容 |
|----|------|
| 鉴权 | **公开**（无需 token） |
| 请求体 | ```json { "username": "小明", "email": "ming@example.com", "password": "123456" } ``` |
| 前端类型 | `RegisterRequest { username, email, password }`（types/auth.ts） |
| 后端 DTO | `RegisterDto`：username `IsString+IsNotEmpty`，email `IsEmail+IsNotEmpty`，password `IsString+IsNotEmpty+MinLength(6)` |
| 处理 | ① 查 email 重复 → `409 ConflictException('Email already registered')`；② 查 username 重复 → `409`；③ `bcrypt.hash(password, 10)`；④ 建 User |
| 响应 201 | ```json { "user": { "id": "4f6...", "username": "小明", "email": "ming@example.com", "createdAt": "2026-...", "updatedAt": "2026-..." }, "accessToken": "eyJhbGciOiJIUzI1NiIs..." } ``` |

> **注意两个坑**：① 响应里的 `user` **不会包含 `passwordHash`**——`auth.service.toPublicUser` 解构时把它剔除了（`const { passwordHash, ...result } = user`），所以 JSON 里只有 5 个字段。② `AuthResponse.user`（types/auth.ts）正好是这 5 个字段：`{ id, username, email, createdAt, updatedAt }`，前后端一致。

### 1.2 登录 `POST /auth/login`

| 项 | 内容 |
|----|------|
| 鉴权 | **公开** |
| 请求体 | ```json { "email": "ming@example.com", "password": "123456" } ``` |
| 前端类型 | `LoginRequest { email, password }` |
| 后端 DTO | `LoginDto`：email `IsEmail`，password `IsString+IsNotEmpty` |
| 处理 | 查 user → 无或 `bcrypt.compare` 失败 → **统一 `401 'Invalid credentials'`**（不区分用户不存在/密码错） |
| 响应 200 | 同注册：`{ user, accessToken }` |

### 1.3 当前用户 `GET /auth/me`

| 项 | 内容 |
|----|------|
| 鉴权 | **Bearer** |
| 前端 | `auth.ts getCurrentUser(): Promise<User>`（⚠️ 整个项目没地方调用它，见第 6 篇缺陷清单） |
| 处理 | 从 JWT `sub` 查 DB，返回 PublicUser |
| 响应 | `{ id, username, email, createdAt, updatedAt }` |

## 2. AI 大模型（2 个）

### 2.1 模型列表 `GET /ai/models`

| 项 | 内容 |
|----|------|
| 鉴权 | **Bearer**（Controller 级 `@UseGuards`） |
| 前端 | `ai.ts getModels(): Promise<ListModelsResponse>` |
| 后端 | 调 Ollama `GET http://localhost:11434/api/tags`，映射为 `{ name, size, modifiedAt }` |
| 未启动 Ollama | **不报错**，返回兜底默认模型列表 + `note` 字段 |
| 响应 | ```json { "provider": "ollama", "models": [ { "name": "qwen2.5:7b", "size": 4863347937, "modifiedAt": "2026-..." }, { "name": "nomic-embed-text", "size": 274000000, "modifiedAt": null } ] } ``` |

> 兜底默认值（Ollama 没起来时）：
> ```json
> { "provider": "ollama",
>   "models": [ {"name":"qwen2.5:7b"}, {"name":"qwen2.5:3b"}, {"name":"deepseek-r1:7b"}, {"name":"nomic-embed-text"} ],
>   "note": "Ollama 未连接，返回默认模型列表" }
> ```
> LLM 节点下拉框、Chat 页模型下拉框都用它。**注意：模型名必须和 Ollama 里 `ollama list` 完全一致**（含 tag），否则跑节点时报错。

### 2.2 聊天 `POST /ai/chat`

| 项 | 内容 |
|----|------|
| 鉴权 | **Bearer** |
| 请求体 | ```json { "model": "qwen2.5:7b", "messages": [ { "role": "system", "content": "你是客服助手" }, { "role": "user", "content": "退款多久到账？" } ], "temperature": 0.7, "maxTokens": 512, "knowledgeBaseIds": ["kb-uuid"] } ``` |
| 前端类型 | `ChatRequest { model, messages, temperature?, maxTokens?, knowledgeBaseIds? }` |
| 后端校验 | `model` 为空 → 400；`messages` 空 → 400（其余零校验） |
| 处理 | 透传 `AIService.chat`；`temperature` 默认 `0.7`。**`knowledgeBaseIds` 被忽略（源码 TODO）** |
| 响应 | ```json { "content": "通常 3~5 个工作日到账…", "model": "qwen2.5:7b", "usage": { "promptTokens": 128, "completionTokens": 96, "totalTokens": 224 } } ``` |
| 前端类型 | `ChatResponse { content, model, usage? }` |

> **非流式**：做不出打字机效果。要流式只能用 `GET /event-stream`（投喂模块，第 5 篇讲过）或工作流 `POST /workflow/run/stream`。

## 3. Workspaces 工作空间（5 个）

> 权限模型：**读** = owner 或 member；**改/删** = 仅 owner。

### 3.1 创建 `POST /workspaces`

| 项 | 内容 |
|----|------|
| 请求体 | ```json { "name": "我的空间" } ``` |
| 前端类型 | `CreateWorkspaceRequest { name }` |
| 后端 DTO | `CreateWorkspaceDto`：name `MaxLength(100)` |
| 处理 | 建 Workspace `ownerId = 当前用户`，**同时** `members.create({ userId })`（事务里两条表） |
| 响应 201 | ```json { "id": "6f2...", "name": "我的空间", "ownerId": "4f6...", "createdAt": "...", "updatedAt": "...", "_count": { "members": 1, "workflows": 0 } } ``` |

### 3.2 列表 `GET /workspaces`

| 项 | 内容 |
|----|------|
| 条件 | `WHERE ownerId = me OR members.some(userId = me)` |
| 排序 | `createdAt DESC` |
| 响应 | 数组，每个元素同 3.1（含 `_count`） |
| 前端类型 | `WorkspaceApiItem[]`；页面里再转成 `WorkspaceItem { workflowCount, knowledgeCount, reportCount, memberCount }`（types/workspace.ts，注意 reportCount 后端不返回，前端补 0） |

### 3.3 详情 `GET /workspaces/:id`

| 项 | 内容 |
|----|------|
| 权限 | 非 owner/非 member → `404 Workspace not found`（不泄露存在性） |
| 响应 | 单个 Workspace（同 3.1） |
| 前端 | ⚠️ 前端 API 层**没封装**（api/workspace.ts 只有 3 个函数） |

### 3.4 更新 `PUT /workspaces/:id`

| 项 | 内容 |
|----|------|
| 请求体 | ```json { "name": "新名字" } ``` |
| 权限 | `assertOwner` → 非 owner → `403 'Only the workspace owner can modify it'` |
| 前端 | ⚠️ 前端 API 层**没封装** |

### 3.5 删除 `DELETE /workspaces/:id`

| 项 | 内容 |
|----|------|
| 权限 | 仅 owner（403） |
| 处理 | 直接删（Workflow 等子表靠外键级联） |
| 响应 | 返回被删对象（前端 `deleteWorkspace` 推断 `void`，实际有值但不读） |

## 4. Workflows 工作流（6 个）

> **核心机制回顾**（第 4 篇）：保存 = 存 Vue Flow 原样节点（`type:"custom"` + 配置在 `data`）；**运行 = 转业务类型 + 配置搬进 `config`**。两个 DTO 里的 `definition` 都是 `Record<string, unknown>`（宽类型），前端见第 6 篇不同格式差异。

### 4.1 创建工作流 `POST /workspaces/:workspaceId/workflows`

| 项 | 内容 |
|----|------|
| 权限 | workspace member（非成员 → `403 'You do not have access to this workspace'`） |
| 请求体 | ```json { "name": "客服流程", "description": "RAG 客服", "definition": { "nodes": [ { "id": "node1", "type": "custom", "position": {"x":0,"y":0}, "data": { ... } } ], "edges": [] } } ``` |
| 后端 DTO | `CreateWorkflowDto`：name `MaxLength(100)`，description `MaxLength(500)`，definition `IsObject` |
| 处理 | **事务**：① 建 Workflow + 建 **version 1**（`definition` 存 `versions[0]`）；② 用 `versions[0].id` 回填 `currentVersionId` |
| 响应 201 | `Workflow`（含 `currentVersion`） |
| 前端类型 | `Workflow { id, workspaceId, name, description, status, currentVersionId, currentVersion, createdAt, updatedAt }` |

### 4.2 列表 `GET /workspaces/:workspaceId/workflows`

| 项 | 内容 |
|----|------|
| 条件 | workspace member |
| 排序 | `updatedAt DESC` |
| 响应 | `Workflow[]`（**每项带 `currentVersion`**，前端下载用） |

### 4.3 详情 `GET /workflows/:id`

| 项 | 内容 |
|----|------|
| 查询 | `findFirst WHERE id = :id AND workspace.members.some(userId = me)` |
| 响应 | `Workflow` 或 `404 'Workflow not found'` |

### 4.4 更新 `PUT /workflows/:id`

| 项 | 内容 |
|----|------|
| 请求体 | ```json { "name": "新名字", "description": "...", "definition": { "nodes": [], "edges": [] } } ```（name/description 可选；**definition 必须有**） |
| 处理 | 查出最新 `version` → **事务**：建 version N+1，更新 Workflow 的 `currentVersionId` 指向新版本；name/description 只在传了才更新 |
| 响应 | `Workflow`（`currentVersion` 指向最新） |

### 4.5 运行（一次性）`POST /workflow/run`

| 项 | 内容 |
|----|------|
| ⚠️ 鉴权 | **没有 `@UseGuards`**（WorkflowController 类级无 Guard、body 是 `any`）——高风险遗留问题 |
| 请求体 | ```json { "workflow": { "nodes":[ { "id":"start1","type":"start","config":{},"data":{},"position":{"x":0,"y":0} } ], "edges":[] }, "input": "用户的问题或输入" } ``` |
| 前端类型 | `RunWorkflowRequest { workflow: WorkflowDefinition, input: unknown }` |
| 关键 | workflow 里的节点是**业务类型**（`start`/`input`/`llm`/`prompt`/`rag`/`http`/`condition`/`output`）+ 配置在 `config`，**不是保存时的 Vue Flow 格式**。类型写错（比如还是 `custom`）会报 `没有找到 Node Executor: custom` |
| 响应 | ```json { "input": "用户的问题或输入", "data": { "start1": {}, "rag_1": "【问题】…【知识库参考】[1]…", "llm_1": "答案文本" } } ``` |
| 前端类型 | `WorkflowRunResult { input, data }` |

### 4.6 运行（流式）`POST /workflow/run/stream`

| 项 | 内容 |
|----|------|
| 鉴权 | **无 Guard**（同上） |
| 请求 | 同 4.5（运行转格式后的定义） |
| 响应 | SSE。每行 `data: <json>\n\n`，前端按 `\n\n` 分割再取 `data: ` 行（api/workflow.ts 里手动实现） |

SSE 事件（对应前端 `WorkflowStreamEvent`）：

| type | 载荷字段 | 含义 |
|------|---------|------|
| `node:start` | `nodeId,nodeType,label?` | 某节点开跑 |
| `token` | `nodeId, content` | LLM 流式输出片段 |
| `node:complete` | `nodeId,nodeType,output,branch?,metadata?` | 节点完成；**condition 才有 branch 和 metadata** |
| `complete` | `data: Record` | 全部完成 |
| `error` | `message` | 出错 |

## 5. Knowledge 知识库（12 个）

> 权限模型：知识库/文档 **仅 owner**；空间关联动作要求 **workspace member 且（部分）kb owner**（第 7 篇 §3）。

### 5.1 建库 `POST /knowledge-bases`

| 项 | 内容 |
|----|------|
| 请求体 | ```json { "name": "公司制度库", "description": "行政文档", "embeddingModel": "nomic-embed-text", "embeddingDimension": 768 } ``` |
| 后端 DTO | name `MaxLength(200)`，description `MaxLength(1000)`，embeddingModel `MaxLength(100)`，dimension `Int 1..8192` |
| 处理 | `ownerId = 当前用户` |
| 响应 201 | `KnowledgeBase`（见 4.3's kbSelection，含 `_count: {documents, workspaces}`） |
| 前端类型 | `KnowledgeBase { id, ownerId, name, description, embeddingModel, embeddingDimension, documentCount, chunkCount, createdAt, updatedAt, _count? }` |

### 5.2 我的知识库 `GET /knowledge-bases`

| 项 | 内容 |
|----|------|
| 条件 | `ownerId = me`（**只能看自己的**） |
| 排序 | `createdAt DESC` |
| 响应 | `KnowledgeBase[]` |

### 5.3 详情 `GET /knowledge-bases/:id`

owner 校验：不存在的库 → 404；非 owner → 403。响应单个 `KnowledgeBase`。

### 5.4 更新 `PUT /knowledge-bases/:id`

请求体全部可选（同 Create 的字段）。注意：**改 embeddingModel/embeddingDimension 不会重新向量化已有文档**（旧向量还是老模型，检索维度可能不匹配）。响应 `KnowledgeBase`。

### 5.5 删除 `DELETE /knowledge-bases/:id`

| 项 | 内容 |
|----|------|
| 处理 | ① 删磁盘目录 `uploads/<id>`（`rm recursive force`）；② DB 删行（documents/chunks/links 级联删除） |
| 响应 | 被删的 `KnowledgeBase` |

### 5.6 空间关联列表 `GET /workspaces/:wsId/knowledge-bases`

| 项 | 内容 |
|----|------|
| 权限 | workspace member（非成员 → `403 'You do not have access to this workspace'`） |
| 处理 | 查 `WorkspaceKnowledgeBase` 拿 `knowledgeBaseId` 数组 → `findMany in (ids)`（**不再限 owner**，因为库里我才能关联） |
| 响应 | `KnowledgeBase[]` |

### 5.7 关联 `POST /workspaces/:wsId/knowledge-bases/:kbId`

| 项 | 内容 |
|----|------|
| 权限 | **workspace member 且 kb owner** |
| 处理 | `upsert`（避免重复） |
| 响应 | 204/201 空体（前端类型是 `Promise<void>`） |

### 5.8 解绑 `DELETE /workspaces/:wsId/knowledge-bases/:kbId`

workspace member 即可（无需 kb owner）。`deleteMany`，响应空体 204。

### 5.9 ★ 上传文档 `POST /knowledge-bases/:kbId/documents`（multipart）

| 项 | 内容 |
|----|------|
| 权限 | kb owner |
| 请求 | `multipart/form-data`，**字段名必须 `file`**；`FileInterceptor limits.fileSize = 50MB` |
| 前端实现 | 不走 axios，`fetch("/api/...")` + FormData + 手写 `Authorization`（api/knowledge.ts `uploadDocument`） |
| 允许扩展名 | `.pdf .docx .txt .md .markdown`（其他 → 400 '不支持的文件类型'） |
| 处理 | 落盘 `uploads/<kbId>/<docId><ext>` → 建记录 PROCESSING → 解析 → 切块 → 向量化 → **一次请求同步完成** → COMPLETED；失败 → FAILED + errorMessage，返回 500 |
| 响应 201 | `DocumentItem`（见 5.12），状态此时是 `COMPLETED` 或 `FAILED` |

### 5.10 文档列表 `GET /knowledge-bases/:kbId/documents`

kb owner；`createdAt DESC`。响应 `DocumentItem[]`。

### 5.11 文档详情 `GET /documents/:id`

kb owner（经 `assertDocumentOwner`）。响应 `DocumentItem`。
前端 ⚠️ 未封装。

### 5.12 删除文档 `DELETE /documents/:id`

| 项 | 内容 |
|----|------|
| 权限 | kb owner |
| 处理 | 删磁盘文件（失败只 warn）→ 删 DB 行 → **重算** documentCount 和 chunkCount |
| 响应 | **204 空体**（前端 `Promise<void>`） |

**DocumentItem 完整字段（前后端一致）：**

```json
{
  "id": "2a1...",
  "knowledgeBaseId": "6f2...",
  "fileName": "员工手册.pdf",
  "fileType": "PDF",
  "fileSize": 123456,
  "storagePath": "D:\\...\\uploads\\6f2...\\2a1....pdf",
  "mimeType": "application/pdf",
  "status": "COMPLETED",
  "errorMessage": null,
  "pageCount": null,
  "createdAt": "2026-...",
  "updatedAt": "2026-..."
}
```

> `status` 四种：`UPLOADED / PROCESSING / COMPLETED / FAILED`。
> `pageCount`、`tokenCount`（后端有字段）**永远 null**（没人维护，第 7 篇已知缺陷）。

## 7. 常见报错速查（对照表）

| 前端看到 | 实际原因 | 去查哪 |
|---------|---------|--------|
| 401 跳登录页 | 没带 token / JWT 过期 | 第 3 篇 3.x / 第 5 篇拦截器 |
| 400 `message` 是数组 | DTO 校验没通过（某个字段规则违反） | 本节对应 DTO |
| 400 `不支持的文件类型` | 上传了白名单外的扩展名 | §5.9 |
| 409 `Email already registered` | 注册邮箱已存在 | §1.1 |
| 403 `You do not own this knowledge base` | 动了别人的知识库/文档 | §5 |
| 403 `Only the workspace owner can modify it` | 非 owner 改/删工作空间 | §3.4/3.5 |
| 403 `You do not have access to this workspace` | 不是该空间成员 | §3/4/5.6 |
| 404 `xxx not found` | 权限不足也返回 404（故意不泄露） | §3.3 |
| 500 `没有找到 Node Executor: custom` | 运行把「保存格式」当「运行格式」传了 | 第 6 篇 §2 / §4.5 |
| 500 `文档处理失败：DOCX 解析尚未实现` | 传了 docx | 第 7 篇 §4.3 |
| 500 `expected 768 dimensions, not X` | embeddingModel 或 dimension 与模型不符 | 第 7 篇 §7 |
| Ollama 相关报错 | Ollama 没启动 / 模型没 pull | `ollama list` + `ollama pull <model>` |

## 8. 给编程新手的「怎么看这一篇」

1. **先看公共约定**（§0）——理解 axios 解包、鉴权头、错误结构。
2. **按模块挑一个接口**，先看「前端类型」和「请求体 JSON」，想象数据长什么样。
3. **看「后端 DTO」**——这就是「前端传什么，后端才收什么」。
4. **看「处理」和「响应」**——后端怎么花式加工，最后返回什么。
5. **最后对「前端类型」**——两边字段名一致就通了；不一致的地方文档已用 ⚠️ 标出。

> 规律：后端返回一律是**下划线的 snake 分不清？不——全部 camelCase**！
> 只有**数据库列名**是下划线 `snake_case`（不在 JSON 里出现），JSON 字段全是驼峰。别搞混。
