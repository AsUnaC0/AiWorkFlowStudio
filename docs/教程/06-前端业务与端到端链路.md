## 2. 登录页：views/login/index.vue

功能：登录/注册切换、表单校验、成功后跳 Dashboard。

核心逻辑：

```typescript
const isRegister = ref(false);          // 切登录 / 注册
const form = reactive({ username: "", email: "", password: "" });

const submitForm = async () => {
  // 基础校验（注册时 username 必填）
  const { user, accessToken } = isRegister.value
    ? await register(form)
    : await login(form);

  userStore.setToken(accessToken);      // 存 token（内存 + localStorage）
  userStore.setUserInfo(user);          // 存用户信息
  router.push("/dashboard");            // 跳首页
};
```

UI：左"品牌栏"（口号「让每个想法，流动起来。」）+ 右表单；`@media max-width: 720px` 下切换为单列——注意这个页面是**纯手写 CSS**，没用 TDesign 组件。

```typescript
const selectWorkspace = async (ws: WorkspaceItem) => {
  const workflows = await getWorkflows(ws.id);         // ① 查该空间下所有工作流
  let workflowId = workflows[0]?.id;
  if (!workflowId) {                                    // ② 没有就自动建一个"默认工作流"
    const created = await createWorkflow(ws.id, {
      name: "未命名工作流",
      definition: { nodes: [Start→Output], edges: [...] },  // 迷你默认流程
    });
    workflowId = created.id;
  }
  router.push(`/workflow/${workflowId}`);              // ③ 跳到编辑器
};
```

### 4.2 中间：VueFlow 画布

```vue
<VueFlow :nodes="nodes" :edges="edges"
         @node-click="onNodeClick" @pane-click="onPaneClick" fit-view-on-init>
  <template #node-custom="nodeProps">
    <CustomNode v-bind="nodeProps" />      <!-- 自定义节点渲染 -->
  </template>
  <Background pattern-color="#aaa" :gap="16" />
  <Controls />
</VueFlow>
```

VueFlow（`@vue-flow/core`）帮我们做了所有重活：节点拖动、连线、缩放、点击事件。我们只需：
- 提供 `nodes` / `edges` 两个数组（reactive 的数据）；
- 提供回调（点节点、点空白）；

### 4.3 自定义节点组件：components/workflow/CustomNode.vue

```vue
<script setup lang="ts">
import { Handle, Position } from "@vue-flow/core";
defineProps<{
  id: string;
  data: { label: string; nodeType: string };
  selected?: boolean;
}>();

// 根据类型映射图标和颜色
const icons = { start: "🚀", llm: "🤖", output: "📤" };
const colors = { start: "#2ba471", llm: "#0052d9", output: "#e37318" };
</script>

<template>
  <!-- 上方输入端口：非 start 节点显示 -->
  <Handle v-if="data.nodeType !== 'start'" type="target" :position="Position.Top" />
  <div class="node-box" :class="{ selected }" :style="{ borderLeftColor: colors[data.nodeType] }">
    <span class="icon">{{ icons[data.nodeType] ?? "🧩" }}</span>
    <span>{{ data.label }}</span>
  </div>
  <!-- 下方输出端口：output 节点不显示 -->
  <Handle v-if="data.nodeType !== 'output'" type="source" :position="Position.Bottom" />
</template>
```

- `Handle` 就是节点上的小圆点（连线的"插头"）；`target`=进线，`source`=出线。
- start 只出线、output 只进线，逻辑被 `v-if` 表达得很直观。
- `selected` 状态由 VueFlow 传入，选中时蓝色边框发光。

### 4.4 右侧属性面板

选中节点后，`selectedNode` 非空，面板显示：

```vue
<div v-if="selectedNode">
  <p>ID: {{ selectedNode.id }}</p>
  <p>类型: {{ selectedNode.data.nodeType }}</p>
  <t-input v-model="selectedNode.data.label" label="Label" />
  <template v-if="selectedNode.data.nodeType === 'llm'">
    <t-select v-model="selectedNode.data.model" :options="[{ label: 'qwen2.5:7b', value: 'qwen2.5:7b' }]" />
    <t-slider v-model="selectedNode.data.temperature" :max="1.0" :min="0" :step="0.1" label="Temperature" />
    <t-textarea v-model="selectedNode.data.prompt" label="Prompt" />
  </template>
</div>
```

**有意思的点**：`v-model` 直接绑到 `selectedNode.data.xxx`（节点对象是 reactive 的），所以改面板里的输入框，**画布上的节点数据立刻跟着变**，无需额外同步代码。

### 4.5 composables/useWorkflow.ts 里的画布交互

回顾第 2 篇已读过的代码，关键几条：

```typescript
const { addNodes, onConnect, addEdges, project, getNodes, getEdges, setNodes, setEdges } = useVueFlow();

// 实例化时给出"默认流程"：Start → LLM → Output
initialNodes = [
  { id: "start-1", type: "custom", position: { x: 250, y: 50 },  data: { label: "Start",  nodeType: "start" } },
  { id: "llm-1",   type: "custom", position: { x: 250, y: 180 }, data: { label: "LLM", nodeType: "llm", model: "qwen2.5:7b", prompt: "请分析以下内容：\n{{input}}", temperature: 0.7 } },
  { id: "output-1",type: "custom", position: { x: 250, y: 320 }, data: { label: "Output",nodeType: "output" } },
];
initialEdges = [
  { id: "e-start-llm",  source: "start-1",  target: "llm-1" },
  { id: "e-llm-output", source: "llm-1",    target: "output-1" },
];

onConnect((connection) => addEdges(connection));   // 用户连线 → 加到画布
```

**onDrop**（从左侧面板拖到画布建节点）：

```typescript
const onDrop = (event: DragEvent) => {
  event.preventDefault();
  const type  = event.dataTransfer?.getData("application/vueflow");
  const label = event.dataTransfer?.getData("application/vueflow-label");
  if (!type) return;

  const position = project({ x: event.clientX - 280, y: event.clientY - 60 }); // 屏幕坐标→画布坐标
  const newNode = {
    id: `${type}-${Date.now()}`,       // 用时间戳保证唯一
    type: "custom",
    position,
    data: { label: label || type.toUpperCase(), nodeType: type,
            model: type === "llm" ? "qwen2.5:7b" : undefined, prompt: ..., temperature: 0.7 },
  };
  addNodes([newNode]);
};
```

**loadWorkflow**（打开编辑器的加载流程）：

```typescript
const loadWorkflow = async () => {
  if (!/^[0-9a-f-]{36}$/i.test(workflowId)) return;   // 不是 UUID 就跳过
  const workflow = await getWorkflow(workflowId);
  const definition = workflow.currentVersion?.definition;  // 取"当前版本"的定义
  if (definition) {
    initialNodes.value = definition.nodes;
    initialEdges.value = definition.edges;
    setNodes(definition.nodes);    // 把后端 JSON 里的 nodes/edges 填进画布
    setEdges(definition.edges);
  }
};
onMounted(loadWorkflow);
```

**saveWorkflow**（保存 = 调 `PUT /api/workflows/:id`）：

```typescript
const saveWorkflow = async () => {
  const definition = { nodes: getNodes.value, edges: getEdges.value };  // 从画布取当前内容
  await updateWorkflow(workflowId, { definition });   // 后端会新建一个版本
  MessagePlugin.success("工作流保存成功");
};
```

> 注意：前端保存只发 `definition`。后端 `update` 的 DTO 里 `name`/`description` 是可选的，所以前端可以只传 definition——这就是第 4 篇里 `...(dto.name !== undefined ? {} : {})` 展开语法的意义。

## 5. 运行工作流（帮你把前后端全部串起来）

### 5.1 处理函数 handleRunWorkflow（views/workflow/index.vue）

```
用户点"运行"
  → 打开类似聊天的对话框
  → 用户输入一句话
  → handleRunWorkflow()
     ① definition = 画布当前定义（nodes/edges）
     ② 把每个画布节点的 data.nodeType 搬到 type 字段：
        type: String(node.data?.nodeType ?? node.type)
        config: { ...node.data, model: ... }   // 画布上的属性原样带给引擎
     ③ 组装请求体 { workflow, input }  ← workflow 就是 nodes+edges
     ④ 把用户消息加到聊天数组（右侧蓝气泡）
     ⑤ runWorkflowStream(data, onEvent)   ← 开 SSE 流
```

### 5.2 流式事件的 UI 映射

```typescript
const onWorkflowEvent = (event) => {
  switch (event.type) {
    case "node:start":    // 节点开始：顶部显示"正在执行 xxx..."
      statusText = `正在执行 ${event.nodeType} 节点...`
      break;
    case "token":         // 每个 token：追加到 assistant 气泡 → 打字机效果
      assistantMessage.content += event.content
      break;
    case "node:complete": // 节点完成：更新状态
      statusText = `${event.nodeType} 完成`
      break;
    case "complete":      // 全部完成
      statusText = "执行完成"
      break;
    case "error":         // 出错
      showError(event.message)
      break;
  }
};
```

### 5.3 全链路图（终极版）

```
前端：登录 → Dashboard 选择工作空间
  → 没有工作流则自动建默认流
  → 进入 /workflow/:id
  → loadWorkflow() 从数据库读 currentVersion.definition 填进画布
  → 用户拖拽编排 / 改属性
  → 保存: PUT /api/workflows/:id → (后端) new WorkflowVersion → 画笔布数据存库
  → 运行: 输入文本
     → fetch POST /api/workflow/run/stream (SSE)
     → (后端) WorkflowEngine.runStream
         → registry.get("start") → StartExecutor.execute
         → registry.get("llm")   → LLMNodeExecutor.executeStream
             → AIService.chatStream → OllamaProvider → Ollama(:11434)
             → yield token 事件 → SSE write "data: {...}"
         → Yield node:start/token/node:complete/complete 事件
     → (前端) getReader 逐帧解析 → 打字机输出
```
