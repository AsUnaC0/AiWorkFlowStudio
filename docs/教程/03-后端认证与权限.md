## 1. 用大白话建立模型

想象一个**公园（我们的后端）**：

- **注册**：办年卡（创建用户），密码就是"进门密码"。
- **密码哈希**：公园不存你的明文密码，只存一个"密码的指纹"。验证时比对指纹，反向算不出密码。
- **登录**：你报上邮箱 + 密码，公园验证指纹成功 → 发你一张**带防伪签章的通行卡（JWT）**。
- **之后的游玩**：每次进游乐设施，你掏出通行卡，保安一验章就放行。**公园不用记住你**（这就是"无状态"）。
- **Token 过期**：通行卡上写了"7 天后作废"。

本项目的通行卡是 **JWT（JSON Web Token）**。长这样：

```
eyJhbGciOiJIUzI1NiJ9.eyJzdWIiOiIxMjM0NSJ9.7Lz9f...（三段，点号分隔）
```

三段分别是：头（算法）、载荷（用户信息，不加密）、签名（防伪章）。这么设计让通行卡**无需数据库查询就能验证真伪**，因为签名是用 `JWT_SECRET` 算的，别人伪造不了。

## 3. 密码为什么要"哈希"？bcrypt 是什么？

**绝不存明文密码。** 数据库一旦泄露，所有账号明文密码等于白送。所以用 `bcrypt.hash(password, 10)` 生成一长串不可逆的哈希：

```
用户输入: 123456
   ↓ bcrypt.hash(password, 10)   ← 第二个参数叫"计算成本"(salt rounds)=10，越大越难破解
存储的:  $2b$10$WPdBPpJ0sbdbNEb76rM3F.VPQZ69Wr...
```

- **不可逆**：数学上无法从哈希反推回明文。
- **自带盐值（salt）**：每个密码随机加"盐"，即使两个人密码相同，哈希也不同，防止彩虹表破解。
- **成本参数 10**：故意让计算慢一点（几十毫秒），让暴力破解的成本变高。

验证时 `bcrypt.compare(明文, 存储哈希)` → 返回 true/false。它内部会用哈希里记录的那个盐重新计算再比对。

> 为什么不用 MD5/SHA？因为快，暴力破解一秒能算几百万次；bcrypt 故意慢，是"用时间换安全"。

## 4. 注册流程（register）代码逐行

文件：`backend/src/auth/auth.service.ts`

```typescript
async register(dto: RegisterDto) {
  // ① 检查邮箱/用户名是否已被注册（重复就 409 冲突）
  const existingEmail = await this.prisma.user.findUnique({ where: { email: dto.email } });
  if (existingEmail) throw new ConflictException('邮箱已被注册');

  const existingUsername = await this.prisma.user.findUnique({ where: { username: dto.username } });
  if (existingUsername) throw new ConflictException('用户名已被使用');

  // ② 密码哈希（绝不存明文）
  const passwordHash = await bcrypt.hash(dto.password, 10);

  // ③ 创建用户
  const user = await this.prisma.user.create({
    data: { username: dto.username, email: dto.email, passwordHash },
  });

  // ④ 签发 JWT 通行卡
  const accessToken = await this.signToken(user);
  return { user: toPublicUser(user), accessToken };
}
```

`signToken` 的实现：

```typescript
private signToken(user: User) {
  const payload = { sub: user.id, email: user.email, username: user.username };
  return this.jwtService.signAsync(payload, { expiresIn: process.env.JWT_EXPIRES_IN ?? '7d' });
}
```

- `payload` 里放了 `sub`（Subject，用户 ID，JWT 规范字段）、邮箱、用户名。
- 用 `JWT_SECRET` + 过期时间签发出这张卡。
- 前端拿回 `accessToken` 存好，以后每次请求带着它。

## 5. 登录流程（login）

```typescript
async login(dto: LoginDto) {
  const user = await this.prisma.user.findUnique({ where: { email: dto.email } });
  if (!user) throw new UnauthorizedException('邮箱或密码错误');

  const passwordValid = await bcrypt.compare(dto.password, user.passwordHash);
  if (!passwordValid) throw new UnauthorizedException('邮箱或密码错误');

  const accessToken = await this.signToken(user);
  return { user: toPublicUser(user), accessToken };
}
```

注意两处刻意相同的报错文案：**"邮箱或密码错误"**。这是因为只报"邮箱不存在"会帮黑客探测哪个邮箱注册过。统一文案只透露一种结果。

`toPublicUser` 是关键的**脱敏**（`Omit<User, 'passwordHash'>`）：

```typescript
const { passwordHash, ...publicUser } = user;  // 丢掉密码哈希再返回
```

> 思考：为什么连"哈希"都不返回？哈希虽然不可逆，但可离线暴力破解——不给黑客任何可乘之机。

## 6. JWT 验证链路（每次请求都要走一遍）

这是本项目权限体系的"高速公路"。逐文件解释：

### 6.1 Guard（保安）：jwt-auth.guard.ts

```typescript
@Injectable()
export class JwtAuthGuard extends AuthGuard('jwt') {}
```

就一行，表示"使用注册名为 `jwt` 的 Passport 策略"。在某路由上写 `@UseGuards(JwtAuthGuard)` = 这个接口要验通行卡。

### 6.2 Strategy（验卡规则）：jwt.strategy.ts

```typescript
@Injectable()
export class JwtStrategy extends PassportStrategy(Strategy) {
  constructor() {
    super({
      jwtFromRequest: ExtractJwt.fromAuthHeaderAsBearerToken(),  // 从 Headers 的 Authorization: Bearer xxx 取卡
      ignoreExpiration: false,      // 过期卡直接拒
      secretOrKey: process.env.JWT_SECRET,   // 用同一个私章验签
    });
  }

  async validate(payload: JwtPayload): Promise<JwtUser> {
    // 验签通过后，把载荷转成"当前用户"挂到 request.user
    return { id: payload.sub, email: payload.email, username: payload.username };
  }
}
```

流程：请求头 `Authorization: Bearer xxx` → 提取卡 → 验签 + 查过期 → `validate()` 返回用户对象 → **这个对象被挂到 `request.user`**。

### 6.3 装饰器（自取用户）：current-user.decorator.ts

```typescript
export const CurrentUser = createParamDecorator(
  (data: string | undefined, ctx: ExecutionContext) => {
    const request = ctx.switchToHttp().getRequest();
    const user = request.user;
    return data ? user?.[data] : user;   // @CurrentUser('id') 取 .id；@CurrentUser 取整个对象
  },
);
```

那么 Controller 里的用法就很优雅了：

```typescript
@UseGuards(JwtAuthGuard)
async findOne(@CurrentUser('id') userId: string, @Param('id') id: string) {
  return this.workflowsService.findOne(userId, id);
}
```

`@CurrentUser('id')` 自动帮你把 `request.user.id` 取出来传进方法。这样后端永远用**通行卡里的身份**去查数据，不信任前端传的 userId，防伪造。

## 7. 一次请求完整走一遍（GET /api/auth/me）

```
浏览器发: GET /api/auth/me
Headers:  Authorization: Bearer eyJhbGci...

后端:
1. JwtAuthGuard 拦截 → Passport 调 jwt.strategy
2. 提取 token → 用 JWT_SECRET 验签 → 查过期 → 成功
3. validate(payload) 返回 { id, email, username } → 挂到 request.user
4. 进入 AuthController.me() → 注入的 @CurrentUser() 拿到用户
5. AuthService.getMe() 用这个 id 查数据库（此刻 token 就相当于"钥匙"）
6. 把用户信息（脱敏）返回
```

如果：
- **没带 token** → Passport 抛 401 Unauthorized（前端正是利用这点知道要跳登录页）；
- **token 过期** → 401；
- **token 被篡改** → 验签失败 → 401。

## 8. 权限（Authorization）：owner vs member

认证（你是谁）之后还有**授权**（你能干嘛）。本项目的规则：

| 操作 | 权限 |
|------|------|
| 查看工作空间 | 所有成员可看 |
| 修改 / 删除工作空间 | 仅 owner（创建者） |
| 查看/更新工作流 | 该空间所有成员 |
| 创建工作流 | 该空间成员 |

代码体现：`workspaces.service.ts` 里有 `assertOwner()`，`workflows.service.ts` 里有 `assertWorkspaceMember()`：

```typescript
private async assertWorkspaceMember(userId: string, workspaceId: string) {
  const workspace = await this.prisma.workspace.findFirst({
    where: {
      id: workspaceId,
      OR: [{ ownerId: userId }, { members: { some: { userId } } }],  // 是老板 OR 是成员
    },
    select: { id: true },
  });
  if (!workspace) throw new ForbiddenException('You do not have access to this workspace');
}
```

`OR` 里的 `{ ownerId: userId }` 或 `{ members: { some: { userId } } }` 是 Prisma 查询写法："只要你是老板，或者在成员表里有一条记录，就通过"。查不到直接 403 Forbidden。

**经验法则**：授权判断尽量在 Service（业务层）做，而不是 Controller，避免每个接口重复贴一遍。

## 9. 本篇小结

| 问题 | 答案 |
|------|------|
| 为什么密码要 bcrypt？ | 不可逆 + 自带盐 + 故意慢，防明文泄露和暴力破解 |
| JWT 是什么？ | 三段式带签名的"通行卡"，后端可无状态验真伪 |
| 客户端怎么带 token？ | 请求头 `Authorization: Bearer <token>` |
| 401 vs 403？ | 401=没登录/卡失效（你是谁）；403=登录了但没权限（你能干嘛） |
| 用户信息从哪来？ | 永远是通行卡里的 id（`@CurrentUser`），不信前端传参 |
| 为什么登录报错文案统一？ | 防止泄露"哪个邮箱注册过" |

```
登录成功 → 后端返回 { user, accessToken }
  ↓
前端 Pinia store 存 token → 写进 localStorage（刷新不丢）
  ↓
每次请求 → axios 拦截器自动给 Headers 加上 Bearer token
  ↓
后端验票 → 通过就干活，401 → 前端拦截器自动清空登录态 → 跳回登录页
```
