# AI WorkFlow Studio 学习指南
## 第 1 篇：从零搭建运行环境（把项目跑起来）

> 目标：一步步在你电脑上把「数据库 + 后端 + AI模型 + 前端」全部启动，看懂每一步在干什么。
> 全程**慢动作**讲解，每个命令都会解释"为什么"。

---

## 1. 需要提前装好的软件

| 软件 | 版本建议 | 干什么用 | 怎么检查已装 |
|------|---------|---------|-------------|
| Node.js | 18+ | 跑前后端代码 | `node -v` |
| pnpm | 9+ | 装依赖（包管理器） | `pnpm -v` |
| Docker Desktop | 最新 | 跑 PostgreSQL / Redis（免装数据库） | `docker -v` |
| Ollama | 最新 | 本地跑 AI 大模型 | `ollama -v` |

> 类比：Node.js 是"运行程序的引擎"；pnpm 是"装零件的小推车"；Docker 是"一键开餐厅的容器车"——数据库这种服务用 Docker 临时开一个，你不用手动装数据库软件。

---

## 2. 第一步：启动数据库和 Redis（Docker）

项目里已经写好了配置文件 `docker-compose.yml`，它声明了两台"虚拟电脑"：

```yaml
services:
  postgres:                 # 服务名：postgres（我们的数据库）
    image: pgvector/pgvector:pg17
    environment:
      POSTGRES_USER: workflow              # 数据库用户名
      POSTGRES_PASSWORD: workflow          # 数据库密码
      POSTGRES_DB: ai_workflow             # 数据库名
    ports:
      - "5432:5432"                        # 对外端口
  redis:                    # 服务名：redis（目前占位，未来队列用）
    image: redis:7-alpine
    ports:
      - "6379:6379"
volumes:                    # 数据保存到本机磁盘，容器删了数据还在
  postgres_data:
  redis_data:
```

在**项目根目录**执行：

```bash
docker compose up -d
```

- `up` = 启动，`-d` = 后台运行（不占着你的终端）。
- 查看状态：

```bash
docker compose ps
```

看到 `ai-workflow-postgres` 和 `ai-workflow-redis` 都是 running 就成功了。

> 小知识：PostgreSQL 默认端口 5432，Redis 端口 6379。我们的后端要连数据库，就必须用这个端口连。

---

## 3. 第二步：配置后端环境变量

后端通过环境变量读配置。文件在 `backend/.env`（这个文件已经被 gitignore，不会上传仓库，里面是每个开发者的私有秘密）：

```env
DATABASE_URL="postgresql://workflow:workflow@localhost:5432/ai_workflow?schema=public"
JWT_SECRET=39ea001c9c13b868ee031824bac643b608d0664ae015b7a2
JWT_EXPIRES_IN=7d
REDIS_HOST=localhost
REDIS_PORT=6379
```

| 变量 | 含义 |
|------|------|
| `DATABASE_URL` | 连数据库的"地址 + 账号 + 密码"。格式：`postgresql://用户名:密码@主机:端口/数据库名` |
| `JWT_SECRET` | 给 JWT 通行证做防伪签章的"私章"（必须保密） |
| `JWT_EXPIRES_IN` | 通行证有效期 7 天 |
| `REDIS_*` | Redis 地址（当前代码还没用到，预留） |

> 自查：如果你本机 Docker 的数据库端口或密码和上面不一致，改这个文件即可。

## 4. 第三步：安装依赖

后端和前端是两个独立项目，分别进目录装依赖：

```bash
# 后端
cd backend
pnpm install

# 前端
cd ../fronted
pnpm install
```

`pnpm install` 会读取 `package.json`（依赖清单）和 `pnpm-lock.yaml`（锁定版本），把第三方库下载到 `node_modules`。

---

## 5. 第四步：告诉 Prisma 数据库"长什么样"（迁移）

Prisma 是连接代码和数据库的桥梁。`backend/prisma/schema.prisma` 定义了所有表结构（User、Workspace、Workflow...）。

我们要把这份"表结构定义"真正应用到数据库里，叫**迁移（Migration）**：

```bash
cd backend
pnpm prisma migrate deploy    # 应用已有的迁移文件（把表建出来）
pnpm prisma generate          # 生成类型安全的查询代码（@prisma/client）
```

- `migrate deploy`：执行 `prisma/migrations/` 里已经写好的 SQL，在数据库里建表。
- `generate`：生成代码，让 `prisma.user.create(...)` 这种写法有类型提示、不写错字段。

> 区别小贴士：开发中改动了 schema 可以用 `pnpm prisma migrate dev --name 描述` 生成新的迁移；部署到生产用 `migrate deploy`（只应用，不会自作主张改 schema）。

想可视化看看数据库长什么样：

```bash
pnpm prisma studio
```

这会打开一个网页版的"数据库 Excel"，可以直接看表和数据。

---

## 6. 第五步：准备 AI 大脑（Ollama）

工作流里的 LLM 节点要调用大模型。Ollama 是本地模型运行器。

```bash
# 1) 启动 Ollama（装好后通常开机会自启）
ollama serve

# 2) 下载模型（本项目默认用 qwen2.5:7b，约 7GB）
ollama pull qwen2.5:7b
```

验证模型已经就位：

```bash
ollama list
```

> 注意：Ollama 默认开在 `http://localhost:11434`，后端的 OllamaProvider 连的就是这个地址。
> 如果下载太慢，这是国内访问模型仓库的网络问题，可以配置 Ollama 的镜像源（`OLLAMA_HOST` + `OLLAMA_MODELS` 类似的环境变量）。

---

## 7. 第六步：启动后端

```bash
cd backend
pnpm start:dev
```

看到类似 `Nest application successfully started` 就是成功了。

- `start:dev` = `nest start --watch`：监听文件变化，改代码自动重启。
- 后端默认监听 **3000 端口**（`main.ts` 里 `port ?? 3000`）。

验证接口通没通：打开浏览器访问 `http://localhost:3000/api/auth/me`，前端会显示 401 Unauthorized——**这是正常的**，说明后端活着，只是你没登录没有通行证。

---

## 8. 第七步：启动前端

```bash
cd fronted
pnpm dev
```

看到 `Local: http://localhost:5173` 就是成功了。

**关键理解 - 前后端怎么连上：** 前端 `vite.config.ts` 配置了代理：

```typescript
server: {
  proxy: {
    "/api": {
      target: "http://localhost:3000",   // 后端地址
      changeOrigin: true,
    },
  },
},
```

意思是：前端页面发 `POST /api/auth/login`，**开发服务器代发**给 `http://localhost:3000/api/auth/login`，并顺手把 `Origin` 头改成后端的域名——这样就绕过了浏览器跨域限制（前端是 5173，后端是 3000，本来不同源会被浏览器拦截）。

> 生产环境没有这个代理，需要 Nginx 之类的反向代理做同样的事，或者直接让前端打全地址。

## 9. 完整启动清单（Checklist）

```bash
# 终端A：数据库
docker compose up -d

# 终端B（可后装）：Ollama
ollama serve

# 终端C：后端
cd backend && pnpm start:dev

# 终端D：前端
cd fronted && pnpm dev
```

浏览器打开 `http://localhost:5173` → 注册一个账号 → 进入 Dashboard → 点进某个 Workspace → 打开工作流编辑器 → 点「运行」输入一句话 → 看到 AI 打字机式回复。

> 👀 如果看到重启后 `PrismaClientInitializationError`：多半是数据库没起来（检查 `docker compose ps`）或者 `.env` 的账号密码写错。

## 10. 遇到问题怎么排查（小白急救箱）

| 症状 | 大概率原因 | 检查 |
|------|-----------|------|
| 后端起不来，报 `DATABASE_URL` | `.env` 不存在 | `backend/.env` 里有没有配置 |
| 后端连不上数据库 | Docker 没启动数据库 | `docker compose ps` 是否 running |
| prisma 报 `table users does not exist` | 还没做迁移 | 跑 `pnpm prisma migrate deploy` |
| 登录报 401 | token 过期或没带 | 看第 2 篇的 JWT 原理 |
| 前端页面打开是空白 | 后端没启动 / 代理错误 | 看终端 D 的报错 |
| 运行工作流报连不上 Ollama | Ollama 没开 / 模型没下载 | `ollama list`、`curl http://localhost:11434` |
| 前端 5173 起不来 | 端口被占用 | 换个端口 `pnpm dev -- --port 5174` |
