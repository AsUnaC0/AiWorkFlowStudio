# AI WorkFlow Studio 学习指南
## 第 2 篇：后端框架（NestJS）与数据库（Prisma）

> 这篇讲透后端的**骨架**：NestJS 是怎么组织代码的，Prisma 是怎么管数据库的。
> 先把这两个基础吃掉，第 3 篇的 JWT、第 4 篇的工作流引擎就好懂了。

## 1. NestJS 四大基本概念（先建立心智模型）

NestJS 的代码组织方式，可以类比成一家**餐厅**：

| NestJS 概念 | 餐厅类比 | 干什么 |
|------------|---------|--------|
| **Module（模块）** | 一个部门（后厨 / 前台 / 收银） | 把相关功能聚在一起 |
| **Controller（控制器）** | 前台服务员（只接电话、传话） | **只负责接收 HTTP 请求**（url + 方法），不碰业务 |
| **Service（服务）** | 后厨厨师（真正干活的人） | **负责真正的业务逻辑**（算账、验票、查数据） |
| **Dependency Injection（依赖注入）** | 自动配菜系统 | Controller 需要 Service 时，框架**自动创建并传进来**，不用你手动 new |

流程就是：

```
HTTP 请求进来
   ↓
Controller 接收（服务员）
   ↓
Service 处理业务（厨师）
   ↓
Prisma 读写数据库（仓库）
   ↓
Controller 把结果返回
```

每个 Controller/Service 只需要声明"我需要什么依赖"，构造函数一写，框架自动注入：

```typescript
// 用 constructor 声明依赖，NestJS 自动把实例传进来
@Injectable()
export class WorkspacesService {
  constructor(private readonly prisma: PrismaService) {}
}
```

- `@Injectable()`：标记"这个类可以被注入"。
- 构造函数参数里写了 `PrismaService`，NestJS 运行时**自动帮你 new 一个**并塞进来。
- 好处：你不用管理对象什么时候创建、要传什么参数；测试时还能换成"假的"。

## 2. 程序入口 main.ts（逐行看懂）

文件：`backend/src/main.ts`

```typescript
import 'dotenv/config';                          // ① 加载 .env 文件到 process.env
import { ValidationPipe } from '@nestjs/common'; // ② 一个"参数校验器"
import { NestFactory } from '@nestjs/core';      // ③ 创建应用的工厂
import { AppModule } from './app.module';

async function bootstrap() {
  const app = await NestFactory.create(AppModule);      // ④ 把整个应用创建出来
  app.setGlobalPrefix('api');                           // ⑤ 所有路由前加 /api
  app.useGlobalPipes(                                   // ⑥ 全局参数校验
    new ValidationPipe({
      whitelist: true,      // 自动丢弃 DTO 里没有声明的前端字段（安全）
      transform: true,      // 自动把字符串转成预期的类型（如数字/布尔）
    }),
  );
  await app.listen(process.env.PORT ?? 3000);          // ⑦ 起服务，默认 3000
}
bootstrap();
```

| 符号 | 作用 |
|------|------|
| ⑤ `setGlobalPrefix('api')` | 所有路由变成 `/api/auth/login`（前端请求就是这套路径） |
| ⑥ `ValidationPipe` | 配合 DTO 装饰器自动校验参数，不合格直接返回 400，不用在每个方法里手写判断 |

### 2.1 DTO 是什么？校验怎么生效的？

DTO = Data Transfer Object（数据传输对象），就是**规定"前端最多能传哪些字段、每个字段什么格式"**的类。比如 `backend/src/auth/dto/register.dto.ts`：

```typescript
export class RegisterDto {
  @IsString()
  @IsNotEmpty()
  username: string;

  @IsEmail()
  @IsNotEmpty()
  email: string;

  @IsString()
  @IsNotEmpty()
  @MinLength(6)
  password: string;
}
```

```typescript
// Controller 里声明参数类型为 RegisterDto
async register(@Body() dto: RegisterDto) { ... }
```

请求进来时，`ValidationPipe` 自动对 body 做校验：

- 没传 username → 400 报错；
- email 格式不对 → 400 报错；
- 密码少于 6 位 → 400 报错；
- 前端传了一个 DTO 里没有的字段（比如 `admin: true`）→ `whitelist: true` 直接**剔除**，防止恶意注入。

> 这就是"声明式校验"：用装饰器声明规则，框架执行，不需要你写一堆 `if (!email.includes('@'))`。

## 3. 根模块 app.module.ts

文件：`backend/src/app.module.ts`

```typescript
@Module({
  imports: [
    PrismaModule,        // 数据库（全局）
    AiModule,            // AI（全局）
    AuthModule,          // 认证
    WorkspacesModule,    // 工作空间
    WorkflowsModule,     // 工作流 + 执行引擎（核心）
  ],
})
export class AppModule {}
```

NestJS 的「模块」就像拼积木，根模块负责把积木拼起来。目前只注册了 5 个真正有内容的模块，其余目录（users/queue/reports...）是**预留的空壳**。

### 3.1 全局模块是什么？

看 `backend/src/prisma/prisma.module.ts`：

```typescript
@Global()                       // ← 关键：全局标记
@Module({
  providers: [PrismaService],
  exports: [PrismaService],     // 把服务"出口"给别的模块用
})
export class PrismaModule {}
```

**如果没有 `@Global()`**，每个要用 Prisma 的模块都必须 `imports: [PrismaModule]`，很啰嗦。
**有了 `@Global()`**，任何模块的构造函数直接注入 `PrismaService` 就能用，不用声明。`AiModule` 同理。

## 4. PrismaService：数据库连接（全局唯一）

文件：`backend/src/prisma/prisma.service.ts`

```typescript
@Injectable()
export class PrismaService
  extends PrismaClient                    // 继承数据库客户端，自带全部增删改查方法
  implements OnModuleInit, OnModuleDestroy
{
  constructor() {
    super({
      adapter: new PrismaPg({             // 用 PostgreSQL 专用的"驱动"
        connectionString: process.env.DATABASE_URL,
      }),
    });
  }

  async onModuleInit() { await this.$connect(); }     // 应用启动时，连上数据库
  async onModuleDestroy() { await this.$disconnect(); } // 关停时，断开连接
}
```

解读：

- 继承 `PrismaClient` → 一张 `User` 表对应 `prisma.user`，一张 `WorkflowVersion` 对应 `prisma.workflowVersion`，方法名就是表名，查询类型全自动提示。
- `implements OnModuleInit` → NestJS 会在应用启动时自动调用 `onModuleInit()`。

其实我们项目里调用常写成 `this.prisma.xxx`，就是这一个实例。

## 5. Prisma Schema：数据库的"设计图纸"

文件：`backend/prisma/schema.prisma`

### 5.1 五张表的关系地图（ER 图）

```
User (用户) ──拥有──> (1对多) Workspace (工作空间)
User ──通过中间表──> Workspace   （WorkspaceMember 多对多，一个空间多个成员）
Workspace ──1对多──> Workflow (工作流)
Workflow ──1对多──> WorkflowVersion (工作流版本)
Workflow ──指向当前激活版本──> WorkflowVersion
```

### 5.2 User（用户）

```prisma
model User {
  id           String   @id @default(uuid())     // 主键，自动生成 UUID
  username     String   @unique                  // 唯一，不能重名
  email        String   @unique                  // 唯一
  passwordHash String                            // 密码哈希值（绝不放明文）
  createdAt    DateTime @default(now())
  updatedAt    DateTime @updatedAt
  workspaces   Workspace[] @relation("WorkspaceOwner")
  memberships  WorkspaceMember[]
}
```

- `@id @default(uuid())`：主键，用 UUID（一种不可能撞车的随机字符串）当 ID，好处是后期多服务器也能保证唯一，不用全局自增。
- `@unique`：数据库层面保证唯一，重复插报错。
- `passwordHash`：只存哈希，不存明文（第 3 篇细讲）。
- `@relation("WorkspaceOwner")`：因为 User 和 Workspace 之间可能有多重关系（owner 和 member），命名区分。

### 5.3 Workspace（工作空间）

```prisma
model Workspace {
  id        String   @id @default(uuid())
  name      String
  ownerId   String                            // 外键：谁是老板
  owner     User     @relation("WorkspaceOwner", fields: [ownerId], references: [id])
  members   WorkspaceMember[]
  workflows Workflow[]
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt
}
```

**在这里学"外键"**：

- `ownerId` 存的是某个 `User.id`；
- `owner User @relation(..., fields: [ownerId], references: [id])` 告诉 Prisma：`ownerId` 指向 `User` 表的 `id` 字段。
- 有了这层关系，查询时能直接拿到对象：`prisma.workspace.findFirst({ include: { owner: true } })`，Prisma 会自动 JOIN 出 owner 的完整信息。

### 5.4 WorkspaceMember（成员关联表）

```prisma
model WorkspaceMember {
  id          String   @id @default(uuid())
  workspaceId String
  userId      String
  createdAt   DateTime @default(now())
  workspace   Workspace @relation(fields: [workspaceId], references: [id], onDelete: Cascade)
  user        User      @relation(fields: [userId], references: [id], onDelete: Cascade)

  @@unique([workspaceId, userId])   // 一个用户在一个空间最多一条记录
}
```

为什么需要这张表？因为**一个用户可以在多个空间当成员，一个空间有多个用户**，这就是「多对多关系」。关系型数据库无法直接表达多对多，于是拆成一张中间表，一行代表"某某在某某空间里"。

- `onDelete: Cascade`：工作空间删了，所有成员记录一起删（连坐删除），避免残留脏数据。
- `@@unique([workspaceId, userId])`：复合唯一，防止重复加成员。

### 5.5 Workflow（工作流）

```prisma
model Workflow {
  id               String   @id @default(uuid())
  workspaceId      String
  name             String
  description      String?
  status           String   @default("DRAFT")
  currentVersionId String?
  workspace        Workspace @relation(fields: [workspaceId], references: [id], onDelete: Cascade)
  versions         WorkflowVersion[] @relation("WorkflowVersions")
  currentVersion   WorkflowVersion? @relation("WorkflowCurrentVersion", fields: [currentVersionId], references: [id], onDelete: SetNull)
  createdAt        DateTime @default(now())
  updatedAt        DateTime @updatedAt
  @@index([workspaceId])
  @@unique([currentVersionId])
}
```

- `String?`：可空字段（描述可以不写）。
- `status @default("DRAFT")`：每个工作流有状态，默认草稿。
- `@@index([workspaceId])`：给经常查询的字段建索引，加速 `按工作空间查工作流`。

### 5.6 WorkflowVersion（工作流版本）

```prisma
model WorkflowVersion {
  id           String @id @default(uuid())
  workflowId   String
  version      Int
  definition   Json                              // 核心！整张工作流图（nodes+edges）存在这
  createdAt    DateTime @default(now())
  workflow     Workflow @relation("WorkflowVersions", fields: [workflowId], references: [id], onDelete: Cascade)
  currentWorkflow Workflow? @relation("WorkflowCurrentVersion")
  @@unique([workflowId, version])
  @@index([workflowId])
}
```

**这是本项目最精妙的设计之一——版本管理**：

- 一个工作流可以有很多版本（version=1、2、3...），每个版本都保存一份完整的 JSON（`definition`）。
- 每次编辑保存，**不覆盖旧定义，而是新建一条版本记录**，version 递增。
- `Workflow.currentVersionId` 指向「当前用哪个版本」。
- 好处：可以随时回溯历史任意一版，团队的改动能追溯，这在真实产品里非常重要。

> 类比：有点像「文档自动保存历史版本」，每存一次留一个快照，随时能找回。

## 6. 一次带事务的操作：以 WorkflowsService.create 为例

文件：`backend/src/workflows/workflows.service.ts`

```typescript
async create(userId: string, workspaceId: string, dto: CreateWorkflowDto) {
  await this.assertWorkspaceMember(userId, workspaceId);   // ① 权限校验

  return this.prisma.$transaction(async (transaction) => {  // ② 事务
    const workflow = await transaction.workflow.create({
      data: {
        workspaceId,
        name: dto.name,
        description: dto.description,
        versions: { create: { version: 1, definition: dto.definition } },  // 连建第1版
      },
      select: { id: true, versions: { select: { id: true } } },
    });

    return transaction.workflow.update({                   // ③ 回写 currentVersionId
      where: { id: workflow.id },
      data: { currentVersionId: workflow.versions[0].id },
      select: workflowSelection,
    });
  });
}
```

两个关键点：

**① `versions: { create: ... }`（嵌套创建）**
一次 create 连着把 `Workflow` 和它的第一个 `WorkflowVersion` 都建出来，Prisma 自动处理外键。这得益于 schema 里定义的关系。

**② `$transaction`（事务）**
「创建工作流」和「设置当前版本」是两个操作，必须**要么都成功、要么都失败**。事务保证原子性——如果第二步失败，第一步也会回滚，数据库不会被写成"半成品"。

## 7. 本篇小结

| 概念 | 一句话记住 |
|------|-----------|
| Module/Controller/Service | 部门 / 服务员 / 厨师 |
| 依赖注入 | 需要的依赖写构造函数里，框架自动给 |
| main.ts | 全局前缀 `/api` + 全局参数校验 + 起服务 |
| DTO + ValidationPipe | 用装饰器声明校验规则，自动校验 |
| Prisma Service | 继承 PrismaClient，全局可用，自带连/断 |
| Schema | 数据库设计图纸；关系/外键/索引/默认值都在里面 |
| 版本管理 | 每次保存新建 WorkflowVersion，currentVersionId 指向当前版 |
| 事务 | 多步操作要么全成要么全不成 |
