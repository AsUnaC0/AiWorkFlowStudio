## 第 5 篇：前端全局基础设施 —— 一次请求是怎么从页面发出的

> **本篇核心**：页面上的按钮怎么把请求发出去？token 是怎么自动带的？401 了为什么会跳回登录页？
>
> 前端目录名是 **`fronted`**（历史遗留拼写，不要改成 frontend）。vue 3 + Vite + Pinia + Vue Router + TDesign。

## 1. 启动那一刻的三件事

文件：`fronted/src/main.ts`（全文 13 行）

```typescript
import { createApp } from 'vue'
import { createPinia } from 'pinia'
import './styles/global.less'
import 'tdesign-vue-next/es/style/index.css'
import App from './App.vue'
import router from './router'

const app = createApp(App)

app.use(createPinia())   // ① 状态管理（登录态、选中 workspace……）
app.use(router)          // ② 路由
app.mount('#app')        // ③ 挂到 <div id="app">（index.html 里）
```

| 启动步骤 | 作用 |
|---------|------|
| `createApp(App)` | 创建 Vue 应用 |
| `use(createPinia())` | 每个页面都能用 `useXxxStore()` 拿全局状态 |
| `use(router)` | 生效路由配置 + 全局守卫 |
| `mount('#app')` | 渲染进 `index.html` 的 `<div id="app">` |

`App.vue` 更简单，就一行：

```vue
<template>
  <router-view />
</template>
```

**所有页面都是通过 `<router-view>` 渲染出来的。** 路由表是「整棵界面树的蓝图」。

## 2. 路由表：9 个页面

文件：`fronted/src/router/index.ts`

### 2.1 完整的路由结构

```
/
├── (MainLayout 布局)              ← 带 Sidebar+Header 的框架
│   ├── /chat                      Chat 页面（默认，redirct）
│   ├── /knowledge                 知识库列表
│   ├── /knowledge/:kbId           知识库详情（文件管理）
│   ├── /workspace                 工作空间（有 ?workspaceId= 时显示该空间的工作流列表）
│   ├── /friends                   ★ 好友（搜人/请求/列表）
│   ├── /skills                    ★ Skill 管理
│   └── /mcp                       ★ MCP Server 管理
├── /login                         登录/注册页（public，不套布局）
└── /workspace/:id                 工作流编辑器（standalone，不套布局）
```

### 2.2 代码实现

```typescript
const router = createRouter({
  history: createWebHistory(),

  routes: [
    {
      path: "/",
      component: () => import("@/layout/MainLayout.vue"),   // ③ 布局壳
      redirect: "/chat",                                     // ① 进 / 就到 /chat
      children: [
        { path: "chat",            component: () => import("@/views/chat/index.vue"),        meta: { title: "chat" } },
        { path: "knowledge",       component: () => import("@/views/knowledge/index.vue"),    meta: { title: "知识库" } },
        { path: "knowledge/:kbId", component: () => import("@/views/knowledge/detail.vue"),   meta: { title: "知识库详情" } },
        { path: "workspace",       component: () => import("@/views/workspace/index.vue"),    meta: { title: "工作空间" } },
        { path: "friends",         component: () => import("@/views/friends/index.vue"),      meta: { title: "好友" } },
        { path: "skills",          component: () => import("@/views/skills/index.vue"),       meta: { title: "Skills" } },
        { path: "mcp",             component: () => import("@/views/mcp/index.vue"),          meta: { title: "MCP" } },
      ],
    },
    { path: "/login",      component: () => import("@/views/login/index.vue"),   meta: { title: "登录", public: true } },
    { path: "/workspace/:id", component: () => import("@/views/workspace/workflow.vue"), meta: { title: "工作流编辑", standalone: true } },
  ],
});
```

**三个值得注意的设计：**

| 设计 | 原因 |
|------|------|
| **懒加载** `() => import(...)` | 页面代码按需加载，`/chat` 不会连带下载 workflow 编辑器 |
| `/`、`/knowledge`、`/workspace` 都是 `MainLayout` 的**子路由** | 共享侧边栏；只有内容区 `<router-view>` 切换 |
| `/login`、`/workspace/:id` 独立于布局 | 编辑器要全屏；登录页不该有侧边栏 |

**子路由的嵌套渲染**：`MainLayout.vue` 里自己还有一个 `<router-view>`：

```vue
<main class="main-content">
  <router-view v-slot="{ Component }">
    <transition name="page" mode="out-in">
      <component :is="Component" />
    </transition>
  </router-view>
</main>
```

所以 `/knowledge/123` 渲染三层：App `<router-view>` → MainLayout `<router-view>` → detail 页面。

> **`<transition name="page">`**：页面切换时的淡入 + 上移动画，定义在 MainLayout 的 `<style>` 里（`.page-enter-*` 那几个）。

### 2.3 全局路由守卫：没登录去哪都会被弹回登录页

```typescript
router.beforeEach((to) => {
  const userStore = useUserStore();
  const isAuthenticated = !!userStore.token;          // 有 token 就算登录
  const isPublic = to.meta.public === true;           // 只有 /login 标记了 public

  if (isPublic) {
    // 已登录的人再访问登录页 → 踢回 /chat
    if (isAuthenticated) return { path: "/chat" };
    return true;
  }

  if (!isAuthenticated) {
    // 没登录访问任何页面 → 去登录，并记下来时路径（redirect=xx）
    return { path: "/login", query: { redirect: to.fullPath } };
  }

  return true;   // 放行
});
```

**流程图：**

```
用户输入 URL
  ↓
beforeEach 守卫
  ├─ /login 且已登录      → 去 /chat
  ├─ /login 且未登录      → 放行（登录页）
  ├─ 其他页 且已登录      → 放行
  ├─ 其他页 且未登录      → /login?redirect=当时路径
  └─ 登录成功后要跳哪      → 优先 query.redirect，否则 /chat
```

> 登录页代码：
> ```typescript
> const redirect = (route.query.redirect as string) || "/chat";
> await router.push(redirect);
> ```

**⚠️ 守卫只查「有没有 token」，不查「token 是否有效」。**
token 过期了的请求是进到 `utils/request.ts` 的响应拦截器里被处理的（见第 4 节）——到那时才真正"踢下线"。

## 3. 状态管理 Pinia：`stores/user.ts`

```typescript
export const useUserStore = defineStore("user", () => {
  const token = ref<string>(localStorage.getItem("token") || "");   // 启动时从本地恢复
  const userInfo = ref<User | null>(null);

  const setToken = (newToken: string) => {
    token.value = newToken;                         // 内存（响应式）
    localStorage.setItem("token", newToken);        // 本地持久化
  };

  const setUserInfo = (user: User) => { userInfo.value = user; };

  const logout = () => {
    token.value = "";
    userInfo.value = null;
    localStorage.removeItem("token");
  };

  return { token, userInfo, setToken, setUserInfo, logout };
});
```

| 状态 | 持久化? | 存哪 | 谁写 |
|------|--------|------|------|
| `token` | ✅ | `localStorage` key=`token` | 登录成功后 `setToken` |
| `userInfo` | ❌ | 仅内存 | 登录成功后 `setUserInfo` |

> **⚠️ `userInfo` 不持久化 → 刷新页面后 userInfo 回到 null**。
> 侧边栏头像区域会退回「用户」。`api/auth.ts` 本来提供了 `getCurrentUser()`，
> 但**没有任何地方调用它**——这块是留给你修的功能。

## 4. axios 实例：`utils/request.ts`（★ 全前端最重要的文件）

```typescript
export const request = axios.create({
  baseURL: "/api",       // ★ 所有请求自动带 /api 前缀
  timeout: 100000,       // 10 秒
});

// ① 请求拦截器：自动带 token
request.interceptors.request.use(
  (config) => {
    const userStore = useUserStore();
    if (userStore.token) {
      config.headers.Authorization = `Bearer ${userStore.token}`;
    }
    return config;
  },
  (error) => Promise.reject(error),
);

// ② 响应拦截器：已经帮你把 response.data 剥出来了；401 统一踢下线
request.interceptors.response.use(
  (response) => response.data,          // ★ 返回 response.data（不是整个 response！）
  (error) => {
    if (error.response?.status === 401) {
      MessagePlugin.error("登录过期，请重新登录");
      const userStore = useUserStore();
      userStore.logout();               // 清 token
      router.replace({ path: "/login" });   // 去登录页
    }
    return Promise.reject(error);
  },
);
```

### 4.1 「为什么我的 api 函数直接拿到数据？——因为剥了一层」

因为响应拦截器里 `return response.data`，所以写 api 函数时很自然：

```typescript
export const getWorkspaces = (): Promise<WorkspaceApiItem[]> => {
  return request.get("/workspaces");
};
```

调用它的时候：

```typescript
onMounted(async () => {
  const workspaces = await getWorkspaces();     // ★ 拿到的已经是数组，不是 { data: [...] }
});
```

**如果去掉拦截器的 `return response.data`**，你每个调用都要写 `res.data.data`，业务代码会很烦。

### 4.2 401 处理的流程

```
某个请求返回 401
  ↓
响应拦截器捕获 error
  ↓
弹「登录过期」提示
  ↓
logout() 清内存+localStorage
  ↓
router.replace('/login')
  ↓
当前页面里 await 的这个请求把 error reject 出去
  → 调用处的 try/catch 会拿到 error（页面自己决定要不要再提示）
```

> **注意**：`logout()` 只清内存/localStorage，不调后端（后端没有登出接口）。
> 因为 JWT 无状态，真正让 token 失效的是「丢了它」。

### 4.3 ⚠️ 三种「带 token」的方式（第 3 篇提过，这里看代码）

| # | 位置 | 代码 | 原因 |
|---|------|------|------|
| 1 | `utils/request.ts`（绝大多数 api） | 拦截器自动加 | axios 请求自动处理 |
| 2 | `api/workflow.ts` 的 `runWorkflowStream` | `fetch` + 手写 header | axios 不支持流式读取 |
| 3 | `api/knowledge.ts` 的 `uploadDocument` | `fetch` + 手写 header | FormData 上传也绕过了 axios |

**stream 请求为什么不能走 axios？** 见第 6 篇 SSE 部分。

## 5. 三个「跨域」真相（前后端怎么连上的）

### 5.1 开发时：Vite 代理

`fronted/vite.config.ts`：

```typescript
server: {
  proxy: {
    "/api": {
      target: loadEnv(mode, process.cwd()).VITE_API_BASE_URL,   // 默认 http://localhost:3000
      changeOrigin: true,
    },
  },
},
```

```
浏览器请求  http://localhost:5173/api/auth/login
                  ↓ 匹配到 /api
Vite 代理转发到  http://localhost:3000/api/auth/login
```

**为什么需要代理？** 后端**没有开 CORS**（`main.ts` 里没 `app.enableCors()`）。
浏览器直连 `localhost:3000` 会被「跨域」拦下。代理让请求看起来**同源**了。

### 5.2 生产时：整个前端文件由后端/网关托管

前端 `build` 出来的文件放到后端托管，路径都是 `/api/...`，天然同源。
（本项目开发阶段用代理即可，生产部署方案可后续调研。）

### 5.3 一张图记住

```
开发环境：
浏览器(:5173) ──/api──► Vite 代理 ──► 后端(:3000/api)

生产环境：
浏览器 ─────────────────────────► 后端(托管的静态文件 + /api 接口)
```

## 6. `@` 别名 && 常用的库

`vite.config.ts` 里：

```typescript
resolve: {
  alias: {
    "@": fileURLToPath(new URL("./src", import.meta.url)),   // @/xxx = src/xxx
  },
},
```

所以 `@/stores/user`、`@/utils/request`、`@/views/...` 都是 `src/` 下的绝对路径。**别再用 `../../` 这种相对路径了。**

**前端技术栈速查：**

| 库 | 版本 | 干什么 | 出现的位置 |
|----|------|--------|-----------|
| Vue 3 | 3.5 | 框架 | 所有 .vue |
| Vite | 8 | 构建 + 开发服务器 | vite.config.ts |
| Vue Router | 5 | 路由 | router/index.ts |
| Pinia | 4 | 状态管理 | stores/user.ts |
| axios | 1 | HTTP | utils/request.ts |
| TDesign | 1.20 | 组件库 | `<t-button>` 等 |
| Vue Flow | 1.48 | 流程图/画布 | views/workspace/workflow.vue |
| monaco-editor | 0.56 | 代码编辑器（节点配置） | workflow 属性面板 |
| echarts | 6 | 图表 | 暂无页面用到（依赖先装了） |
| @iconify/vue | 5 | 图标 | AppSidebar 等 |

> **AutoImport / Components 插件**：`vite.config.ts` 里的 unplugin 帮你在代码里用 `<t-icon>` 等 TDesign 组件时**自动 import 类型/组件**，所以你不用手写 `import { Title } from "tdesign-vue-next"`。初次看代码会觉得"组件哪来的"，答案在这。

## 8. 前端常见的数据映射模式：API 形状 → 页面形状

以后端 workspaces 为例（第 2 篇也提到过）：

### 8.1 后端返回（Prisma `select` 的结果）

```json
{
  "id": "uuid",
  "name": "我的空间",
  "ownerId": "uuid",
  "createdAt": "2026-01-01T00:00:00.000Z",
  "updatedAt": "2026-01-01T00:00:00.000Z",
  "_count": { "members": 1, "workflows": 3 }
}
```

### 8.2 前端定义 API 类型

`fronted/src/types/workspace-api.ts`：

```typescript
export interface WorkspaceApiItem {
  id: string;
  name: string;
  ownerId: string;
  createdAt: string;
  updatedAt: string;
  _count: { members: number; workflows: number };
}
```

### 8.3 页面用的类型（更「平」）

`fronted/src/types/workspace.ts`：

```typescript
export interface WorkspaceItem {
  id: string;
  name: string;
  workflowCount: number;
  knowledgeCount: number;
  memberCount: number;
}
```

### 8.4 映射函数（`useWorkspace.ts`）

```typescript
const mapWorkspace = (w: WorkspaceApiItem): WorkspaceItem => ({
  id: w.id,
  name: w.name,
  workflowCount: w._count?.workflows ?? 0,
  knowledgeCount: 0,                    // ⚠️ 后端还没这个字段，先硬编码 0
  memberCount: w._count?.members ?? 0,
});
```

**这种「API 类型 + 页面类型 + map 函数」的模式**在全项目到处用：
- 工作流：`Workflow`（后端）→ `WorkflowItem`（前端）也有类似转换
- 知识库：同样有 `mapKnowledgeBase` 这类函数

**好处**：后端改了字段名，你只需要改 `map` 函数，页面不用动。

## 9. 前端「日期时间」的处理约定

访问到的 `createdAt` 都是 ISO 字符串（如 `2026-09-30T08:15:00.000Z`）。
前端显示通常直接截断/格式化。工作流编辑器里就有这种写法：

```typescript
new Date(item.updatedAt).toISOString().slice(0, 10)   // → "2026-09-30"
```

`toISOString()` 会转成 UTC 时间，`slice(0,10)` 取日期部分。
