## 1. 前端入口：main.ts

文件：`fronted/src/main.ts`

```typescript
import { createApp } from 'vue'
import { createPinia } from 'pinia'
import './style.css'
import 'tdesign-vue-next/es/style/index.css'   // 组件库的全局样式
import App from './App.vue'
import router from './router'

const app = createApp(App)
app.use(createPinia())   // ① 注册状态管理
app.use(router)          // ② 注册路由
app.mount('#app')        // ③ 挂载到 index.html 的 <div id="app">
```

对应 `index.html`：

```html
<div id="app"></div>
<script type="module" src="/src/main.ts"></script>
```

App.vue 只有一行：

```vue
<template><router-view /></template>
```

`<router-view />` 是个"插口"，路由匹配到哪个页面，它就把哪个页面渲染在这里。所以整个应用本质上就是"地址栏 URL → 一个页面组件"。

## 2. Vite 配置文件（重点：代理）

文件：`fronted/vite.config.ts`

```typescript
export default defineConfig(({ mode }) => ({
  plugins: [
    vue(),
    AutoImport({ resolvers: [TDesignResolver({ library: 'vue-next' })] }),
    Components({ resolvers: [TDesignResolver({ library: 'vue-next' })] }),
  ],
  resolve: {
    alias: {
      "@": fileURLToPath(new URL("./src", import.meta.url)),  // import xxx from '@/api/auth' → src/api/auth
    },
  },
  server: {
    proxy: {
      "/api": {
        target: loadEnv(mode, process.cwd()).VITE_API_BASE_URL,  // .env.development 里的值
        changeOrigin: true,
      },
    },
  },
}));
```

| 配置 | 作用 |
|------|------|
| `AutoImport`/`Components` | 自动按需引入 TDesign 组件，**不用手写 import**，标签一写就生效（生成 `components.d.ts`） |
| `@` 别名 | 写 `@/api/xxx` 代替长长的相对路径 `../../src/api/xxx` |
| `proxy` | 前端 5173 端口发请求 `/api/...` → 开发服务器转发到 `http://localhost:3000`，见第 1 篇 |

### 环境变量在哪定义？

`fronted/.env.development`：

```
VITE_API_BASE_URL=http://localhost:3000
```

`VITE_` 前缀的变量会注入到 `import.meta.env.VITE_API_BASE_URL`，编译期确定。代码里想要类型提示，在 `src/vite-env.d.ts` 里声明：

```typescript
interface ImportMetaEnv {
  readonly VITE_API_BASE_URL: string
}
```

> `public/config.js` 目前是空的。它的"设计意图"是运行时配置（改配置不用重新打包），但当前项目实际用的是环境变量。

## 3. Axios 封装：utils/request.ts（全项目请求的中枢）

文件：`fronted/src/utils/request.ts`

```typescript
import axios from "axios";
import { useUserStore } from "@/stores/user";

// 创建 axios 实例，baseURL 统一加 /api
export const request = axios.create({
  baseURL: "/api",
  timeout: 100000,          // 100 秒：工作流可能跑很久，超时放宽
});

// 请求拦截器：每个请求自动带上 token
request.interceptors.request.use(
  (config) => {
    const userStore = useUserStore();
    if (userStore.token) {
      config.headers.Authorization = `Bearer ${userStore.token}`;
    }
    return config;
  },
  (error) => Promise.reject(error),
);

// 响应拦截器：统一解包 + 401 自动登出
request.interceptors.response.use(
  (response) => response.data,        // 直接返回 data，调用方少写一层 .data
  (error) => {
    if (error.response?.status === 401) {
      const userStore = useUserStore();
      userStore.logout();             // 认证失效，清登录态
    }
    return Promise.reject(error);
  },
);
```

**拦截器 = 给所有请求/响应"统一加料"**：

- 请求时：自动塞 `Authorization: Bearer xxx`。你写 API 函数时不用手动带 token，后台每个请求都替你做。
- 响应时：`response.data` 直接解包 → `login()` 直接拿到 `{ user, accessToken }`，而不是被 axios 包一层的 `{ data: { user,... } }`。
- 401：token 过期/无效 → 自动 `logout()`，前端就能跳回登录页。
- `timeout: 100000`：为什么 100 秒？工作流运行（尤其 LLM）可能几秒到几十秒，默认超时（几秒）会误杀，所以放宽。

## 4. Pinia 状态管理：stores/user.ts

文件：`fronted/src/stores/user.ts`

```typescript
export const useUserStore = defineStore("user", () => {
  const token = ref<string>(localStorage.getItem("token") || "");  // 初值从 localStorage 恢复
  const userInfo = ref<User | null>(null);

  const setToken = (newToken: string) => {
    token.value = newToken;
    localStorage.setItem("token", newToken);   // 同步持久化，刷新页面不丢
  };

  const setUserInfo = (user: User) => { userInfo.value = user; };

  const logout = () => {
    token.value = "";
    userInfo.value = null;
    localStorage.removeItem("token");
  };

  return { token, userInfo, setToken, setUserInfo, logout };
});
```

**为什么既要内存又要 localStorage？**
- `ref` 里的 token：组件可以**响应式**读取（登录后界面立刻变化）。
- `localStorage`：页面刷新后 JS 内存清空，但浏览器本地还存着 token，刷新后可恢复登录。

这就是"双写"技巧。注意 `userInfo` 只放内存（每次刷新后重新请求 `me` 接口拿最新信息，反而更保险）。

## 5. 路由：router/index.ts

```typescript
const routes = [
  { path: "/", redirect: "/login" },                         // 根路径 → 去登录
  { path: "/login",     component: () => import("@/views/login/index.vue") },
  { path: "/dashboard", component: () => import("@/views/dashboard/index.vue") },
  { path: "/workflow",  component: () => import("@/views/workflow/index.vue") },
  { path: "/workflow/:id", component: () => import("@/views/workflow/index.vue") },  // :id 动态参数
  { path: "/knowledge", component: () => import("@/views/knowledge/index.vue") },
  { path: "/report",    component: () => import("@/views/report/index.vue") },
];

createRouter({ history: createWebHistory(), routes });
```

- 用 `() => import(...)` 是**懒加载**：访问到哪个页面才下载哪个页面的代码，首屏更快。
- `/workflow` 和 `/workflow/:id` 复用同一个页面组件：`workflowId` 有值时加载该工作流，没有时用初始示例。组件里通过 `route.params.id` 拿到 `:id`。

> ⚠️ 现状提醒：**当前没有路由守卫**（没有 `beforeEach`），也就是说用户不登录也能打开 `/dashboard`。它依赖组件内的请求被 401 拦下。**真实项目一定要加全局守卫**，这也是你可以动手加的第一个改进点。

## 6. API 层：api/ 目录（一个接口一个函数）

`api/auth.ts`：

```typescript
export const login = (data: LoginRequest) =>
  request.post<AuthResponse>("/auth/login", data);       // 实际请求 POST /api/auth/login
```

`api/workspace.ts`：

```typescript
export const getWorkspaces = () => request.get<WorkspaceApiItem[]>("/workspaces");
export const createWorkspace = (data: CreateWorkspaceRequest) =>
  request.post<WorkspaceApiItem>("/workspaces", data);
```

`api/workflow.ts`（重点看流式那个）：

```typescript
export const createWorkflow = (workspaceId, data) =>
  request.post(`/workspaces/${workspaceId}/workflows`, data);

export const runWorkflow = (data) => request.post("/workflow/run", data);

// 流式运行：不用 axios，用原生 fetch（axios 不适合 SSE 流式读取）
export async function runWorkflowStream(data, onEvent) {
  const userStore = useUserStore();
  const response = await fetch(`/api/workflow/run/stream`, {
    method: "POST",
    headers: {
      "Content-Type": "application/json",
      Authorization: `Bearer ${userStore.token}`,     // 手动带 token（不走 axios 拦截器）
    },
    body: JSON.stringify(data),
  });

  const reader = response.body.getReader();           // 读"字节管道"
  const decoder = new TextDecoder();
  let buffer = "";

  while (true) {
    const { done, value } = await reader.read();      // 一段段读
    if (done) break;
    buffer += decoder.decode(value, { stream: true });
    let sep;
    while ((sep = buffer.indexOf("\n\n")) !== -1) {   // SSE 帧以空行分隔
      const raw = buffer.slice(0, sep);
      buffer = buffer.slice(sep + 2);
      const line = raw.split("\n").find((l) => l.startsWith("data: "));
      if (line) onEvent(JSON.parse(line.slice(6)));   // 去掉 "data: " 前缀，转成对象交给回调
    }
  }
}
```

**这段代码值得逐行读懂**（SSE 消费端）：

1. `fetch` 拿到响应流 `response.body`；
2. `getReader()` + `ReadableStream`：可以**边读边处理**，这是打字机效果的关键；
3. 字节流 → `TextDecoder` 解码成字符串；
4. SSE 帧以 `\n\n`（空行）分隔，把完整帧切出来；
5. 每帧第一行是 `data: {...}`，取 `:` 后面的 JSON → `onEvent(...)` 传给 UI 更新。

## 7. 类型定义：types/ 一个文件一个职责

```
types/
├── auth.ts            # User / RegisterRequest / LoginRequest / AuthResponse
├── workflow.ts        # Workflow / WorkflowVersion / WorkflowDefinition / NodeConfig
├── workspace.ts       # WorkspaceItem（UI 展示用的形态）
└── workspace-api.ts   # WorkspaceApiItem（后端原始返回）
```

一个有意思的设计：**为什么有 workspace.ts 和 workspace-api.ts 两份**？

- 后端返回的：`{ id, name, ownerId, createdAt, _count: { members, workflows } }`
- 页面展示要的：`{ id, name, workflowCount, knowledgeCount, reportCount, memberCount }`

两者字段不同，所以定义**API 数据模型**和**UI 展示模型**两个，中间用 `mapWorkspace()` 函数转换（在 useWorkspace 里）。好处：后端改接口格式只影响 api 层，页面代码不用动。

## 8. 数据流全景：一次登录到一次请求

```
登录页 submitForm()
  → api/auth.ts: login()
  → request.post(/api/auth/login)   [axios 实例]
  → 拦截器自动加 token?   （此时还没 token，跳过）
  → Vite 代理转发 → 后端 :3000/api/auth/login
  → 后端返回 { user, accessToken }
  → then: userStore.setToken + setUserInfo   （内存 + localStorage）
  → router.push("/dashboard")

之后的任何请求：
  → api/xxx.ts 调 request
  → 请求拦截器读到 userStore.token → 自动加 Authorization
  → 后端验票通过 → 返回数据
  → 若 401 → 响应拦截器 → userStore.logout() → 登录态清空
```
