## 1. 这个项目是什么？

用一句话概括：

> **AI WorkFlow Studio 是一个「AI 工作流可视化编排平台」，你可以在网页上拖拽节点，把大语言模型（LLM）、提示词、输入输出等能力连成一条流水线，然后一键运行。**

### 用生活类比理解

把「工作流」想象成**奶茶店的制作流水线**：

```
顾客点单(输入)
   ↓
加奶(处理1)  →  加茶(处理2)  →  加糖(处理3)
   ↓
出杯(输出)
```

在程序里，我们把「加奶」「加茶」「加糖」抽象成一个个**节点（Node）**，节点之间用**连线（Edge）**串联。这条「节点 + 连线」的结构就叫**工作流定义（Workflow Definition）**，它是一份 JSON 数据：

```json
{
  "nodes": [
    { "id": "start-1", "type": "start",  "data": { "label": "开始" } },
    { "id": "llm-1",   "type": "llm",    "config": { "prompt": "你是一个助手" } },
    { "id": "output-1","type": "output", "data": { "label": "输出" } }
  ],
  "edges": [
    { "source": "start-1",  "target": "llm-1" },
    { "source": "llm-1",    "target": "output-1" }
  ]
}
```

用户通过前端画布拖动出这样的结构，保存到数据库，运行时由后端**引擎（Engine）**根据这份 JSON 一步步执行节点，最终给出结果。

## 2. 整体架构：一个请求如何流转

项目分为三部分：

```
┌─────────────────────────┐        ┌──────────────────────────┐        ┌───────────────┐
│        前端 fronted      │  HTTP  │        后端 backend       │   SQL   │   PostgreSQL  │
│  Vue3 + Vite + VueFlow  │ ─────> │  NestJS + Prisma + JWT   │ ─────> │  用户/工作流   │
│  用户看到的页面          │        │  API + 业务逻辑 + 执行引擎 │        │  版本等数据    │
└─────────────────────────┘        └──────────────────────────┘        └───────────────┘
          │                                   │
          │  localhost:5173                   │  localhost:11434
          ▼                                   ▼
   ┌────────────────┐                ┌────────────────┐
   │ Vite 代理转发    │                │   Ollama(本地AI) │
   │ /api → :3000    │                │   qwen2.5:7b    │
   └────────────────┘                └────────────────┘
   而 Redis(6379) 下半年才用，目前是占位
```

### 一次「运行工作流」的完整旅程（先有个印象）

1. 用户在浏览器工作流页点「运行」，输入一句话。
2. 前端把工作流 JSON 发给后端：`POST /api/workflow/run/stream`。
3. 后端引擎读取 JSON → 找到 `start` 节点 → 依次执行每个节点。
4. 遇到 `llm` 节点时，后端去调用本地 Ollama 服务，让它生成文字。
5. Ollama 的回复通过 **SSE 流式协议** 一段段推回浏览器，前端逐字显示（打字机效果）。

## 3. 技术栈速查表（含"为什么选它"）

### 后端

| 技术 | 干什么的 | 为什么用它 |
|------|----------|-----------|
| **NestJS 11** | Web 后端框架 | 用「模块/控制器/服务」规范组织代码，自带依赖注入，适合中型项目；与 Angular 同构的工程化思维 |
| **Prisma 7** | 数据库操作工具（ORM） | 写 `schema.prisma` 定义表结构，自动生成类型安全的查询代码；改表结构用 `migrate` 生成 SQL |
| **PostgreSQL** | 关系型数据库 | 存储用户、工作空间、工作流；支持 JSONB 和 pgvector（未来做向量检索） |
| **Passport + JWT** | 登录认证 | 无状态认证：后端不存"登录状态"，只给客户端发一张带签名的通行证 |
| **bcrypt** | 密码加密（哈希） | 明文密码绝不能入库，bcrypt 自带盐值，抗暴力破解 |
| **class-validator** | 请求参数校验 | 用装饰器一行一个校验规则，省去手写 if 判断 |

### 前端

| 技术 | 干什么的 | 为什么用它 |
|------|----------|-----------|
| **Vue 3 + `<script setup>`** | 前端框架 | 组合式 API 让逻辑可以抽成函数复用（对应 `composables/`） |
| **Vite** | 开发服务器 + 打包 | 启动快、热更新快；开发时能配置代理解决跨域 |
| **Pinia** | 全局状态管理 | 存"当前登录用户/token"这类全局数据 |
| **Vue Router** | 路由（页面跳转） | 管理 URL 与页面的对应关系 |
| **Axios** | 发 HTTP 请求 | 拦截器可以统一注入 token、统一处理 401 错误 |
| **@vue-flow/core** | 可视化画布 | 拖拽节点、连线、缩放都由它完成，我们只需提供数据和回调 |
| **TDesign Vue Next** | UI 组件库 | 按钮、弹窗、表单等现成组件，风格统一 |
| **Monaco Editor** | 代码编辑器 | 未来 Prompt/Code 节点里写代码、写提示词用 |
| **ECharts** | 图表 | 未来做报表可视化 |

### 基础设施

| 技术 | 干什么的 |
|------|----------|
| **Docker / docker-compose** | 一键拉起 PostgreSQL 和 Redis，不用手动装数据库 |
| **Ollama** | 本地运行大模型（qwen2.5:7b），是后端 AI 节点的"大脑" |
| **pnpm** | 包管理器，比 npm 更快、省磁盘 |

## 4. 根目录结构一眼看

```
AI WorkFlow Studio/
├── backend/             # 后端项目（NestJS）
├── fronted/             # 前端项目（Vue3，注意目录名少了个 n，是历史遗留）
├── docs/                # 项目文档（本教程在这里）
└── docker-compose.yml   # PostgreSQL + Redis 一键启动文件
```

> 小知识：项目不是"一个程序"，而是**前端 + 后端两个独立程序**，通过 HTTP 通信。这也叫 **前后端分离** 架构。正因为分离，前端可以单独部署到静态服务器，后端单独部署到 Node 服务器。

### 后端目录

```
backend/src/
├── main.ts          # 程序入口（启动函数）
├── app.module.ts    # 根模块，把下面所有模块组装起来
├── prisma/          # 数据库连接服务（全局可注入）
├── auth/            # 登录注册（JWT）
├── workspaces/      # 工作空间
├── workflows/       # 工作流（含 engine/ 执行引擎，本项目最核心）
├── ai/              # AI 服务（封装 Ollama）
├── users/           # 空目录，预留
├── common/          # 空目录，预留
├── queue/  reports/  knowledge/  files/  documents/   # 都是预留空目录
```

### 前端目录

```
fronted/src/
├── main.ts             # 前端入口
├── App.vue             # 根组件（就一个 <router-view />）
├── router/             # 路由表
├── stores/             # Pinia 状态（user.ts 存登录态）
├── api/                # 所有请求后端的函数
├── utils/request.ts    # Axios 封装（拦截器核心）
├── composables/        # 可复用逻辑：useWorkflow / useWorkspace
├── types/              # TypeScript 类型定义
├── views/              # 页面（login/dashboard/workflow/knowledge/report）
├── components/         # 组件（workflow/CustomNode.vue 自定义节点）
└── layout/             # 空目录，预留
```

## 5. 一些必须理解的术语（小白准备篇）

| 术语 | 大白话解释 |
|------|-----------|
| **API / 接口** | 后端对外开放的"窗口"，前端通过 `POST /api/auth/login` 这样的地址来调用功能 |
| **HTTP 方法** | GET=拿数据；POST=提交新数据；PUT=修改数据；DELETE=删除。可以类比快递（GET 查件 / POST 寄件 / PUT 改地址 / DELETE 退件） |
| **JSON** | 一种通用的数据格式，`{ "name": "张三" }`，前后端之间传数据都靠它 |
| **JWT (Token)** | 打印了一张带防伪签章的"通行证"，客户端每次访问带着它，后端验章通过就放行 |
| **SSE** | 服务器到客户端单向的实时消息通道（类似电子屏幕实时滚动字幕），用于流式输出 AI 文字 |
| **ORM** | 把数据库的"表"变成代码里的"对象"，比如 Prisma 的 `prisma.user.create(...)` 就是在数据库插入一条用户 |
| **依赖注入 (DI)** | NestJS 帮你创建对象并自动传给需要它的地方，你不用手动 `new`（类似咖啡店自动配送原料，不用你亲自去仓库取） |
