## 一、仍然成立的实现缺口（代码侧）

### G2 · 流式路径的 LLM 节点不支持 MCP 工具

| 项 | 内容 |
|---|---|
| 位置 | `backend/src/workflows/engine/executors/llm.executor.ts:115-153`（`executeStream`） |
| 现状 | `executeStream()` 调了 `createParams()`（返回 `tools` / `mcpBindings`），但**只解构了 `messages` / `options` / `provider`**，随后直接 `provider.streamChat(messages, options)`，工具定义被丢弃 |
| 对比 | 异步路径 `execute()` 在 `:76-80` 判断 `tools.length > 0` 就走 `executeWithTools()`（`chatWithTools` 循环 + MCP `callTool`） |
| 影响 | 画布「调试运行」（SSE 流式）的 LLM 节点**调不到 MCP 工具**；只有 BullMQ 异步路径才生效 |
| 文档 | 已在 `05-工作流引擎.md` 标注为已知缺口 |
| 修复方向 | 把流式路径也改成「有 tools 就先跑工具循环、末轮再流式输出」；或在前端明示「画布调试不支持 MCP 工具」 |

## 三、本轮（2026-10-29）新修正的文档描述

> 这些是**文档写错、代码没问题**的条目，已直接改进对应篇目，列在这里只为留痕。

| # | 位置 | 原来写的 | 实际 |
|---|---|---|---|
| 1 | 03 §八 | 「每次调用**前后**各调一次 `recordModelCall`」 | 调用**结束后记 1 条**（成功 SUCCESS / 异常 FAILED 后 rethrow） |

| 4 | 04 §五 | 「前后各调一次 `recordAgentCall`」 | 同上，一次调用只落一条 |
