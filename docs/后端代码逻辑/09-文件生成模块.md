# 09 - 文件生成模块（Files）

> 让 AI 真正**产出可下载的文件**（Word / Excel / PDF / Markdown / CSV），而不是在回复里编一个下载链接。
> 这是 `backend/src/files/**` 的完整逻辑讲解。
>
> 🔁 **方向相反的能力**：本模块是「**AI → 用户**」（AI 产出文件）；用户上传文件给 AI 是另一个模块 **10 - 聊天文件上传模块**（`ChatAttachment`，落 `chat-files/**`）。两者共用 `StorageService` + `FilePreviewService`，但落库模型、生命周期、是否向量化都不同。

---

## 一、模块定位

**文件路径**：`backend/src/files/`

```
files/
├── files.controller.ts          HTTP 接口（9 个）
├── files.service.ts             业务门面 + 权限校验
├── file-generator.service.ts    统一调度 5 个生成器
├── file-storage.service.ts      上传对象存储 + 元数据落库
├── file-preview.service.ts      文件 → 前端可渲染的预览数据
├── files.module.ts
├── dto/create-file.dto.ts
├── types/generated-file.types.ts 内容模型 + 格式元信息
└── generators/
    ├── word.generator.ts        docx（docx 库）
    ├── word.repair.ts           docx 兼容性修复（重点，见第六节）
    ├── opc.util.ts              OPC 包规范化重打包
    ├── excel.generator.ts       xlsx（exceljs）+ csv
    ├── pdf.generator.ts         pdf（pdfkit）
    ├── markdown.generator.ts    md
    └── markdown.util.ts         Markdown ↔ DocBlock 互转
```

**4 个 Service 各管一段，互不越界**：

| Service | 职责 | 不做的事 |
|---|---|---|
| `FileGeneratorService` | 结构化内容 → 二进制 Buffer | 不存储、不落库 |
| `FileStorageService` | 上传对象存储 + 写 `GeneratedFile` 记录 | 不生成内容 |
| `FilePreviewService` | 文件 → 预览数据（HTML / 表格 / rawUrl） | 不改文件 |
| `FilesService` | 业务门面 + **权限校验** | 不碰二进制细节 |

> 这是**公共能力**，不只给聊天页用：`Chat / Agent` 走 `generate_file` 工具，`Workflow`、`Skill` 是预留的后续接入方。`FilesModule` 导出 `FilesService` + `FileGeneratorService` + `FilePreviewService` 供别的模块注入。

> `POST /api/files/generate` 的 `sourceType` 默认是 **`export`**（`dto.sourceType ?? 'export'`，`files.controller.ts:69`）——
> 与 schema 的 `@default("chat")` 不同，走生成接口创建的文件都算「导出」来源。

## 二、数据模型

```prisma
model GeneratedFile {
  id          String   @id @default(uuid())
  userId      String            // 权限校验依据
  workspaceId String?
  sessionId   String?           // 来源会话
  messageId   String?           // 文件卡片渲染到这条消息下方

  fileName    String
  mimeType    String
  extension   String
  size        Int      @default(0)
  storageKey  String   @unique  // 对象存储 Key（本地模式为绝对路径）

  format      String            // docx / xlsx / pdf / md / csv
  sourceType  String   @default("chat")  // TS 类型是 5 值：chat / agent / workflow / skill / export
  status      String   @default("READY") // PROCESSING / READY / FAILED
  previewType String?           // pdf / image / document / spreadsheet / markdown / text / csv
  errorMessage String?

  title       String?
  summary     String?
}
```

> ⚠️ **表里不存二进制**。文件实体在对象存储（七牛云）里，数据库只有 `storageKey`。要拿内容必须 `StorageService.readBuffer(key)` 回源。

## 三、内容模型 —— LLM 只给「结构化内容」，不给二进制

**文件路径**：`backend/src/files/types/generated-file.types.ts`

设计原则：**模型不产出文件，只产出内容**。同一份内容可以导出 docx / pdf / md 三种格式。

### 文档类（`DocumentContent`）

```typescript
interface DocumentContent {
  title?: string;
  subtitle?: string;
  summary?: string;
  blocks: DocBlock[];
}

type DocBlock =
  | { type: 'heading';   text: string; level?: number }   // 1~6
  | { type: 'paragraph'; text: string }
  | { type: 'bullets';   items: string[] }
  | { type: 'numbers';   items: string[] }
  | { type: 'quote';     text: string }
  | { type: 'code';      text: string; language?: string }
  | { type: 'table';     headers: string[]; rows: string[][] }
  | { type: 'divider' };
```

### 表格类（`SpreadsheetContent`）

```typescript
interface SpreadsheetContent {
  sheets: Array<{
    name: string;
    columns?: Array<{ header: string; key?: string; width?: number }>;
    rows: Array<Record<string, unknown> | unknown[]>;  // 对象形式 or 数组形式都收
    note?: string;
  }>;
}
```

### 格式元信息 `FORMAT_META`

| format | extension | mimeType | previewType |
|---|---|---|---|
| `docx` | docx | `…wordprocessingml.document` | document |
| `xlsx` | xlsx | `…spreadsheetml.sheet` | spreadsheet |
| `pdf` | pdf | `application/pdf` | pdf |
| `md` | md | `text/markdown` | markdown |
| `csv` | csv | `text/csv` | csv |

## 四、生成链路（重点）

**入口**：`POST /api/files/generate` 或 Agent 的 `generate_file` 工具

```
FilesService.generate(input, ctx)
  │
  ├─① FileGeneratorService.generate()
  │     ├─ assertFormat()          不在 5 种格式里 → 400
  │     ├─ buildFileName()         清洗文件名 + 补扩展名
  │     ├─ normalizeDocument()     markdown → DocBlock[]（docx/pdf/md 路径，见下）
  │     ├─ normalizeSpreadsheet()  表格输入归一化（xlsx/csv 路径）
  │     ├─ assertHasContent()      内容为空 → 400（防生成空文件）
  │     └─ 按 format 分派到生成器 → Buffer
  │
  ├─② FileStorageService.save()
  │     ├─ StorageService.upload(buffer, fileName, 'generated')  → { key, size }
  │     └─ prisma.generatedFile.create({ … status: 'READY' })
  │
  └─③ toDto()  →  返回给前端（文件卡片）
```

> **只有「真正生成 + 上传 + 落库成功」才返回 READY**。不允许「模型说生成了就算生成」。

### `normalizeDocument()` —— Markdown → DocBlock[]

`markdown.util.ts` 里手写了一个 Markdown 子集解析器，支持：`#` 标题、`-` 无序列表、`1.` 有序列表、`>` 引用、\`\`\` 代码块、`| a | b |` 表格、`---` 分隔线，其余合并为段落。

两个容易踩的点：

1. **`stripInline()` 会把行内标记剥成纯文本**（`[百度](url)` → `百度`）。所以 `docx` / `pdf` 里**没有行内富文本**（已知限制）；`md` 格式为了保住链接，走的是**原始 markdown 直通**（`generateMarkdown(content, input.markdown)`），不走 blocks 往返。
2. 若 markdown 首个块就是 H1，会被提取成 `title` 并从 blocks 里移除，避免正文里重复一个标题。

### 5 个生成器各自的要点

| 生成器 | 库 | 要点 |
|---|---|---|
| `generateWord` | `docx@9` | 生成后**必须**过一次 `canonicalizeOpcPackage()`（见第六节）；编号列表必须在 Document 上注册 `numbering.config` |
| `generatePdf` | `pdfkit` | 不依赖 Chromium。中文靠系统字体：`PDF_CJK_FONT_PATH` 环境变量优先，否则依次找 `simhei.ttf` / `msyh.ttc` / `simsun.ttc` / `Deng.ttf` / `PingFang.ttc` / `Noto CJK`；**一个都找不到就回退 Helvetica，中文会缺字但不报错** |
| `generateMarkdown` | 无 | 给了 raw markdown 就原文输出（保行内语法），标题用 `applyTitleToRaw()` 智能前置 |
| `generateExcel` | `exceljs` | 支持多工作表；`resolveHeaders()` 同时兼容 `["a","b"]` 字符串数组和 `[{header:"a"}]` 对象数组 |
| `generateCsv` | 无 | 输出带 **UTF-8 BOM**（`\uFEFF`），否则 Excel 打开中文乱码 |

## 五、预览链路

**入口**：`GET /api/files/:id/preview`（别名 `/content`）

| previewType | 处理方式 |
|---|---|
| `markdown` | 读文本 → `marked` 渲染 → `sanitize-html` 消毒 → `html`；**同时返回原始 `text`**（`file-preview.service.ts:52`） |
| `document` | `mammoth` 把 docx 转 HTML → 消毒 → `html` |
| `spreadsheet` | `exceljs` 读工作簿 → `sheets[]` |
| `csv` | 手写 CSV 解析（支持引号内换行）→ 单 `sheets[]` |
| `text` | 原文 `text` |
| `pdf` / `image` | **不转内容**，返回 `rawUrl`，前端带 JWT 抓 blob 交给浏览器原生渲染 |

- 预览截断上限：`MAX_PREVIEW_ROWS = 500`、`MAX_PREVIEW_COLS = 60`，超了给 `truncated: true`。
- 所有 HTML 都过 `sanitize()`：白名单标签 + `a` 强制加 `target="_blank" rel="noopener noreferrer"`。**AI 生成的内容不能直接 v-html。**

## 六、Word（.docx）兼容性 —— 本模块最大的坑

> 现象：**前端预览正常，Microsoft Word 打开报「无法读取内容 / 需要修复」**。

### 为什么会这样

预览库（docx-preview / mammoth）用 jszip **按名**读取部件，对包结构不敏感；而 Word 的 OPC 读取器校验严格。历史上有两类缺陷会让 Word 直接拒收：

**缺陷 1：`[Content_Types].xml` 不在 zip 首位**

OPC 规范要求内容类型流是包内第一个部件，`docx@9` 的 Packer 默认把它**追加在末尾**。

```typescript
// generators/opc.util.ts
export async function canonicalizeOpcPackage(buffer: Buffer): Promise<Buffer> {
  const src = await JSZip.loadAsync(buffer);
  const ct = src.file('[Content_Types].xml');
  if (!ct) return buffer;

  const out = new JSZip();
  out.file('[Content_Types].xml', await ct.async('nodebuffer'));  // ← 强制第一个
  for (const name of Object.keys(src.files)) { /* 其余照抄，跳过目录项 */ }
  return out.generateAsync({ type: 'nodebuffer', compression: 'DEFLATE', platform: 'DOS' });
}
```

`generateWord()` 最后一行就是 `return canonicalizeOpcPackage(raw)`。

**缺陷 2：`w:numId` 是未解析的占位符**

`numbers` 列表段引用了**没有在 Document 里注册**的 numbering reference 时，`docx` 库**不会报错**，只是把占位符原样留在 XML 里：

```xml
<w:numId w:val="{default-numbering-0}"/>   <!-- ❌ w:numId 必须是正整数 -->
```

Word 看到直接判定文档损坏。所以 `word.generator.ts` 里显式注册了编号定义：

```typescript
numbering: {
  config: [{
    reference: 'default-numbering',
    levels: [{ level: 0, format: LevelFormat.DECIMAL, text: '%1.', alignment: AlignmentType.START }],
  }],
},
```

> ⚠️ **自查手段**：解包 docx，grep `word/document.xml` 里有没有 `{...}` 残留。有就是中招了。

### 历史文件怎么办 —— 读取时修复

上面的修复只对**新生成**的文件生效；已经存进对象存储的老文件仍然是坏的。所以在读取链路上加了一层修复：

```typescript
// FilesService.readRaw()
if (file.format === 'docx') {
  const { buffer: fixed, changed, notes } = await repairDocx(buffer);
  if (changed) buffer = fixed;   // 修复失败则降级返回原 buffer，不阻断下载
}
```

`word.repair.ts` 的 `repairDocx(buffer)`：

1. 找出所有非数字 `w:numId`，给它们分配一个**真实存在**的 numId（必要时新建 decimal `abstractNum`，并补齐 `[Content_Types].xml` 的 Override 和 `document.xml.rels` 的 Relationship）。
   → 是**重新指向**而不是删掉 `w:numPr`，**列表序号不会丢**。
2. 重打包，`[Content_Types].xml` 置顶。
3. **只读、幂等**（修过的文件再修一次 `changed = false`）、失败降级。

下载（`/download`）和预览（`/raw`）走的是同一个 `readRaw()`，所以两边同时受益——**用户不用重新生成文件**。

## 七、HTTP 接口

**文件路径**：`backend/src/files/files.controller.ts`（全部 `JwtAuthGuard` + 校验 `file.userId === 当前用户`）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/files/formats` | 支持的格式列表 |
| POST | `/api/files/generate` | 生成文件（落库后返回 READY） |
| GET | `/api/files` | 我的文件列表（可按 `sessionId` / `messageId` 过滤） |
| GET | `/api/files/:id` | 文件元数据 |
| GET | `/api/files/:id/preview` | 预览数据（HTML / 表格 / rawUrl） |
| GET | `/api/files/:id/content` | 同上（语义别名） |
| GET | `/api/files/:id/raw` | 原始文件流（`inline`，前端转 blob 预览） |
| GET | `/api/files/:id/download` | 原始文件流（`attachment` 下载） |
| DELETE | `/api/files/:id` | 删除记录 + 对象存储对象 |

> 七牛云是**私有空间**，不能直接把对象 Key 拼成 URL 给浏览器。所有读取都必须走后端代理，并带上 `Authorization`。文件名用 **RFC 5987** 编码：
> `Content-Disposition: attachment; filename*=UTF-8''${encodeURIComponent(fileName)}`，否则中文文件名乱码。

## 八、Agent 侧：`generate_file` 工具

**文件路径**：`backend/src/agent/tools/generate-file.tool.ts`

- 工具名常量 `GENERATE_FILE_TOOL_NAME = 'generate_file'`
- 由 `Agent.enableFileGeneration`（默认 `true`）控制是否注入，`ToolRegistry.buildDefinitions()` 里 `options.enableFileGeneration !== false` 才 push
- 执行成功后把文件 **push 进 `context.files`**，由 `AgentService` 推送 SSE `file` 事件并关联到聊天消息，前端就渲染出文件卡片
- **失败不抛错**，返回一段让模型自己修正参数的提示文本（"请检查 format 是否支持、内容是否为空"），避免 ReAct 循环直接崩掉

## 九、最容易踩的 6 个坑

1. **`docx` 生成后必须 canonicalize**，否则 `[Content_Types].xml` 在末尾，Word 打不开。
2. **numbering reference 必须注册**，否则 `w:numId` 变成 `{default-numbering-0}` 占位符，`docx` 库还不报错。
3. **改了生成器只对新文件生效**，老文件靠 `readRaw()` 里的 `repairDocx()` 兜底——别把修复逻辑只写在生成侧。
4. **`stripInline()` 会吃掉行内 Markdown**，所以 docx/pdf 没有富文本；要保链接就得走 md 的 raw 直通路径。
5. **七牛云私有空间不能拼 URL**，必须走 `/raw` / `/download` 代理并带 JWT。
6. **CSV 必须带 BOM**，否则 Excel 打开中文乱码；PDF 找不到中文字体时是**静默回退**（中文缺字但不报错），别以为生成成功就一定能看。
