## 一、main.ts — 应用启动入口

**文件路径**：`backend/src/main.ts`

NestJS 应用的启动只有一个函数 `bootstrap()`，做了 3 件事：

```typescript
async function bootstrap() {
  const app = await NestFactory.create(AppModule);    // ① 创建应用实例
  app.setGlobalPrefix('api');                         // ② 全局路由前缀
  app.useGlobalPipes(new ValidationPipe({             // ③ 全局管道 + 过滤器
    whitelist: true,    // 自动剔除 DTO 中未声明的字段（防注入）
    transform: true,    // 自动把 plain object 转成 DTO 类实例
  }));
  app.useGlobalFilters(new AllExceptionsFilter());
  await app.listen(process.env.PORT ?? 3000);
}
```

**全局中间件的作用**：

| 配置                              | 效果                                                                            |
| ------------------------------- | ----------------------------------------------------------------------------- |
| `setGlobalPrefix('api')`        | 所有 Controller 的路由前面都自动加 `/api`，比如 `@Get('auth/me')` → 实际 URL 是 `/api/auth/me` |
| `ValidationPipe({ whitelist })` | 前端传了 DTO 里没定义的字段会被**自动丢弃**，不会进入 Controller                                    |
| `ValidationPipe({ transform })` | 自动把 `@Body()` 拿到的 JSON 对象 **转成 DTO 类实例**，这样 DTO 里定义的 `@IsString()` 等装饰器才能生效   |
| `AllExceptionsFilter`           | 所有未捕获的异常都走这个统一过滤器，返回标准化 JSON 格式                                               |

## 二、app.module.ts — 模块依赖图

**文件路径**：`backend/src/app.module.ts`

这是根模块，所有业务模块都在这里 `imports`：

```
AppModule
├── BullModule           ← BullMQ 队列（Redis）
├── PrismaModule         ← 数据库访问层
├── AiModule             ← 大模型 Provider（全局，@Global）
├── AuthModule           ← 认证鉴权
├── ChatFilesModule      ← 聊天附件上传 + 解析 + 上下文注入，见 10
├── DashboardModule      ← 统计看板
├── FilesModule          ← 文件生成（Word/Excel/PDF…），见 09
├── FriendshipModule     ← 好友关系
├── KnowledgeModule      ← 知识库 + 文档处理
├── LlmConfigModule      ← 模型管理（自定义云端模型）
├── WorkspacesModule     ← 工作空间
├── WorkflowsModule      ← 工作流引擎
├── QueuesModule         ← 异步任务队列
├── AgentModule          ← Agent 智能体
├── AssistantModule      ← 平台助理（默认 Agent 的「操作系统」能力），见 11
├── PersonaModule        ← ★ 平台助理的人格配置，见 12
├── MemoryModule         ← ★ 长期记忆（沉淀 / 召回 / 3D 网络），见 12
├── SkillModule          ← Skill
├── McpModule            ← MCP Server
├── StorageModule        ← 统一存储服务（本地/七牛云）
├── TtsModule          ← ★ TTS 语音合成（桌宠后端兜底，/tts/synthesize），见 08 第九节
└── DesktopPetModule     ← ★ 桌宠客户端启动器（spawn 本机 Electron），见 12 §11
```

> `AssistantModule` 内部会导入 `PlatformToolsModule`（19 个平台工具的注册中心）和 `PersonaModule`（拼 System Prompt 时取人格）。
> 依赖方向是单向的：`AgentModule → AssistantModule → PlatformToolsModule`；
> `AgentModule → { PersonaModule, MemoryModule }`；`MemoryModule → KnowledgeModule`（只为拿 `EmbeddingService`）。
> **`PersonaModule`** **刻意只依赖** **`PrismaModule`** —— 如果它反过来 import `AssistantModule` 来复用「平台助理校验」，
> 就会和 `AssistantModule → PersonaModule` 组成环，Nest 启动直接失败（见 [12](./12-人格与记忆模块.md) §十）。
> `DesktopPetModule` 同样零依赖：它只做「把本机 Electron 拉起来」，桌宠的业务请求全走既有接口。

**一个重要细节**：`AiModule` 带了 `@Global()` 装饰器，意味着它的 `AIService` 在任何模块里都可以直接注入，不用再在 imports 里重复声明。

## 三、全局异常过滤器

**文件路径**：`backend/src/common/filters/all-exceptions.filter.ts`

所有 Controller 抛出的异常最终都被这个过滤器接住，返回统一格式：

```typescript
// 最终响应长这样：
{
  "statusCode": 401,
  "error": "Unauthorized",
  "message": "邮箱或密码不正确",
  "timestamp": "2026-10-10T12:00:00.000Z",
  "path": "/api/auth/login"
}
```

过滤器的真实取信息逻辑（`all-exceptions.filter.ts`）：

```typescript
if (exception instanceof HttpException) {
  const res = exception.getResponse();          // 可能是字符串，也可能是对象
  if (typeof res === 'object') {
    // ValidationPipe 的错误形如 { message: [...], error: "Bad Request" }
    error   = res.error ?? exception.message;
    message = Array.isArray(res.message) ? res.message.join('；') : (res.message ?? exception.message);
  } else {
    error   = exception.name.replace('Exception', '');
    message = res;
  }
} else {
  // 非 HttpException：先尝试翻成「可操作的中文提示」，翻不出来才用笼统 500
  statusCode = 500;
  error      = 'Internal Server Error';
  message    = describeInfraError(exception)    // P2021/P2022 → 提示跑 migrate；P1001/1002/1017 → 检查数据库…
    ?? '服务器内部错误，请稍后重试或联系管理员';
  logger.error(完整堆栈);   // 只在服务端日志里
}

// 二次保护：登录接口 401 的 message 统一改写，杜绝"邮箱不存在 vs 密码错误"的区分
// 其余接口（token 过期/缺失）保持「登录已过期，请重新登录」，避免误导前端
if (statusCode === 401) {
  message = request.path.includes('/auth/login')
    ? '邮箱或密码不正确'
    : '登录已过期，请重新登录';
}
```

**需要注意的三点**：

1. `message` 的默认兜底是**中文脱敏文案**，不是 `"Internal Server Error"`（后者是 `error` 字段的值）
2. **登录接口（`POST /api/auth/login`）的 401 会被强制改成「邮箱或密码不正确」**——这是过滤器做的，不只是 AuthService 里的处理；其他接口的 401（token 过期/缺失）返回「登录已过期，请重新登录」
3. ValidationPipe 的校验错误数组会用「；」拼接成一个字符串

**基础设施类异常会被翻译**：非 HttpException 走 500 分支时，先经过
`describeInfraError()`（`all-exceptions.filter.ts:95-138`）——Prisma 的 P2021/P2022（表/列不存在，
通常是「改了 schema 没跑迁移」）、P1001/P1002/P1017（连不上库）、P2002/P2003（唯一/外键约束）
都会被翻成一句可操作的中文提示（如「请在 backend 目录执行 `npx prisma migrate deploy` 后重试」），
`NODE_ENV !== 'production'` 时还会把原始错误信息一并返回，方便本地排障。翻不出来才用笼统的
「服务器内部错误」兜底，**任何情况下都不向前端泄露 SQL 和堆栈**。

前端取信息：`statusCode` 判断分支，`message` 直接展示即可。

## 四、PrismaService — 数据库访问层

**文件路径**：`backend/src/prisma/prisma.service.ts`

所有业务 Service 里看到的 `this.prisma.xxx` 就是它。它继承 `PrismaClient` 并实现
`OnModuleInit` / `OnModuleDestroy` 两个生命周期钩子：

```typescript
export class PrismaService extends PrismaClient implements OnModuleInit, OnModuleDestroy {
  constructor() {
    // Prisma 7 走 driver adapter：构造时用 PrismaPg 把 DATABASE_URL 包成连接
    super({
      adapter: new PrismaPg({ connectionString: process.env.DATABASE_URL }),
    });
  }

  async onModuleInit()    { await this.$connect(); }     // 模块初始化时连库
  async onModuleDestroy() { await this.$disconnect(); }  // 应用关闭时断开
}
```

> 注意 `$connect()` 是在 `onModuleInit()` 里调用的（NestJS 生命周期钩子），**不是构造函数里**。
> 构造函数只负责通过 `@prisma/adapter-pg` 的 `PrismaPg` 注入数据库连接——Prisma 7 的驱动适配器模式。

**数据库表一览**（从 Prisma schema 推断）：

| 表名                                                                 | 用途                                                                                           |
| ------------------------------------------------------------------ | -------------------------------------------------------------------------------------------- |
| `User`                                                             | 用户（邮箱、用户名、密码哈希、在线状态）                                                                         |
| `Workspace` + `WorkspaceMember`                                    | 工作空间 + 成员（owner + members，无 role 字段）                                                         |
| `WorkspaceKnowledgeBase`                                           | Workspace ↔ KnowledgeBase 多对多中间表                                                             |
| `KnowledgeBase`                                                    | 知识库（embedding 配置、documentCount / chunkCount）                                                 |
| `Document`                                                         | 知识库下的文档（文件元数据 + 存储路径 + 处理状态）                                                                 |
| `DocumentChunk`                                                    | 文档分块（content + chunkIndex；向量列见下方说明）                                                          |
| **`KnowledgeBaseEmbeddingVersion`** ★                              | 知识库的向量版本（模型 / 维度 / 物理表名 / 状态 / 是否生效 / 进度）                                                    |
| **`DocumentChunkEmbedding`** ★                                     | 某 chunk 在某版本下的向量化状态（PENDING / DONE / FAILED，**只记状态不存向量**）                                    |
| `Workflow` + `WorkflowVersion` + `WorkflowRun` + `WorkflowNodeRun` | 工作流 + 版本 + 运行记录 + 节点执行记录                                                                     |
| `ModelCallLog`                                                     | 大模型调用日志（token 用量 / 延迟 / 费用），Dashboard 的 `tokenUsage` 就来自它                                    |
| `Agent` + `ChatSession` + `ChatMessage`                            | Agent 智能体 + 聊天会话 + 消息历史                                                                      |
| **`AgentPersona`** ★                                               | 平台助理的人格配置（名字 / 标签 / 提示词 / 音色 / 主动程度），`agentId` 唯一，见 12                                       |
| **`Memory`** ★                                                     | 长期记忆条目（`summary` / `content` / `embedding Float[]` / `importance` / `category`），见 12         |
| **`MemoryLink`** ★                                                 | 记忆之间的关联边（3D 网络里的连线），`sourceId → targetId` + `weight`（余弦相似度，`@@unique([sourceId, targetId])`） |
| **`MemorySetting`** ★                                              | 记忆偏好，按 `userId` 一条：`autoCaptureEnabled` / `captureModelId` / `recallLimit`                   |
| **`DesktopPetSettings`** ★                                         | 桌面桌宠的窗口与行为配置（位置 / 尺寸 / 穿透 / 透明度），按 `userId` 一条                                               |
| **`RefreshToken`** ★                                               | 短时效刷新凭证（给 Electron 桌宠这类长驻客户端用，避免长期持有主 token）                                                 |
| `ChatAttachment`                                                   | 聊天附件（用户上传给 AI 的文件，见 10；与知识库 `Document` 解耦，不向量化）                                              |
| `GeneratedFile`                                                    | AI 生成的可下载文件（Word / Excel / PDF…），见 09                                                        |
| `PlatformOperationLog`                                             | 平台助理的操作审计账本（谁用什么工具动了哪个资源），见 11                                                               |
| `LlmProviderConfig` + `LlmModel`                                   | 自定义 LLM 配置 + 可用模型列表                                                                          |
| `McpServer`                                                        | MCP Server 配置                                                                                |
| `Skill`                                                            | Skill 定义                                                                                     |
| `Friendship`                                                       | 好友关系（单向存储，查询用 OR 双向匹配）                                                                       |

> 共 **31 张表**（上一轮 +2：`KnowledgeBaseEmbeddingVersion` / `DocumentChunkEmbedding`；
> ★ 本轮 +6：`AgentPersona` / `Memory` / `MemoryLink` / `MemorySetting` / `DesktopPetSettings` / `RefreshToken`，见 [12](./12-人格与记忆模块.md)）。
> 注意 `WorkspaceMember` **没有 role 列**，"OWNER / MEMBER" 是 `WorkspacesService` 在查询时用 `user.id === workspace.ownerId` 现算出来的（详见 [08](./08-MCP-Skill-Storage-其他模块.md)）。
>
> ★ **向量存在哪**：`DocumentChunk` 只存文本块（`content` + `chunkIndex`）；向量按「版本」存在各自独立的物理表
> `EmbeddingVector_<versionId>`（列是 `vector(该版本 dimensions)` + HNSW 索引）。
> 因为 pgvector 的 HNSW/IVFFlat **只能建在固定维度列上**，换 Embedding 模型 = 换维度 = 必须换表。
> 详见 [06](./06-知识库与RAG.md) §六。
>
> ⚠️ **遗留列**：`DocumentChunk` 上仍保留一个旧版 `embedding vector(768)?` 列（`Unsupported` 类型，由手写迁移维护，
> 对应 IVFFlat 索引 `dc_embedding_ivf`）。新写入的向量都进版本物理表，这个列**只是遗留、不再被新代码写入**，
> 别看到它就以为向量还挂在 chunk 上。
>
> ⚠️ 迁移是**手写 SQL**（`prisma/migrations/<timestamp>_xxx/migration.sql` → `npx prisma migrate deploy` → `npx prisma generate`），
> **不要用** **`prisma migrate dev`** —— 它会把 pgvector 的 IVFFlat 索引当「多余对象」生成 `DROP INDEX` 删掉（见 11 第十节）。

## 五、StorageService — 统一存储抽象

**文件路径**：`backend/src/storage/storage.service.ts`

项目支持两种存储后端，通过 `.env` 中的 `STORAGE_TYPE` 切换：

| 存储类型        | `.env` 配置            | 实际操作                                   |
| ----------- | -------------------- | -------------------------------------- |
| `local`（默认） | `STORAGE_TYPE=local` | 文件写到 `LOCAL_UPLOAD_DIR`（默认 `uploads/`） |
| `qiniu`     | `STORAGE_TYPE=qiniu` | 文件存到七牛云对象存储                            |

**实现方式（重要）**：只有**一个** `StorageService` 类，`storage.module.ts` 里就是 `providers: [StorageService]`。它在构造函数里读一次 `STORAGE_TYPE` 存到 `this.type`，之后每个方法内部按 `this.type` 分支——**不存在** `LocalStorageService` / `QiniuStorageService` 两个实现类，也没有按 env 条件注入的戏法。

**对外暴露的方法**（注意方法名和返回值）：

```typescript
class StorageService {
  readonly type: 'local' | 'qiniu';

  // 上传 —— 返回 { key, size }，不是字符串！
  //   local 的 key 是绝对路径： uploads/documents/<uuid>.ext
  //   qiniu 的 key 是对象 Key： documents/<yyyy-mm-dd>/<uuid>.ext
  async upload(buffer: Buffer, originalName: string, subDir = 'documents')
    : Promise<{ key: string; size: number }>;

  // 删除：local → unlink（失败静默）；qiniu → bucketManager.delete（失败只 warn）
  async delete(key: string): Promise<void>;

  // 取可读取的本地路径
  //   local → key 本身就是绝对路径，直接返回
  //   qiniu → 下载到系统临时目录，返回临时文件路径（调用方用完要清理）
  async getLocalPath(key: string): Promise<string>;

  // 生成可访问 URL：local → null；qiniu → 拼 QINIU_DOMAIN（未配 domain 也返回 null）
  getDownloadUrl(key: string, expireSeconds = 3600): string | null;
}
```

**七牛云下载不是"一次下载"**：`getLocalPath()` 在 qiniu 模式下会构造 4 个候选 URL 依次尝试——签名 http → 签名 https → 公开 http → 公开 https，全失败才抛错。因为私有空间必须签名、而签名要求 domain 带协议前缀。

**完整环境变量**：

```
STORAGE_TYPE=local|qiniu
LOCAL_UPLOAD_DIR=uploads          # 仅 local
QINIU_ACCESS_KEY / QINIU_SECRET_KEY / QINIU_BUCKET   # 仅 qiniu，缺一即启动抛错
QINIU_REGION=z0|z1|z2|na0         # 默认 z0（华东）
QINIU_DOMAIN=xxx                  # 七牛云下载必需，未提供无法解析文件
```

业务逻辑层（DocumentService、KnowledgeService）只调用这几个方法，完全不知道底层是本地还是云存储——这就是依赖倒置。

## 六、加密服务

**文件路径**：`backend/src/common/crypto/encryption.service.ts`

用于加密存储 LLM 的 API Key（明文存数据库不安全）。

- `encrypt(plainKey)` → **AES-256-GCM** 加密，返回 `base64(iv):base64(authTag):base64(ciphertext)`（用 `:` 分隔的三段）
- `decrypt(cipherText)` → 运行时解密（格式不对抛 `密文格式不正确`）
- `maskApiKey(plainKey)` → 脱敏：取**前 4 位 +** **`****`** **+ 后 4 位**（如 `sk-abcdef1234` → `sk-a****1234`）；长度 ≤ 8 直接返回 `****`；传 null 返回 null

**密钥来源（优先级依次降低）**：

```
LLM_CONFIG_ENCRYPTION_KEY  →  JWT_SECRET  →  'dev-only-insecure-key-change-me'
```

取到源字符串后统一用 `createHash('sha256')` 摘要成固定 32 字节，满足 AES-256 密钥长度。

> ⚠️ 环境变量名是 **`LLM_CONFIG_ENCRYPTION_KEY`**，不是 `ENCRYPTION_KEY`。没配时会打 warn 日志并回退到 `JWT_SECRET`——这意味着**改 JWT\_SECRET 会导致已存的 API Key 全部解不开**，生产环境务必单独配置。
