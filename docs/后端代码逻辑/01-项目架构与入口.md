## 一、main.ts — 应用启动入口

**文件路径**：`backend/src/main.ts`

NestJS 应用的启动只有一个函数 `bootstrap()`，做了 3 件事：

```typescript
async function bootstrap() {
  const app = await NestFactory.create(AppModule);    // ① 创建应用实例
  app.setGlobalPrefix('api');                         // ② 全局路由前缀
  app.useGlobalPipes(new ValidationPipe({             // ③ 全局管道 + 过滤器
    whitelist: true,    // 自动剔除 DTO 中未声明的字段（防注入）
    transform: true,    // 自动把 plain object 转成 DTO 类实例
  }));
  app.useGlobalFilters(new AllExceptionsFilter());
  await app.listen(process.env.PORT ?? 3000);
}
```

**全局中间件的作用**：
| 配置 | 效果 |
|---|---|
| `setGlobalPrefix('api')` | 所有 Controller 的路由前面都自动加 `/api`，比如 `@Get('auth/me')` → 实际 URL 是 `/api/auth/me` |
| `ValidationPipe({ whitelist })` | 前端传了 DTO 里没定义的字段会被**自动丢弃**，不会进入 Controller |
| `ValidationPipe({ transform })` | 自动把 `@Body()` 拿到的 JSON 对象 **转成 DTO 类实例**，这样 DTO 里定义的 `@IsString()` 等装饰器才能生效 |
| `AllExceptionsFilter` | 所有未捕获的异常都走这个统一过滤器，返回标准化 JSON 格式 |

## 二、app.module.ts — 模块依赖图

**文件路径**：`backend/src/app.module.ts`

这是根模块，所有业务模块都在这里 `imports`：

```
AppModule
├── BullModule           ← BullMQ 队列（Redis）
├── PrismaModule         ← 数据库访问层
├── AiModule             ← 大模型 Provider（全局，@Global）
├── AuthModule           ← 认证鉴权
├── DashboardModule      ← 统计看板
├── FriendshipModule     ← 好友关系
├── KnowledgeModule      ← 知识库 + 文档处理
├── LlmConfigModule      ← 模型管理（自定义云端模型）
├── WorkspacesModule     ← 工作空间
├── WorkflowsModule      ← 工作流引擎
├── QueuesModule         ← 异步任务队列
├── AgentModule          ← Agent 智能体
├── SkillModule          ← Skill
├── McpModule            ← MCP Server
└── StorageModule        ← 统一存储服务（本地/七牛云）
```

**一个重要细节**：`AiModule` 带了 `@Global()` 装饰器，意味着它的 `AIService` 在任何模块里都可以直接注入，不用再在 imports 里重复声明。

## 三、全局异常过滤器

**文件路径**：`backend/src/common/filters/all-exceptions.filter.ts`

所有 Controller 抛出的异常最终都被这个过滤器接住，返回统一格式：

```typescript
// 最终响应长这样：
{
  "statusCode": 401,
  "error": "Unauthorized",
  "message": "邮箱或密码不正确",
  "timestamp": "2026-10-10T12:00:00.000Z",
  "path": "/api/auth/login"
}
```

过滤器的真实取信息逻辑（`all-exceptions.filter.ts`）：

```typescript
if (exception instanceof HttpException) {
  const res = exception.getResponse();          // 可能是字符串，也可能是对象
  if (typeof res === 'object') {
    // ValidationPipe 的错误形如 { message: [...], error: "Bad Request" }
    error   = res.error ?? exception.message;
    message = Array.isArray(res.message) ? res.message.join('；') : (res.message ?? exception.message);
  } else {
    error   = exception.name.replace('Exception', '');
    message = res;
  }
} else {
  // 非 HttpException：不向客户端泄露 Prisma 报错码 / SQL / 堆栈
  statusCode = 500;
  error      = 'Internal Server Error';
  message    = '服务器内部错误，请稍后重试或联系管理员';
  logger.error(完整堆栈);   // 只在服务端日志里
}

// 二次保护：所有 401 的 message 统一改写，杜绝"邮箱不存在 vs 密码错误"的区分
if (statusCode === 401) message = '邮箱或密码不正确';
```

**需要注意的三点**：
1. `message` 的默认兜底是**中文脱敏文案**，不是 `"Internal Server Error"`（后者是 `error` 字段的值）
2. **任何 401 的 message 都会被强制改成「邮箱或密码不正确」**——这是过滤器做的，不只是 AuthService 里的处理
3. ValidationPipe 的校验错误数组会用「；」拼接成一个字符串

前端取信息：`statusCode` 判断分支，`message` 直接展示即可。

## 四、PrismaService — 数据库访问层

**文件路径**：`backend/src/prisma/prisma.service.ts`

所有业务 Service 里看到的 `this.prisma.xxx` 就是它。构造函数里调用 `$connect()` 连接 PostgreSQL，应用关闭时 `$disconnect()`。

**数据库表一览**（从 Prisma schema 推断）：

| 表名 | 用途 |
|---|---|
| `User` | 用户（邮箱、用户名、密码哈希、在线状态） |
| `Workspace` + `WorkspaceMember` | 工作空间 + 成员（owner + members，无 role 字段） |
| `WorkspaceKnowledgeBase` | Workspace ↔ KnowledgeBase 多对多中间表 |
| `KnowledgeBase` | 知识库（embedding 配置、documentCount / chunkCount） |
| `Document` | 知识库下的文档（文件元数据 + 存储路径 + 处理状态） |
| `DocumentChunk` | 文档分块（content + chunkIndex + pgvector `vector(768)` embedding） |
| `Workflow` + `WorkflowVersion` + `WorkflowRun` + `WorkflowNodeRun` | 工作流 + 版本 + 运行记录 + 节点执行记录 |
| `Agent` + `ChatSession` + `ChatMessage` | Agent 智能体 + 聊天会话 + 消息历史 |
| `LlmProviderConfig` + `LlmModel` | 自定义 LLM 配置 + 可用模型列表 |
| `McpServer` | MCP Server 配置 |
| `Skill` | Skill 定义 |
| `Friendship` | 好友关系（单向存储，查询用 OR 双向匹配） |

> 共 14 张表。注意 `WorkspaceMember` **没有 role 列**，"OWNER / MEMBER" 是 `WorkspacesService` 在查询时用 `user.id === workspace.ownerId` 现算出来的（详见 [08](./08-MCP-Skill-Storage-其他模块.md)）。

## 五、StorageService — 统一存储抽象

**文件路径**：`backend/src/storage/storage.service.ts`

项目支持两种存储后端，通过 `.env` 中的 `STORAGE_TYPE` 切换：

| 存储类型 | `.env` 配置 | 实际操作 |
|---|---|---|
| `local`（默认） | `STORAGE_TYPE=local` | 文件写到 `LOCAL_UPLOAD_DIR`（默认 `uploads/`） |
| `qiniu` | `STORAGE_TYPE=qiniu` | 文件存到七牛云对象存储 |

**实现方式（重要）**：只有**一个** `StorageService` 类，`storage.module.ts` 里就是 `providers: [StorageService]`。它在构造函数里读一次 `STORAGE_TYPE` 存到 `this.type`，之后每个方法内部按 `this.type` 分支——**不存在** `LocalStorageService` / `QiniuStorageService` 两个实现类，也没有按 env 条件注入的戏法。

**对外暴露的方法**（注意方法名和返回值）：
```typescript
class StorageService {
  readonly type: 'local' | 'qiniu';

  // 上传 —— 返回 { key, size }，不是字符串！
  //   local 的 key 是绝对路径： uploads/documents/<uuid>.ext
  //   qiniu 的 key 是对象 Key： documents/<yyyy-mm-dd>/<uuid>.ext
  async upload(buffer: Buffer, originalName: string, subDir = 'documents')
    : Promise<{ key: string; size: number }>;

  // 删除：local → unlink（失败静默）；qiniu → bucketManager.delete（失败只 warn）
  async delete(key: string): Promise<void>;

  // 取可读取的本地路径
  //   local → key 本身就是绝对路径，直接返回
  //   qiniu → 下载到系统临时目录，返回临时文件路径（调用方用完要清理）
  async getLocalPath(key: string): Promise<string>;

  // 生成可访问 URL：local → null；qiniu → 拼 QINIU_DOMAIN（未配 domain 也返回 null）
  getDownloadUrl(key: string, expireSeconds = 3600): string | null;
}
```

**七牛云下载不是"一次下载"**：`getLocalPath()` 在 qiniu 模式下会构造 4 个候选 URL 依次尝试——签名 http → 签名 https → 公开 http → 公开 https，全失败才抛错。因为私有空间必须签名、而签名要求 domain 带协议前缀。

**完整环境变量**：
```
STORAGE_TYPE=local|qiniu
LOCAL_UPLOAD_DIR=uploads          # 仅 local
QINIU_ACCESS_KEY / QINIU_SECRET_KEY / QINIU_BUCKET   # 仅 qiniu，缺一即启动抛错
QINIU_REGION=z0|z1|z2|na0         # 默认 z0（华东）
QINIU_DOMAIN=xxx                  # 七牛云下载必需，未提供无法解析文件
```

业务逻辑层（DocumentService、KnowledgeService）只调用这几个方法，完全不知道底层是本地还是云存储——这就是依赖倒置。

## 六、加密服务

**文件路径**：`backend/src/common/crypto/encryption.service.ts`

用于加密存储 LLM 的 API Key（明文存数据库不安全）。

- `encrypt(plainKey)` → **AES-256-GCM** 加密，返回 `base64(iv):base64(authTag):base64(ciphertext)`（用 `:` 分隔的三段）
- `decrypt(cipherText)` → 运行时解密（格式不对抛 `密文格式不正确`）
- `maskApiKey(plainKey)` → 脱敏：取**前 4 位 + `****` + 后 4 位**（如 `sk-abcdef1234` → `sk-a****1234`）；长度 ≤ 8 直接返回 `****`；传 null 返回 null

**密钥来源（优先级依次降低）**：
```
LLM_CONFIG_ENCRYPTION_KEY  →  JWT_SECRET  →  'dev-only-insecure-key-change-me'
```
取到源字符串后统一用 `createHash('sha256')` 摘要成固定 32 字节，满足 AES-256 密钥长度。

> ⚠️ 环境变量名是 **`LLM_CONFIG_ENCRYPTION_KEY`**，不是 `ENCRYPTION_KEY`。没配时会打 warn 日志并回退到 `JWT_SECRET`——这意味着**改 JWT_SECRET 会导致已存的 API Key 全部解不开**，生产环境务必单独配置。
