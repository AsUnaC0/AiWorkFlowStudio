## 新增 reasoning（推理过程）双通道

**核心设计决策：`streamChat` 从 `AsyncGenerator<string>` 改成 `AsyncGenerator<ChatStreamChunk>`。**

推理过程和正文在同一个响应里是**两条流**，早期只能二选一：拼进正文（污染气泡 / 写进
`ChatMessage.content` / 被桌宠念出来 / 被工作流节点当输出）或者直接丢。改成联合类型：

```ts
export type ChatStreamChunk =
  | { type: 'content'; text: string }
  | { type: 'reasoning'; text: string };
```

配一个 `contentOnly(source)` 辅助函数（同文件导出）给「只要正文」的调用方降级用。
**为什么不用 `ChatOptions.onReasoning` 回调**：`streamChat` 是 async generator，
回调里不能 `yield`，消费方只能等下一个 content 分片才拿回控制权 —— 推理阶段前端会完全没有输出。
改类型后 `tsc` 会把 4 个调用点全部报出来（`ai.service` / `agent.service` ×2 / `llm.executor`），不会漏。

**字段探测**：`reasoning_content`（DeepSeek reasoner / 硅基流动）→ `reasoning`（OpenRouter）→
Ollama 的 `message.thinking`。都过 `normalizeContentToString()`（可能返回内容块数组）。
没有就**不返回 `reasoning` 字段**（不是空串），调用方据此判断「这模型有没有思考过程」。

**分层落地**：
- 非流式：`ChatResult.reasoning?` / `ToolChatResult.reasoning?`
- 流式：`{ type:'reasoning', text }` 分片
- Agent SSE：新事件 `{ type:'reasoning', content }`，**累积语义**（和 `message` 一致，每次推全文），
  前端直接覆盖渲染，不用自己拼接
- 持久化：推理全文作为**一条** trail 步骤 `{ type:'reasoning', content }` 存进 `ChatMessage.trail`，
  刷新会话走同一条读取路径，**没有加新的消息字段 / 数据库迁移**
- 工作流 LLM 节点：显式丢掉 reasoning 分片（属于聊天展示层概念，混进节点输出会污染下游变量）

**`thinking` vs `reasoning` 必须分清**（文档里反复强调过）：`thinking` 是后端自造的
「思考中...」状态提示，无信息量、前端过滤掉不渲染；`reasoning` 才是模型真实思维链。

**前端**：`views/chat/index.vue` 新增 `.reasoning` 折叠区（灰底 + 次要文字色，视觉权重低于蓝底的
`.process`）。状态机复用「处理过程」那套：流式中恒展开（`streamingMsgId === msg.id`），
结束后自动折叠成「已深度思考 / 点击展开」。`processSteps()` 必须**继续过滤** reasoning，否则会串进处理过程列表。
桌宠 `pet.js` 加 `case 'reasoning'` 只为保持 thinking 动画（推理可能几十秒无 content，否则形象会提前静止）。

**验证方式**（可复用）：`.workbuddy-ai/tmp/reasoning-check/check.ts` 起假 HTTP 服务端，
用真实 `OpenAICompatibleProvider` / `OllamaProvider` 打过去，12 条断言覆盖
非流式 / 流式 / chatWithTools / 普通模型无 reasoning。跑法：
`cd backend && TS_NODE_COMPILER_OPTIONS='{"module":"commonjs","moduleResolution":"node"}' npx ts-node --transpile-only ../.workbuddy-ai/tmp/reasoning-check/check.ts`
（**必须加 `TS_NODE_COMPILER_OPTIONS`**，否则 ts-node 报 TS5109 `moduleResolution` 冲突）。
另有 `preview.html` + 本机 Chrome headless 截图验证样式，注意 `--screenshot` 与页面都要传**绝对
`file:///` URL**（带空格要 `%20`），只传相对路径会报 `ERR_NAME_NOT_RESOLVED`。
