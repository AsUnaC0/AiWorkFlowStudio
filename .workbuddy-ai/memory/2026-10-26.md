# 2026-10-26

## 平台助理新增 MCP / Skill 创建能力（17 → 19 个工具）

### 新增工具（`platform-tools/tools/skill-mcp.tools.ts`）
- `create_mcp_server`（CREATE / MEDIUM）：只创建配置 + `authType=NONE` 时自动 `testConnection()` 发现工具。
  **Schema 里没有 apiKey / bearerToken**，模型硬塞就返回 FAILED 并拒绝执行（不静默丢弃）。
- `create_skill`（CREATE / MEDIUM）：PROMPT / WORKFLOW / TOOL 三型分别校验必填项与资源归属
  （SkillService.create 本身不做归属校验，必须工具层自己查）。

### 配套改动
- `McpService.createPendingCredentials()`：跳过 `assertCredentialsProvided`，credentials 留空、
  status=DISCONNECTED，凭据只能由用户在 /mcp 页面补。SSRF 校验与 `create()` 完全一致。
- `PlatformToolsModule` 导入 `McpModule` + `SkillModule`（两者都是叶子模块，不形成环）。
- `PlatformOperationLog.sanitizeParams()`：key 全等匹配改为**子串正则**
  （`api[-_]?key|token|secret|passw|credential|authorization|cookie|session[-_]?id`）——
  旧写法 `bearerToken` 会漏，密钥明文进审计表。
- `platform-assistant.prompt.ts`：新增「MCP Server / Skill 创建规范」一节；
  原来那句「配置 Agent、Skill 和 MCP」与实际工具集不符，已改成准确表述。

### 验证
- `tsc --noEmit` 通过；`nest start` 日志 `平台工具注册完成，共 19 个`。
- 临时冒烟脚本（已删）实测：传密钥被拒且审计 params 为 `***`、127.0.0.1 被 SSRF 拦、
  非法 transport 报错、API_KEY 只建配置 credentials=null、同 URL 去重、无认证分支连接失败落 ERROR。
