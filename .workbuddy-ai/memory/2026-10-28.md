## 桌宠 MVP 打通 + 修掉后端「生成两遍答案」

### 桌宠为什么「打不开」

仓库里原本**根本没有桌面客户端**：只有 `backend` / `fronted` / `docs`。人格里的「允许显示桌宠」
开关只写进 `AgentPersona.desktopPetEnabled`，**没有任何客户端读它**；`DesktopPetSettings` /
`RefreshToken` 两张表建了但没有接口读写。确认后按 MVP 范围新建 `desktop/` Electron 工程。

### 交付内容（`desktop/`）

透明置顶无边框窗口 + 托盘 + 拖拽 + 内联 SVG 形象（呼吸/眨眼/说话/思考）+ 文字气泡 +
登录 → 拉平台助理 → SSE 对话。不含 Live2D / TTS / 截屏感知。

关键取舍（README 与需求文档都写了）：

- **网络全放主进程**：后端 `main.ts` 没开 `enableCors()`，渲染进程是 `file://` 源（`Origin: null`），
  直接 `fetch` 必被拦。主进程走 Node 不受同源约束，渲染进程只收 IPC 事件 —— 附带好处是 token 不出主进程。
- **鼠标穿透用坐标命中**：`setIgnoreMouseEvents(true, { forward: true })` 转发的 mousemove 不做命中测试，
  `e.target` 是 `<html>`，`closest()` 永远判不到。改成拿 `clientX/Y` 比 `getBoundingClientRect()`。
- **SSE 结束靠空闲兜底**：Electron 主进程读 `text/event-stream` 拿不到可靠 EOF —— 后端已 `response.end()`
  （Node 原生 fetch 3s 就 close），但 `end` / `close` / `aborted` 一个都不触发。分档：思考 90s、出字后 5s。
  阈值给小了会把「首 token 慢」误判成结束，表现成只收到 meta/thinking 就断流。

### 修掉的后端缺陷（重要）

`agent.service.ts` 分支 B，`toolCalls.length === 0` 时原本：
先 yield `chatWithTools` 的 `content`，**再调一次 `streamChat` 重新生成**并从头累积。

三个后果：① 同一轮多花一次模型调用（实测 2.8s → 5.9s）；② `temperature > 0` 下两次生成不一致，
前端气泡**突变**；③ 累积长度**回退**（102 → 1），桌宠气泡先显示一段完整介绍再被换成一句短招呼。

改为 `streamAsTypewriter(result.content)`：切 3 字一片，按总长度反推间隔让整段约 600ms 打完。
只调一次模型、内容唯一、首字延迟 6.6s → 2.8s。保留「`content` 为空才退回 `streamChat`」的兜底。
网页端同样受益（费用减半、少一轮等待），之前没人报是因为网页端被第二次输出覆盖，看着只是「字重播」。

## 桌宠支持「网页点开」（不用命令行）

### 为什么网页点不开

浏览器沙箱**不允许网页启动本地程序**；自定义协议（`xiaodie://`）要先安装注册，
开发期（`npm start` 跑的不是安装包）也常被拦。所以只能绕后端：

  1. 目录**靠探测**：从 `process.cwd()` 和 `__dirname` 各往上找 `desktop/package.json`（≤6 层）。

  2. 必须 `delete env.ELECTRON_RUN_AS_NODE`，否则 Electron 以纯 Node 模式启动直接崩。

### 顺手修掉：`npm start` 在本机根本起不来

实测 `cd desktop && npm start` 一闪而过。日志：
`GPU process exited unexpectedly: exit_code=-1073741819` ×10 → `FATAL: GPU process isn't usable. Goodbye.`

**只调 `app.disableHardwareAcceleration()` 不够**，必须三个命令行开关一起上：

```js

app.commandLine.appendSwitch('disable-gpu');
app.commandLine.appendSwitch('in-process-gpu');   // ← 关键，别再 fork GPU 子进程
app.disableHardwareAcceleration();
```

加上之后 `npm start` 正常常驻（3 个 electron 进程）。之前 README 里那条命令是坏的。

## 桌宠改为「后台自动登录」，不弹登录面板

用户诉求：「让桌宠进行后台自动登录，前端不要展示，当前平台登录之后才会进入页面去点击桌宠」。
即用户一定是在网页登录过的，桌宠不该再问一次密码。

### 机制：一次性交接文件

```
网页点按钮 → POST /api/desktop-pet/launch（带 JWT）
  → 后端写 %TEMP%/xiaodie-handoff-<uuid>.json
      { token, baseUrl, userId, email, expiresAt }  mode 0600，TTL 60s
  → spawn 时只把【文件路径】放进 env.XIAODIE_HANDOFF
  → 桌宠读文件 → 立即删除 → safeStorage 加密存进自己的 config → 后台拉 /platform/assistant
```

**token 绝不走命令行参数或 env 本身** —— 进程命令行对同机任何用户可见，等于公开 7 天有效的 JWT。
`baseUrl` 由请求的 `Host` 推断，所以后端起在 3100 时桌宠自动跟着走，不用手填。

### 踩到的坑（必须记住）

**交接文件必须在拿单实例锁之前读。**

第一版把 `applyHandoff()` 放在 `app.whenReady` 里、`second-instance` 时再调一次。
实测发现：桌宠已经开着时再点按钮，第二个进程 `requestSingleInstanceLock()` 失败立刻退出，
**它的 env 传不到第一个实例** —— 结果
1. 交接文件烂在临时目录 60 秒（我 dump 出来看过，里面是完整 token，276 字符）
2. 「换账号后再点一次」完全失效，桌宠还停在旧账号

修法：模块顶层先 `consumeHandoff()`，再用 `requestSingleInstanceLock({ handoff: pendingHandoff })`
→ `second-instance` 的第 4 个参数 `additionalData` 交给第一个实例。
修完残留归零。

### 其他细节

- 换账号判断用 `userId` 比对；不同则清 `agentId / displayName / workspaceId / sessionId / email`，
  否则会把上一个用户的会话串过来。
- `applyHandoffData()` 的返回值改成「身份是否真的变了」（比对旧 token），
  `second-instance` 只在变了时才 `reload()` —— 同账号重复点按钮不该把气泡刷掉。
- 前端不展示登录面板：`pet:state` 的 `loggedIn = Boolean(getToken())`，
  交接后 token 有效 → `fetchAssistantInfo()` 成功 → `error=null` → boot 走「我是小蝶」分支，不 `openPanel()`。
  登录面板只在**自动登录失败**（token 过期 / 后端没起）时兜底出现。

### 验证

1. 把 `pet-config.json` 重置成无 token → 调 launch → config 里出现 `tokenEnc` / `email` / `userId` /
   `agentId` / `displayName`。**`agentId` 有值就是铁证**：它是 `fetchAssistantInfo()` 成功后才写的，
   说明交接的 token 真的能用。
2. 交接文件残留 0。
3. 重复点击：进程数保持 3、登录态保持、残留 0。

## 审计：桌宠记忆「向量化 + 分类」实现核对

逐行核对 `backend/src/memory/` + `agent.service.ts` + `schema.prisma`：

1. **向量化已实现**：`MemoryService.create()` 先 `tryEmbed(summary+content)` 调 `EmbeddingService.embedBatch`，
   再把 `embedding Float[]` + `embeddingModel` 与 `content` **同一次 `prisma.memory.create` 落库**（原子，非两步）。
   schema 里 `Memory.embedding Float[]` / `embeddingModel String?` 已就位。
2. **分类不是「查列表/建列表」**：`MEMORY_CATEGORIES` 是 `memory.constant.ts` 里写死的枚举（PREFERENCE/FACT/TASK/EVENT/EMOTION/OTHER），
   没有独立的分类表/实体，`create()` 只 `isMemoryCategory()` 校验，非法值归 `OTHER`。不会去查也不会去建分类列表。
3. **降级**：无 Embedding 模型 / 调用失败 → `tryEmbed` 返回 null → 存 `embedding:[]`，记忆照存（原文+摘要）但无向量，
   召回退回 jaccard 关键词；失败一次熔断 5 分钟（`embeddingDisabledUntil`）。`buildLinks` 在无向量时直接返回 0（不连线）。
4. 用户问题表述的「先存原文到分类、再向量化」与实际相反：实现是**先算向量、再连同原文一次性插入**。

## 桌宠语音开关 + Edge TTS 播报（需求 §3.3）

### 关键发现：`edge-tts` npm 包已失效（403）

`edge-tts@1.0.1`（latest）只发 `Sec-MS-GEC` **v1**（纯 SHA256），微软现在要求 **v2**
（`"<16位CS64>-<64位SHA256>"`，`SEC_MS_GEC_VERSION=2-143.0.3650.75`），直连一律 **403**。
时钟偏差不是原因（实测 MS 服务器 `Date` 与本机一致）。
改用 **`msedge-tts@2.1.1`**（CJS，`dist/SecMsGec.js` 实现了 v2 CS64，带时钟偏移校正），
实测合成成功（中文短句 ~2s，22~24KB，magic `fff3`）。backend / desktop 都已换装并移除 `edge-tts`。

### 后端（`backend/src/tts/`，新增）

- `TtsService.synthesize()`：`MsEdgeTTS` 每段新建实例、`setMetadata` + `toStream` + 收集 chunk + `close()`；

## 修正：桌宠语音改为「边读边出字」+ 语音开关找不到的问题

用户反馈两点：① 文字先整段出来、随后才响语音；② 前端根本看不见语音开关。

### ② 才是真问题：登录后没有任何入口能打开设置面板

`onPetClick()` 只在 `!loggedIn` 时 `openPanel()`，登录后点小蝶只会弹输入框。
面板里那个「语音播报」勾选框对已登录用户**永远打不开**，等于开关不存在。
补了三个入口：右上角齿轮按钮、**右键点小蝶**、托盘菜单「设置…」（`emit({type:'open-panel'})`）。
另外右上角加了常驻**喇叭浮标**，直接点就能静音/恢复（`.muted` 时显示斜杠、变灰）。

### ① 同步方案（推翻原来的「整段防抖后朗读」）

- 删掉 700ms 防抖 + `onTtsAudio` 事件推送。事件方式拿不到「这一句播完」的时序，必然竞争。
  改成 `ipcMain.handle('tts:speak')` **直接 return `{ok, audio:base64}`**，渲染进程能 `await` 单句。
- `pet.js` 流水线：`message`（累积文本）→ 按 `[。！？!?\n]` 切句 → 逐句「合成 → 播放 → 写到哪句显示哪句」。
- **打字机速度取自 `AudioBuffer.duration`**：音频真正开始发声时才 `onStart(duration)`，
  之后按 `(Date.now()-startAt)/durationMs` 算进度（不是每次 tick 累加固定字数 ——
  `setInterval` 会漂移，累加写法会让句末文字比声音慢半拍）。
- `speechEpoch` 代次守卫：reset / 静音 / 换账号都 +1，丢弃过期回调，避免旧句子写进新气泡。
- 预取：最多 2 条并行合成；`>45 字`的句子再按逗号切一刀，缩短首字延迟。
- 合成失败（`item.audio === null`）→ 该句整句直接显示，只丢声音不丢文字。
- 气泡是纯文本，加了 `stripMarkdown()` 剥掉 `**`/反引号/井号/列表符号（用户看到的 `我叫**小蝶**` 就是它）。

### 追加修正：真正的坑是 `t-menu-group` 的 title prop 会顶掉 #title 插槽

上一版把按钮放进 `<t-menu-group>` 的 `#title` 插槽，用户实测**仍然看不到**，
并且他自己把插槽里的文案改成「会话123」，侧栏依旧显示「会话」——
说明渲染出来的是 `title="会话"` 这个 **prop**，插槽整段被丢掉了。

根因（`tdesign-vue-next@1.20.7`，`es/_chunks/dep-272265e9.mjs` 的 `useTNodeJSX`）：
`menu-group.mjs` 调用 `renderTNodeJSX('title', { silent: false })`，**没传 `slotFirst`**，
于是走 `isPropExplicitlySet(instance, 'title')` 分支，而该分支对非空字符串直接 `return propsNode2`，
永远走不到后面的 `if (renderSlot)`。→ **prop 优先于插槽，且静默丢弃，无任何警告。**

结论 / 约定：
- `t-menu-group` 想自定义标题，必须**同时删掉 `title` 属性**，否则插槽白写。
- 更稳的做法：标题就用 `title` prop，额外操作按钮放进**默认插槽**（和菜单项同级），
  默认插槽确定会渲染（会话项、`agent-empty` 都靠它）。
- 本次最终形态：`.session-new-row`（`<li>`）+ `.session-new-btn`（整行虚线框「＋ 新建会话」），
  放在会话列表最上方；空状态只留「还没有会话」一行，避免两个按钮重复。
- 顺带把 `.t-menu-group__title` 从 `padding: 0` 改成 `padding: 8px 12px`，
  让「我的 Agent」「会话」两个标题和下面的条目文字左对齐。
- 删掉了已无用的 `.section-header` 样式块。
