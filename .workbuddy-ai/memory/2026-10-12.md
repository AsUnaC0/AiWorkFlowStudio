## 功能 17：Agent 多类型输出（文件生成）— 验证与修复

完成了「需求 17」的收尾验证（前端编译 + 后端冒烟测试），并在过程中发现并修复了两个真实缺陷：

### 修复 1：Markdown 生成丢失行内标记（链接/粗体等）
- 根因：`parseMarkdownToBlocks` 用 `stripInline()` 把所有行内 Markdown 剥成纯文本，而 `md` 生成器又经 blocks 往返再序列化，导致 `[百度](url)` 变成 `百度`、丢失链接。
- 修复：`generateMarkdown(content, rawMarkdown?)` 新增可选 raw 参数；当提供原始 markdown 时直接输出原文（完整保留行内语法），标题用 `applyTitleToRaw` 智能处理（正文已以 H1 开头则保留原文，否则文首前置 H1）。`FileGeneratorService.generate` 的 md 分支传入 `input.markdown`。
- docx/pdf 生成器渲染的是已 strip 的纯文本 `TextRun`，无破损语法，保持原行为（已知限制：docx/pdf 暂无行内富文本）。

### 修复 2：表格表头对字符串列名不兼容
- 根因：`resolveHeaders` 假设 `SheetSpec.columns` 为 `{header}` 对象数组；LLM 常直接给 `["a","b"]` 字符串数组，导致表头变为 `undefined`。
- 修复：`resolveHeaders` 同时兼容 `string` 与 `{header}` 两种写法（excel.generator.ts）。

### 验证结果
- 前端：`vue-tsc -b && vite build` 通过（chat 页集成编译正常）。
- 后端：`nest build` 通过；编译产物冒烟测试覆盖 生成(docx/pdf/md/xlsx/csv) + 预览(脚本消毒/链接保留/多列表头/CSV) + 鲁棒性，全部 PASS。
- 环境注意：backend/.npmrc 使用 `node-linker=hoisted` 解决沙箱中 pnpm 符号链接缺失问题（影响 docx/exceljs/pdfkit/mammoth/marked/sanitize-html 解析）。

### 后端构建修复（解决用户「后端启动报错」）
用户报告 `nest start`/`nest build` 报错：TS2688 `Cannot find type definition file for 'jest'/'node'`，且 CLI 崩溃 `chalk.blue is not a function`。

根因与修复：
1. **TS2688（类型找不到）**：沙箱里 pnpm 符号链接未生成，顶层 `@types`、`@nestjs`、`@prisma` 等作用域目录为空（真实环境 `pnpm install` 正常，因为 `@types/node@^24`、`@types/jest@^30` 均已在 package.json 声明并会被安装）。沙箱用 `flatten-deps.cjs` 把 `.pnpm` 仓库里的包直接 copy 到顶层 node_modules，绕开坏符号链接。
2. **`chalk.blue is not a function`（CLI 崩溃）**：flatten 时把顶层 `ansi-styles@6`/`supports-color@8`/`string-width@5`/`strip-ansi@7`/`ansi-regex@6`/`emoji-regex@9`（均为 ESM-only）覆盖到了 chalk@4.1.2 / cli-table3 等 CJS 消费者需要的 CJS 版本之上，导致颜色方法与 `stringWidth` 为 undefined。修复：从 `.pnpm` 仓库把对应 CJS 版本 copy 回顶层（ansi-styles@4.3.0、supports-color@7.2.0、string-width@4.2.3、strip-ansi@6.0.1、ansi-regex@5.0.1、emoji-regex@8.0.0）。is-fullwidth-code-point@3.0.0 顶层本就正确。ESM 消费者保留各自 `.pnpm` 嵌套副本，不受降级影响。

验证结果：
- `node node_modules/@nestjs/cli/bin/nest.js build` → EXIT 0。
- `nest start` → 编译、定位入口（dist/src/main.js，因 tsconfig 无 rootDir 且根目录有 prisma.config.ts，故产物在 dist/src/ 下）、启动至 `app.listen(3000)`，日志 `Nest application successfully started`，全部路由（含新增 dashboard 运行监控 3 个端点）映射正常。
- 注意：`start:prod` 脚本为 `node dist/main`，而实际入口是 `dist/src/main.js`；若要在生产直接跑 dist，需改用 `node dist/src/main.js` 或给 tsconfig 设 `rootDir: "src"`（但会排除根目录 prisma.config.ts，需相应调整 include）。开发用 `nest start` 不受影响。

## 修复：三个接口 500（schema 漂移 / 未应用迁移）

用户报告 `/api/agents`、`/api/dashboard/overview`、`/api/dashboard/recent-activities` 同时 500。

**根因**：代码已加新 schema 并重新生成 Prisma Client，但**迁移未应用到数据库**。库内最后应用迁移停在 `20261010140712_add_model_refs`，之后 3 个迁移（`20261012100000_add_generated_file`、`20261012101000_add_agent_file_generation`、`20261012120000_add_run_monitoring`）pending。直接后果：
- `WorkflowRun` 缺 `errorCode/triggerType/durationMs` 列 → dashboard overview / recent-activities 查询这些字段时 Prisma 抛错。
- `ModelCallLog` 表不存在（`to_regclass`=null）→ overview 的 modelCallLog.aggregate 抛错。
- `Agent` 缺 `enableFileGeneration` 列 → `/api/agents` 查询抛错。

**修复**：`prisma migrate deploy` 一次应用 4 个 pending 迁移（含此前也遗漏的 `20261010060846_shadow_replay_check`）。三个迁移均为纯增量（CREATE TABLE / ADD COLUMN 带默认值 / CREATE INDEX，无 DROP/DELETE/TRUNCATE），安全。

**验证**：先用 `pg` 直连确认列/表已就位、原报错 SELECT 可执行；再用应用同款 `PrismaPg` adapter 的 PrismaClient 跑三个接口的真实查询，全部通过。Prisma 查询每请求独立，迁移后无需重启即可恢复。

**沙箱注意**：`prisma` CLI 在沙箱又被 CJS/ESM 冲突挡（`proper-lockfile` → `onExit is not a function`，因顶层 `signal-exit@4.1.0`(ESM) 覆盖了 proper-lockfile 需要的 `signal-exit@3.0.7`(CJS)）。从 `.pnpm` 仓库 copy `signal-exit@3.0.7` 覆盖顶层后 deploy 正常。另经验证 Prisma `_prisma_migrations.checksum` = 迁移文件内容的 SHA-256 hex（可作为手改迁移历史的兜底）。

**套路沉淀**：本项目新增/修改 schema 后，`prisma migrate dev/deploy` 必须显式执行到正在用的那个库；光改 schema.prisma + generate 不迁移 → 运行时 500。
