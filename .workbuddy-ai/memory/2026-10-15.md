# 2026-10-15

## 工作流列表页：删除按钮可见性 + 重命名

**背景**：用户反馈「工作流列表页没有删除工作流等功能」。排查发现删除功能其实在
`views/workspace/index.vue` 里已经存在（10-14 那次加的，一直未提交），但
`.run-btn` / `.wf-delete-btn` 基础样式是 `opacity: 0`，只有 hover 整行才出现 → 用户根本看不到。

**改动**：
- `fronted/src/views/workspace/index.vue`
  - `.run-btn` / `.wf-delete-btn` 基础 `opacity` 改 1（并去掉 `transform: scale(0.9)`），常驻可见；
    hover 时仍变主题色/红色。新增 `.wf-rename-btn` 样式（同款常驻）。
  - 新增重命名：`wfRenameDialogVisible / wfRenaming / wfRenameInput / wfRenameError / targetRenameWf`
    + `openWfRenameDialog` / `handleRenameWorkflow`；行内加重命名图标按钮（`t-icon name="edit"`，
    编辑按钮用的是 `edit-1`），弹窗复用创建弹窗的 t-form 版式。
  - 重命名后 shallowRef 数组整体替换：`workflows.value.map(wf => wf.id===id ? {...wf, ...updated} : wf)`。
- `fronted/src/types/workflow.ts`：`UpdateWorkflowRequest.definition` 改为可选。

**关键后端改动（为重命名不产生新版本）**：
- `backend/src/workflows/dto/update-workflow.dto.ts`：`definition` 加 `@IsOptional()`。
- `backend/src/workflows/workflows.service.ts` `update()`：`shouldCreateVersion = dto.definition !== undefined`；
  不传 definition 时跳过 `workflowVersion.create` 且不动 `currentVersionId`。
  → 不这么做的话，重命名会让已发布工作流被标成「有未发布改动」，属于可见 bug。

**范围约束**：用户明确要求「不要修改画布」，所以 `views/workspace/workflow.vue`（编辑器）与
`composables/useWorkflow.ts` 未改动。此前给编辑器加的删除/重命名/节点删除改动已 `git checkout` 还原。

**注意**：Workspace 列表行（`.ws-delete-btn`）仍是 hover 才出现的老交互，本次按范围没动，后续可一并统一。

**验证**：`backend npx tsc --noEmit` 通过；`fronted npx vue-tsc --noEmit -p tsconfig.app.json` 通过。
