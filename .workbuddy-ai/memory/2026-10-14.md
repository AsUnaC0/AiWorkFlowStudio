## 修复：首次进入页面时 401 弹窗刷屏（「邮箱或密码不正确」×N）

原因链：
1. 路由守卫只判断 `!!userStore.token`，过期 token 被放行 → 页面先挂载再被踢回登录页；
2. 页面挂载会并发/串行发 4 个请求（getWorkspaces / getLlmModels / getChatFilePolicy / listAgents），
   全部 401，旧拦截器对每个 401 都弹一次 toast + 跳一次登录页；
3. 后端 `AllExceptionsFilter` 把所有 401 的 message 改写成「邮箱或密码不正确」，token 过期也被误报；
4. 页面自己的 catch 再补一条「加载 Agent 列表失败」。

改动：
- 新增 `fronted/src/utils/token.ts`：`isTokenExpired()` 解析 JWT exp（解析失败按未过期处理，交给后端判定）。
- `fronted/src/router/index.ts`：守卫里先校验 exp，过期直接 logout + 跳 /login（带 redirect），不再闪一下页面。
- `fronted/src/utils/request.ts`：新增 1.5s 静默窗口 `authRedirecting`，同一波 401 只提示一次「登录已过期，请重新登录」、
  只跳转一次并带 redirect；窗口内且未重新登录的后续请求直接 `axios.Cancel`；导出 `isAuthFailure(err)`；
  登录/注册接口的错误不弹全局 toast（登录页内联展示）。
- `views/chat/index.vue`、`views/agents/index.vue`：加载失败 catch 里用 `isAuthFailure` 跳过重复提示。
- `backend/src/common/filters/all-exceptions.filter.ts`：401 只对 `/auth/login` 脱敏成「邮箱或密码不正确」，
  其余返回「登录已过期，请重新登录」。
- 同步更新 docs 里「所有 401 一律脱敏」的旧表述（01/02/03/08 + 审查报告）。

验证：`vue-tsc -b` 与 `vite build` 均通过；后端 `tsc --noEmit` 通过。
待用户侧验证：清掉 localStorage 旧 token 后重新进入页面应直接到登录页且无报错弹窗。

  `confirm-btn="null"` 可隐藏确认按钮；多于 2 个按钮时用 `#footer` 插槽。

## skills / mcp / knowledge 列表页：行内「编辑/删除」按钮点不动

症状：skills 页（以及 mcp、knowledge 列表）行尾的「⋯」下拉里 Edit/Delete 点不出来，等于无法编辑/删除。

根因：行操作用了 `<t-dropdown @click.stop>` + 触发按钮 `<button class="row-more-btn" @click.stop>`。
TDesign 1.20.7 的 `Dropdown` 依赖内部 `Popup` 触发器上的 click 来展开菜单，但触发按钮上的
`@click.stop` 在事件冒泡到触发器包裹层之前就 `stopPropagation()`，导致菜单永远打不开。
（`t-dropdown-item` 自身的 `@click` 在 1.20.7 是正常的，问题在 trigger 的 `.stop`。）

修法（三页统一）：去掉脆弱的 dropdown，行尾直接放显式按钮
`<button class="row-action-btn" @click.stop="openEditDialog(x)">` 与
`<button class="row-action-btn row-action-danger" @click.stop="openDeleteDialog(x)">`
（knowledge 页为 Open/Delete），hover 时显示；`@click.stop` 防触发整行点击。
CSS：`.row-more-btn` → `.row-action-btn`，删除按钮加 `&.row-action-danger:hover` 红色高亮。

验证：`vue-tsc -b` + `vite build` 通过；grep 确认 `row-more-btn`/`t-dropdown-item` 已无残留。

## 修复：聊天页切菜单后 AI 回答不回显（缺 keep-alive）

**根因三层**：`MainLayout.vue` 的 `<router-view>` 没有 keep-alive → 路由切换销毁 chat 组件 →
`onBeforeUnmount` 清空 `messages` → SSE 回调 `handleAgentEvent` 里 `messages.find(id)` 返回 undefined
直接 `return`，流式数据被静默丢弃。若切走时流未结束（后端也未落库），回来就永远看不到这段回答。

**修复（4 个文件）**：
- `router/index.ts`：chat 路由 meta 加 `keepAlive: true`
- `layout/MainLayout.vue`：`<transition>` 内包 `<keep-alive :include="cachedViews">`；`cachedViews`
  由 `router.getRoutes()` 过滤 `meta.keepAlive === true` 自动收集（不硬编码，新增缓存页无需改本文件）
- `views/chat/index.vue`：`defineOptions({ name: "Chat" })` 与路由 name 对齐；新增 `onActivated`
  （还原滚动位置 + 轻量校准会话列表，首次触发跳过避免与 onMounted 重复请求）；滚动状态用
  `@scroll.passive` **持续记录**——不能在 `onDeactivated` 里读 scrollTop，该钩子触发时 DOM 已被移走、
  scrollTop 已归零；`onBeforeUnmount` 里 abort 进行中的流 + `disposed` 标志避免销毁后仍发请求
- `api/agent.ts`：`runAgentStream` 加可选 `signal`（仅真正销毁时 abort，keep-alive 切菜单**不**abort）

**验证**：`vue-tsc -b` 仅剩 dashboard 既有 3 个错误；`vite build` 成功（沙箱批量删除保护拦截了

## 放开系统预设 Agent 的「模型配置」修改（PATCH /agents/:id 报 400）

**症状**：在 Agent 配置页改平台助理（`isSystem=true`）的模型后保存 → 400「系统预设 Agent 不允许修改」。

**决策**：不是全放开，而是**白名单只放开模型配置**。系统 Agent 的 name/description/systemPrompt/
绑定资源由 `PlatformAssistantService.ensure()` 在每次访问时纠正，改了也没意义；而模型必须能改 ——
用户接的是自己的模型服务。所以：

后端 `agent.service.ts`：
- 新增 `SYSTEM_AGENT_EDITABLE_FIELDS = ['llmModelId', 'model', 'temperature']`。
- `update()` 里 `isSystem` 分支改为：只允许白名单字段，带任何其他字段（含 `undefined` 之外的实参）
  直接 400 并列出被拒字段名；**跳过 `createdBy` 归属校验**（系统 Agent 的 createdBy 是 null）。
- 顺手删掉两个从未被调用的死方法 `canAccess` / `canModify`，权限规则改成内联 + 顶部注释说明。
- `remove()` 不变：系统 Agent 一律不可删。

前端 `views/agents/detail.vue`：
- `handleSave` 分叉：系统 Agent **只发 `llmModelId` + `temperature`**（多带一个字段整请求就 400）；
  同时跳过「名称不能为空」校验。
- 「最大工具调用轮数」滑块对系统 Agent 加 `:disabled`（ensure() 会用 `Math.max(...,12)` 覆盖它，放开也没用）。
- 提示文案改为「名称/描述/提示词/绑定资源不可改，模型配置可调整」。

**语义提醒（重要）**：平台助理默认 `llmModelId=null` 时走「按当前用户默认对话模型解析」；
一旦在配置页选定模型，`llmModelId` 有值 → `runStream` 优先按它解析，**对该实例下所有用户生效**。
选回「Ollama 本地」会清空 `llmModelId`（`''` → null），恢复按用户解析的行为。
